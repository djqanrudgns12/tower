# Gemini Argon 제작·인수 계약 v0.2

2026-10-27 · Codex: 규격·구현·검사 / Gemini Argon: 미술 원본·문항 초안 / Argon·Codex·Claude: 공동검수 / 사용자: 베타테스트

이 파일은 실제 제작 요청에 복사할 작업 지시다. Gemini 작업을 이미 실행했거나 콘텐츠를 승인했다는 뜻이 아니다. 아래 치수는 1종 렌더링 표본으로 확정할 제안 기본값이다.

## 1. 공통 전달 형식

작업마다 `jobId`, `contractVersion`, `styleDirection`, `referenceFiles`, `requestedIds`, `status`, `files`, `rejections`를 기록한다. JSON은 UTF-8, LF, 마지막 쉼표/주석 없이 제출한다. 파일명은 영문 소문자·숫자·하이픈으로 구성한다. 결과를 설명문만으로 제출하거나 ID를 임의 변경하지 않는다.

한 배치에 완료/보류/반려 ID가 모두 들어가야 한다. 요청 누락은 완료가 아니다. Codex는 incoming에 수신 → 자동 검사 → 작은 크기 시각 검수 → 승인 파일만 원본 저장 → 재현 가능한 패킹 → 게임 내 검수 순서로 처리한다. 사용자·검수자에게는 파일 수정 작업 대신 승인/수정 포인트가 보이는 접촉판과 목록을 제공한다.

원본과 배포 파일을 분리한다. sourceHash는 원본 bytes의 SHA-256, artifactHash는 실제 배포 bytes의 SHA-256이다. 경로는 상대경로이고 `..`/절대경로/외부 URL을 허용하지 않는다. 원본 수정은 revision을 올린다.

## 2. 미술 고정 규칙

- 선택한 방향은 세계관·재료·팔레트·외곽선·UI 어조를 정한다. 원문의 타워 기능/맵 경로/학년/전투 규칙은 바꾸지 않는다.
- 정사영에 가까운 상부 사선 2D, 동일한 지면 투영과 좌상단 광원. 높이 표현은 짧은 측면 한 면으로 제한한다. 실제 3D 렌더/등각 격자 혼합은 금지한다.
- 최종 표시 기준 외곽선 1.5~2px, 내부선 약1px, 소형 텍스처는 제거한다. 배경 대비 타워/적 채도를 높이되 전체 강조색은 역할 색을 포함해 제한한다.
- 타워는 기반+공격 기관+역할 표식의 세 덩어리로 읽혀야 한다. 아군은 안정된 바닥 실루엣, 적은 이동 방향이 드러나는 비대칭 실루엣. 정예는 방패/띠, 보스는 크기/형태/표식을 함께 쓴다.
- 한글·숫자·가격·레벨·버튼을 그림에 넣지 않는다. 그림에 그려진 가짜 글자/임의 문양/서명/워터마크를 인수하지 않는다.
- 도형만으로 정답/오답을 표현하지 않고 런타임 라벨과 기호를 병행한다. 과한 축하 팝업·유리 카드·네온 테두리·전체 화면 흔들림은 기본에서 제외한다.

## 3. 파일 크기·좌표·레이어

| 자산 | 원본 프레임 후보 | 실제 표시 기준 | 기준점/레이어 |
|---|---|---|---|
| 타워 본체 | 128×128 PNG RGBA | 40~56 CSS px | frame pivot (64,104), 발사점 별도 |
| 타워 무기 | 128×128 투명 PNG | 본체와 동일 스케일 | pivot·muzzle 좌표를 본체 기준으로 기록 |
| 일반 적 | 64×64 PNG RGBA | 22~30 CSS px | pivot (32,48), 선택 영역은 논리 데이터 |
| 보스 | 128×128 PNG RGBA | 38~48 CSS px | pivot (64,96), 경로/타워를 과도하게 덮지 않음 |
| 성문 | 192×192 PNG RGBA | 54~72 CSS px | 맵 출구 위치와 anchor 별도 |
| 장식 타일 | 128×128 PNG RGBA | 맵 스케일에 동기화 | 경로/슬롯 영역은 비워 둠 |
| 배경 판 | 최대1536×1536 후보 | 정사각 전장 | 타워·경로·슬롯·텍스트를 합성하지 않음 |

배경에 길까지 그려서 논리 경로와 어긋나는 문제를 막는다. 지면/장식/길/슬롯/성문/타워/적/효과/UI를 독립 레이어로 둔다. 최종 DPR과 맵 폭으로 원본 해상도를 다시 판단한다. 동작 프레임의 trim offset과 pivot은 원본 좌표로 보존한다. 패킹 시 회전은 끄고 프레임 간 padding2px+edge extrusion2px 후보로 시작한다. 실제 필터링 테스트 후 확정한다.

PNG 원본을 기준으로 하고 웹 배포는 무손실 WebP 또는 PNG를 비교한다. 밝은/어두운/4맵 배경에서 alpha 가장자리의 흰 테두리·검은 테두리를 확인한다. 투명처럼 보이는 체크무늬가 포함된 이미지는 반려한다. 아틀라스 한 장은 초기 최대2048×2048, 필요한 묶음만 로드한다. 파일 용량과 GPU 비압축 메모리(폭×높이×4)를 별도로 기록한다.

## 4. 30종 외형의 생산 계획

| 단계 | Gemini 원본 | Codex 구현 | 인수 게이트 |
|---|---|---|---|
| 표본 | 궁수 기본1, 기본 적1, 성문1, 배경 일부1 | 실제 크기 축소·반동·이동·피격 | 32/48/64px 가독성·기준점 |
| 핵심 | 궁수/포탑/서리 기본3 + 빠른 적 | 1맵 실제 전투 | 경로/문제 영역 가림 없음 |
| 기본 확장 | 나머지 기본7종 | 공격 프로필별 연결 | 실루엣만으로 역할 구별 |
| 진화 | A/B 분기20종 | Lv3~5 공용 + 레벨 DOM 표식 | A/B가 색 외에도 구별 |
| 적 확장 | 일반 나머지4 + 보스1 + 정예 표식2 | 상태/퇴장/HP 표시 | 64개 동시 인지 가능 |
| 맵 확장 | 배경4·성문 테마별 정상/손상/위기 | 검증된 경로/슬롯 합성 | 모든 맵의 대비·히트 영역 일치 |

권장 기본 자산 구성은 타워마다 정지 본체1 + 필요한 회전 무기1 + 반동/강조를 위한 보조 레이어0~1이다. 캐릭터형 창병/수호기사만 공격2~4프레임을 우선 검토한다. 적은 이동4프레임, 피격은 공용 tint/짧은 압축, 처치는 2~3프레임 또는 공용 축소/소멸로 시작한다. 방향은 적 정면상부/측면의2기준을 우선 시험하고 좌우 반전으로 필요한 방향을 충족하되 방패 방향 등 의미가 바뀌면 별도 원본을 받는다.

최종 프레임 수는 표본 승인 전 확정하지 않는다. 여러 독립 생성 프레임이 흔들리면 한 기준 이미지를 부품 분리해 코드로 움직인다. Gemini가 연속 프레임을 납품하지 못하면 기준 원본+부품 형태로 재요청한다. 품질을 희생해 frame count만 채우지 않는다.

### 외형별 역할 표식

궁수=가는 활/시위, 석궁=넓은 가로 활, 포탑=짧은 원통, 마탑=수직 결정, 서리=갈라진 얼음, 번개=두 갈래 전극, 화염=열린 노즐, 창병=긴 직선 창, 수호기사=방패와 굵은 몸체, 깃발=수직 천. A/B 분기는 공격 기관 형태와 공용 분기 표식으로 구별하고 과도한 장식 증가를 피한다. 적과 타워의 얼굴 표정을 매번 다르게 생성하지 않는다.

## 5. 동작·효과 사양

판정은 30Hz domain, 시각 효과는 보간된 렌더 시각을 따른다. 발사 event가 이펙트를 시작하며 애니메이션 마지막 프레임이 피해를 발생시키지 않는다. pause 시 장식도 멈추며 설정 패널만 작동한다.

|---|---|---:|---|
| 배치 | 바닥 접지→본체 96→100% | 120ms | 즉시 표시+선택 테두리 |

| 마법 | 작은 구체와 짧은 표적 링 | 120~200ms | 링1회 |
| 서리 | 적 발 아래 얼음 표시 | 효과 지속 동안 | 동일 표식 유지 |

피격 flash는 흰색 화면 덮기가 아니라 적 개체의 국소 톤 변화로 제한한다. 동일 적에 많은 공격이 와도 피격 효과를 합쳐 잦은 점멸을 만들지 않는다. 파티클·투사체 렌더 개수는 원문 예산을 지키되 피해 사건을 삭제하지 않는다. 전체 화면 카메라 흔들림은 기본0. 모든 효과는 문제 영역 clipping 밖으로 나오지 않는다.

## 6. 오디오와 UI 토큰

Gemini가 오디오 생성 가능한지는 별도 확인하며 이미지 생성 능력으로 추정하지 않는다. 생성이 불가능하면 배포권 확인된 별도 음원 또는 Codex의 간단 합성 효과음을 후보로 제시한다. 무음 상태로 핵심 게임 검증을 진행할 수 있다.

최소 목록: 메뉴BGM1, 전투BGM1, 정답/오답/배치/거래실패/강화/진화/누출/웨이브/패배 효과. 발사음은 모든 타워 개체마다 무제한 재생하지 않고 종류별 동시수와 재생 간격을 제한한다. BGM 기본20%, SFX40%는 사용자 시험용 제안. 음량은 실제 재생 확인으로 조정한다. WebAudio 첫 사용자 동작 활성화, 정지/복귀 중복재생 검사.

UI 토큰은 spacing4/8/12/16/24/32, 모서리4/8/12 중 선택, 그림자 최대1단계. 본문 고딕, 숫자 tabular, 제목에만 선택 스타일 허용. 문제18/21/24px, 보기 최소18px 후보, 줄간격1.5~1.65. 장문보기는 1열과 3줄 이상 자연 줄바꿈을 허용하고 말줄임하지 않는다. 일반 텍스트 대비4.5:1 목표, 버튼 경계·focus·비텍스트 상태3:1 목표를 실제 색 조합에서 측정한다. 미술 색 선정 자체가 접근성 통과는 아니다.

## 8. 문항 제작 계약

원문 §9~10의 필드와 승인을 유지한다. 추가 필드: `batchId`, `curriculumReference`(판/연도/단원), `evidenceArtifactId`, `licenseDecision`, `estimatedReadingLoad`, `retirementStatus`. 사전 URL과 의미 ID가 실제 같은 의미를 가리키는지 Codex가 검사하고 검수자는 학년·문맥 적합성을 승인한다.

추천 소배치: 한 학년20개 표본 → 30~50개 검증 은행 → 100개 → 300개. 처음부터 3,200개를 생성하지 않는다. 유형 비율은 유일답/학년 적합성을 만족하는 범위에서만 맞춘다. 해설은 정답의 이유를 설명하고 ‘정답은 X이기 때문입니다’처럼 답을 반복하지 않는다.

목표 길이(제안, 강제 자동 축약 금지): 지문20~90자, 짧은 보기2~30자, 문장형 보기15~65자, 해설40~100자. 초과는 반려 확정이 아니라 실제 줄바꿈/읽기량 수동 검토 대상으로 표시한다. 조사/어미가 어느 보기에서도 자연스럽게 이어지는지 검사한다. 학년 난도를 단순 글자 수로 판정하지 않는다.

자동 검사: required 필드, 4개 서로 다른 optionId/text, correctOptionId 존재, 정답 외3개 오답 이유, source와 evidence 대응, 허용 학년/유형, revision 증가, NFC, 제어문자, 문장 중 보기번호 참조, 거의 같은 문항, 출처 누락, 미승인 상태. 복수 정답/사실 정확성/학년 적합성은 자동 검사만으로 통과시키지 않는다.

각 AI 검수자는 `questionId/revision`, 검수 주체, 실제 모델/도구, 일시, 통과 또는 반려 이유를 남긴다. 오답 보기 하나라도 타당하면 보류한다. 생성 모델이 자기 결과에 `joint_review_approved`를 붙이면 인수 오류로 취급한다. 제작자는 `draft/machine_checked`만 제출한다. Codex는 세 주체의 실제 보고서를 수합하고 불일치 해소 후 승인 레지스트리를 만든다. 승인 revision의 hash가 달라지면 재검수한다. 실제 교사 검수로 표시하지 않는다. 구체 절차는 `joint_review_protocol_v0_2.md`를 따른다.

학생 배포본에서 검수자 개인정보·API 키·원문 수집 덤프를 제외한다. 표시 출처와 이용 조건에 필요한 필드는 유지한다. 결과 복습에서 `lemma`와 `senseKey`를 따로 집계한다. 정답 키는 브라우저에서 열람 가능하므로 보안 비밀로 취급하지 않는다.

## 9. 그대로 전달할 문항 요청

> jobId와 contractVersion에 맞춰 제공된 학년별 어휘 목록·실제 사전 근거·schema만 사용하여 한국어 문항 초안 20개를 만들어 주세요. 의미 ID와 근거 URL을 새로 지어내지 마세요. 각 문항은 보기4개, 유일답1개, 짧은 해설, 오답3개의 구체적 반박 이유를 포함합니다. 빈칸 문제는 모든 보기를 조사·어미까지 대입하고, 동의/반의어는 해당 문맥의 의미를 고정합니다. 근거 부족·복수 정답·부자연스러운 문장은 억지로 채우지 말고 rejection에 이유를 기록하세요. 승인 상태는 draft 또는 machine_checked까지만 사용하세요. 질문 수량보다 타당성을 우선하고, 생성/반려/수정/중복 의심 목록을 함께 제출하세요.
