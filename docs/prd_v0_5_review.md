# PRD v0.5 점검 기록

2026-10-28 · 작성: Claude Code의 Claude Opus 5.5(`claude-opus-5-5`) · 제품 구현 미착수 · 외부 Argon/Codex 검토가 반환된 문서가 아니다.

## 판단

v0.4(Codex 작성)는 전투 판정·경제·저장·오답 정책·작업 분담의 골격이 좋고, 대부분은 그대로 구현에 쓸 수 있다. 다만 **수치를 실제로 돌려 보면 드러나는 결함**이 있었다. 초보 학생이 Normal 1웨이브에서 2분 만에 지는 경우가 생기고, 한 판이 [확정] 목표 15~25분의 1.5배가 되며, ‘모르겠어요’가 정직한 학생에게 손해이고, 학교 크롬북·iPad 가로 화면이 화면 규격에서 빠져 있었다. 구현 쪽에서는 BigInt 의무·1칸=1024·부동소수 초→틱이 불필요한 복잡도와 실제 결정성 오류를 만들 수 있었다. v0.5는 이 결함만 근거와 함께 고치고 나머지 결정은 유지했다.

## 점검한 입력

- 현재 PRD v0.4 전문, v0.4 검토 기록, 작업 지시문, 작업 게시판, 인계서, 계약 파일 4종, 검산 도구.
- 원문 v0.1의 오답·모르겠어요 정책 원문(태그 없는 제안값임을 확인), v0.3 결정·추가 문서, v0.2 구현 계획의 기술 선택표.
- 41번 원화 PNG를 직접 열어 HUD·관리·문제판·지도 요소를 하나씩 대조했다. `archive/design-v0.7`의 41번 생성 지시문과 41–50 비교 문서도 확인했다. 다른 시안 이미지는 이미 삭제되어 있어 지시문과 기록만 보았다.
- npm 레지스트리(2026-10-28)에서 계획한 패키지의 최신 버전·Node 요구·peer 범위, Phaser 공식 React TS 템플릿의 `package.json`.

## 바꾸지 않은 것과 이유

- 준비 5/3문항, 생존 시 전회복, 0HP 패배 우선, 음수 PT, 오답 4초+수동 진행, 무한 웨이브, 15×9 지도·4맵 좌표, 시작 골드 120, 타워·적 기본 수치, 고비 보상: [확정]이거나 근사 모델에서 문제가 드러나지 않았다.
- 타워 수치: §7.5의 골드당 표에서 마법탑·수호기사가 낮지만 칸이 20개로 제한되어 후반에는 칸당 효율이 중요하고, 마법탑 Lv5 A는 궁수 Lv5 A보다 칸당 효율이 높다. 수치를 바꾸지 않고 S11 수용 기준을 두었다.
- Hard·Crazy 1웨이브: 무작위 배치를 용서하지 않지만, 집중형은 0/6 패배다. 관문으로 두고 안내·미리보기로 보완했다. 추가로 쉬워지게 하는 대신 S11 목표(Hard 초보형 정답률80% 패배 30% 이하)를 걸었다.
- 렌더러: Phaser+React DOM을 유지한다. 카메라 확대가 §12.4에 직접 쓰이고 규칙이 렌더러와 분리되어 있다.
- 문항 품질 절차·공동검수·스키마: 그대로 유지하고 읽기 수준 규칙만 더했다. 초안 스키마 필드는 바꾸지 않았다(`readingLoad`는 게시 빌드에서 계산).

## 사용자 확정(2026-10-28)

점검 뒤 사용자가 아래 네 결정을 확정했다. PRD v0.5에 [확정]으로 표시했고 `product.defaults.v0.5.json`의 `userDecisions`·`approval`, `balance.candidate.v0.3.json`의 `userConfirmed`에 기록했다. 확정 값은 사용자 결정 없이 바꾸지 않는다.

1. **‘모르겠어요’ 0PT·0골드** — 원래 문서의 ‘오답과 동일’은 태그 없는 제안값이었고 교육 의도상 0PT로 바꿨다.
2. **난이도 한국어 표시** — 화면은 쉬움/보통/어려움/아주 어려움, 내부 ID `Easy~Crazy`는 유지한다.
3. **배속 없음** — 읽기 시간 보호를 위해 넣지 않는다.
4. **HP 성장 115%** — S11에서 목표 시간을 벗어나면 성장률 밖의 수단(초반 완충·적 수 증가 폭·처치 골드·강화 비용)을 먼저 쓰고, 성장률 변경이 필요하면 근거와 함께 사용자 결정을 받는다(PRD §8.2). 초반 완충(1~3웨이브 간격)은 확정이 아니며 엔진 시뮬레이션에서 다시 잰다.

## 남은 위험

- 근사 모델에서도 Normal 한 판이 30~32분으로 목표보다 길다. 실제 학생은 더 적게 버틸 가능성이 높지만 확인되지 않았다.
- 정답률 60%→95%의 생존 차이가 약2웨이브로 작다. 정답이 생존보다 기록에 크게 작용한다. 학생이 ‘문제를 풀 이유’를 느끼는지는 베타에서만 알 수 있다.
- 초보형은 보스를 약 10~60%만 잡는다. 큰 보상을 체감하지 못할 수 있다.
- 궁수 집중이 균형 전략과 같거나 앞선다(§7.5 수용 기준으로 추적).
- 읽기 20초 학생은 일찍 막히지 않지만 한 판이 32~43분이다.

## 검증 기록

`node tools/validate-plan.mjs`(문서 링크·절 참조·PRD 표↔밸런스 JSON·화면 모드 계산표 재계산·맵 품질·보존 해시)와 `node tools/balance-sketch.mjs`를 실행했다. 실제 결과는 [검산 보고서](contracts/prd_v0_5_validation.json)와 PRD §17.3 표에 있다. 앱 빌드·게임 시험·브라우저·실기기·엔진 밸런스 시뮬레이션·문항 공동검수·외부 모델 실행·배포는 **미실행**이다. 이 작업은 커밋하지 않았다.

보존: v0.1·v0.3·41번 PNG는 수정하지 않았다. v0.4 PRD·검토·지시문은 맨 위에 이력 안내 한 줄만 더했고 본문은 그대로다(검산 도구가 v0.4 PRD 해시를 고정).
