## 20. 도메인 실행 계약의 구체화

### 20.1 숫자·시간·난수

논리 틱은 30Hz다. 시간은 `ceil(초×30)`이며 밀리초 원본은 정수 비율로 변환한다. 전체 run tick, wave, sequence, 누적 골드/PT, HP/피해는 BigInt를 사용한다. 좌표는 한 칸1024단위의 정수 Number, 제한된 지역 쿨다운/효과 잔여시간은 정수 Number다. Number/BigInt의 암묵적 혼합을 금지한다. JSON의 큰 정수는 십진 문자열, 음수는 PT에만 허용한다. 화면 축약 표시는 원본을 변환하지 않으며 자세히 보기에서 정확한 값을 제공한다.

경로 진행은 `progressUnits`와 이동 나머지를 저장하여 매틱 반올림 누적으로 맵별 통과 시간이 달라지지 않게 한다. 기본 적은 경로 길이/720틱 속도를 유리수로 갖는다. 종류·정예·감속 비율을 정수 비율로 합성하고 나머지를 다음 틱에 넘긴다. 모서리를 넘으면 잔여 이동량을 다음 경로 구간에 전달한다. 경로 끝 이상이면 누출이고 입구/출구에 추가 숨은 길이는 없다.

seed는 uint32, PRNG 알고리즘은 xorshift32 후보로 고정하고 0 seed는 정해진 비영값으로 매핑한다. 전투 편성/문항 선택/보기 섞기/시각 효과는 서로 다른 스트림이다. 같은 결과의 장기 재생을 위해 알고리즘·seed 유도 방식을 버전화한다. Fisher–Yates shuffle의 정수 선택은 rejection sampling으로 modulo 편향을 피한다. 암호학적 보안 용도가 아니다. 이 구현의 실제 golden vector를 테스트에 고정한다.

### 20.2 피해 공식과 정렬

범위 비교는 정수 좌표의 거리 제곱으로 하며 경계(`<=`)를 포함한다. 기본 타깃은 진행도 내림차순→생성 순번 오름차순. 실수 atan2·삼각함수는 시각 회전에만 사용한다. 부채꼴과 직선 판정은 dot/cross 정수식으로 해결하고 중간 곱이 안전 정수 범위를 넘으면 BigInt 비교한다.

직접 피해 = Lv1피해×레벨배율×분기배율×상황배율×(1+외부피해보너스)×(1−유효저항). 모든 배율은 정수 분수로 곱한 후 마지막에 내부 HP1/1000단위로 내림한다. 양의 공격이 저항 계산 후0이 되면 최소1내부단위. 무피해 지원 효과는0을 유지한다. 물리저항 무시는 최종 물리저항 합산/상한 적용 뒤 그 수치의 비율을 줄인다. 마법저항에 물리관통을 적용하지 않는다.

화상은 `Lv1 총피해 × 레벨배율 × 화상분기배율 × (1 − 유효 마법저항)`을 사용한다. 저항 수치 자체를 곱하지 않는다. 깃발 직접피해·직접피해 전용 분기는 화상에 적용하지 않는다. 출처는 타워 instanceId이며 판매 후 이미 걸린 효과는 원래 만료까지 유지한다.

화상 피해 시계는 **적 한 마리마다 하나**다. 처음 화상에 걸린 틱을 t라 하면 첫 피해는 t+15틱, 이후15틱마다 발생한다. 서로 다른 타워가 다른 시각에 맞혀도 출처별 피해 타이머를 추가하지 않는다. 같은 출처 재적중·우세 출처 변경은 기존 다음 피해 시각을 바꾸지 않는다. 각 출처는 피해 스냅샷과 고유 만료 틱을 유지하며 재적중은 자기 세기/만료만 갱신한다. 매 피해 시점에 유효 출처 중 총피해가 가장 큰 하나를 선택하고 동률은 타워 생성 순번으로 정한다.

내부 정수 총피해 D에 대해 적의 `burnRemainder`를 사용하여 `지급 = (D + burnRemainder) / 4`의 정수 몫, `새 나머지 = (D + burnRemainder) % 4`로 처리한다. 이를 통해 같은 출처의 정상4회 피해 합이 D가 되고 중간 반올림 손실을 막는다. 재적중과 우세 출처 변경은 나머지를 초기화하지 않는다. 모든 화상이 끝나면 시계와 나머지를 제거한다. 기존 출처의 작은 나머지는 다른 출처로 넘어갈 수 있으나 내부 피해1단위 미만이며 별도 추가 공격을 만들지 않는다.

화상은 적용 틱 자체에는 피해를 주지 않고 **만료 틱에 예약된 마지막 피해까지 포함**한다. t에 적용한2초 화상은 t+15/30/45/60에서4회 피해 후 제거한다. 틱 시작의 만료 정리는 화상 출처를 `currentTick > expiresTick`일 때 제거하고, 화상 피해 처리 후 `currentTick >= expiresTick`인 출처를 제거한다. 반면 감속·기절·버닝·오라의 유효 시간은 종료 틱 미포함으로 유지한다. 이 차이를 공용 만료 함수 하나로 뭉개지 않는다.

버프 범위는 타워 바닥 중심 간 거리로 판정한다. 거래 후 다음 공격 계산 전에 오라를 재계산한다. 공격 간격은 `ceil(baseIntervalTicks × branchRatio / (1 + min(0.5, externalSpeedSum)))`, 최소 `ceil(0.15×30)=5틱`이다. 이미 예약된 공격 시각은 바꾸지 않는다. 버프 만료는 `currentTick >= expiresTick` 때 공격 이전에 제거한다.

같은 틱 공격 내부 순서: 만료 정리(화상 마지막 피해 예외 포함) → 도착 예약공격(공격 생성 순번순) → 화상(적 생성 순번순으로 우세효과1개, 이후 종료 출처 정리) → 발사 가능한 타워(타워 생성 순번순) → 이동/누출 → 패배/완료. 순서는 숫자 생성 순번으로 비교하며 `tower-10`과 `tower-2` 같은 문자열 사전순을 사용하지 않는다. 즉시 공격에 죽은 적은 다음 타워 후보에서 제외한다. 새 투사체는 최소 다음 틱 도착. 동일 틱 명령은 sequence순, 정지는 나머지 명령보다 먼저 채택한다. 정지에 밀린 답안/거래는 재개 후 자동 실행하지 않고 취소하여 재입력을 받는다.

### 20.4 웨이브 편성

일반 종류 정수배정은 비보스 수 N−bossCount에 가중치를 적용한다. 내림 후 남은 자리는 나머지 큰 순→원문 적 ID 표의 순서로 배정한다. 그 후 셔플하고 정예 수만큼 비보스 위치를 무복원 추출한다. armored/swift는 별도 전투 스트림에서 동일 확률로 선택한다. 보스는 최종 배열의 `floor(0.70×(N−1))`번째(0기준)에 삽입한다.

첫 적 생성은 전투 시작 뒤 첫 틱, 이후 간격은 원문 시간의 올림 틱. 실제 생성 횟수는 N이며 보스는 추가 수가 아니다. 웨이브 PT상한은 새 PREP 진입 시 초기화. BigInt wave로 몫/나머지 계산 후 64 등 제한된 수만 Number로 변환한다.

### 20.5 문항 선택과 학습 기록

은행은 학년/승인/revision/철회 조건을 우선 필터링한다. 현재 유효 풀로 셔플 큐를 만들고 후보가 최근30문항 또는8의미 제한에 걸리면 유한 탐색한다. 없으면 의미 이력을 오래된 것부터 완화→문항 이력을 오래된 것부터 완화한다. 즉시 직전 문항은 대안이 하나라도 있으면 피하고 유효풀이1개일 때만 즉시 반복을 허용한다. 무한 재추첨하지 않는다. 큐·cursor·완화 기록·보기 순서를 저장한다.

유형 가중치는 원문의 편성 예시를 후보로 사용하되 승인 문항이 없는 유형은 유효 유형으로 재분배한다. 잘못된 학년이나 미승인 문항으로 빈 유형을 메우지 않는다. 문항/의미 반복 이력은 encounter 생성 때 기록하며 무효 교체는 출제 취소 이력으로 남긴다. 점수는 제출 기준으로만 반영한다.

결과에서 문제 수, 서로 다른 표제어 수, 서로 다른 의미 수, 오답 복습을 구분한다. 초기 MVP는 계정 간 개인화 숙련도 모델·매일 복습 알림을 추가하지 않는다. 학습 효과나 숙련도 점수를 실제 검증 없이 표시하지 않는다.

## 21. 반응형·인터랙션의 실행 기준

**현재 기준(v0.3 인계):** 사용자가 **41번 왕국 원정대** 화풍을 선택했다. `docs/style-lock-v1.md`와 §25가 최종 디자인 방향이다. 한글·훈민정음·세종대왕은 일부 고정 장식물에만 사용하고, 자연물과 섞는다. 전투 자산 전체를 한글 소재로 통일하지 않는다. 41번 외 프로젝트 이미지는 삭제했으며 과거 비교 코드와 지시문은 `docs/archive/`의 이력이다.

전체 전장은 한 화면에서 파악되는 경계 안에 길과 충분한 설치 공간을 함께 둔다. 길은 긴 우회와 여러 사거리 교차 기회를 만들고, 바닥 전체의 반복 격자는 숨긴다. 타워는 정수 셀의 정확한 중심에 고정하며 큰 실루엣을 유지한다. 길·설치 가능·영구 장식의 점유 집합은 겹치지 않는다. 장식의 불규칙한 외곽이 실제 판정을 바꾸지 않는다. 기존 v0.5/0.6의 격자 수·경로 길이·설치 수는 후보이며 최종 밸런스가 아니다.

UI는 세계관의 장착대·조작판·트레이·탭 등 구체적인 구조로 만든다. 평면 배경에 같은 텍스트 카드만 반복하지 않는다. 선택·장착·강화 가능 여부와 눌림을 그림의 구조와 실제 입력 상태로 함께 표현한다. 밝은 중간 톤과 절제된 음영, 읽기 쉬운 윤곽이 기준이다. 어두운 사이버 화면·과밀한 금속 장식·잔가지·과한 빛은 기본값이 아니다. 정답을 유추할 수 있게 보기마다 장식 강도를 다르게 하지 않는다.

문제는 **하단**, 기물 관리는 **우측**을 기본으로 한다. 작은 화면에서는 기물 관리를 접고 문제를 아래에 유지한다. 이미지 안의 한국어와 가격은 예시이며 실제 구현은 DOM/런타임 텍스트다. 최종 UI에서는 예시 그림을 통째로 배경에 놓고 클릭 영역만 맞추는 방식을 쓰지 않는다.

몬스터는 종별 가벼운 보행·독립 위상·방향 전환을 갖는다. 공격은 기물의 포구/손 소켓→투사체 비행→명중 이벤트→국소 피격 반응으로 연결한다. 시각 흔들림이 점유 좌표나 이동 진행도를 바꾸지 않는다. 정지 그림을 동일 위상으로 미는 방식은 최종 인수 기준을 만족하지 않는다. 제작 단계·시간 예산·발사점/피벗 계약은 v0.7 설계 문서를 따른다.

과거 41–50번은 정지 콘셉트, 동작 표본은 별도 예시였다. 현재는 41번 화풍만 확정했고 나머지 이미지는 삭제했다. 과거 표본의 모바일 중앙 확대는 최종 전체 맵 UX가 아니다. 선택 이미지의 길·슬롯·가격은 확정 데이터가 아니므로 실제 맵 좌표와 DOM/런타임 텍스트로 다시 구성한다. 사용자 첨부는 맵 형태만 참고했고 최종 자산은 자체 제작한다.

| 폭/조건 | 배치 제안 | 입력 보호 |
|---|---|---|
| 1024px 이상 | 상단 HUD, 전장과 도구 측면, 하단 독립 문제 | 상점이 보기 영역을 덮지 않음 |
| 600~1023px | 전장 중심, 압축 도구행, 하단 문제 | 태블릿 회전 시 선택/문항 유지 |
| 599px 이하 | HUD→정사각 전장→한줄 도구→문제 | 상점은 문서 흐름 내 펼침, 문제 영역 명시적 스크롤 |
| 낮은 가로 화면 | 전장 아래 문제 유지, 관리 접기, 세로 스크롤 허용 | 한쪽을 숨기거나 글자를 극소화하지 않음 |

320px에서는 선택된 맵의 실제 셀 폭이44px보다 작아질 수 있다. 실제 칸을 가짜로 크게 겹쳐 터치시키지 않는다. 작은 화면은 칸 탭으로 먼저 선택 표시, ‘여기에 설치’ 확인 또는 44px 이상 슬롯 목록으로 구매한다. 목록은 행/열 좌표와 빈칸 상태를 제공한다. 드래그는 데스크톱/충분한 크기에서만 편의 기능이며 전체 지원 필수 조작이 아니다.

브라우저 확대를 막는 viewport 설정 금지. drag surface에만 `touch-action`을 제한하고 문항 스크롤은 보존한다. pointercancel/회전 시 진행 중 drag만 취소하며 골드를 차감하지 않는다. 키보드/스크린리더는 슬롯 목록과 DOM 컨트롤을 사용한다. 실시간 전투 전체를 완전 비시각 접근 가능하다고 주장하지 않으며 실제 지원 범위를 검증한다.

pause는 게임 입력 DOM을 inert 처리하고 문제/보기/해설을 렌더 트리에서 숨긴 뒤 불투명 정지층을 둔다. 포커스를 정지창으로 이동하고 닫을 때 안전한 시작 위치로 복원한다. CSS로만 가린 채 읽기/응답이 가능한 상태를 남기지 않는다. 숫자 단축키는 composing/repeat/텍스트 입력/포커스 상태를 검사하고 질문 전환마다 keyup 또는 새 pointerdown을 요구한다.

첫 안내는 ‘문제를 풀면 골드 → 궁수 선택 → 칸 선택 → 시작 → 생존 시 성문 회복’의 짧은 연습이다. 연습은 별도 practice run으로 공개 기록에서 제외하며 정규 run의 점수/골드/은행 시드를 변경하지 않는다. 건너뛰기와 설명서 재열기를 제공한다. 실제 정규 준비 문항을 연습이라며 무보상으로 바꾸지 않는다.

## 22. 제작/성능/장애 기준의 강화

Gemini에는 최종 스타일 선택 뒤 타워1/적1/성문1/배경1의 표본부터 요청한다. 대량 프레임 생성 전에 실제 모바일 크기로 시험한다. 기본30타워 외형은 부품 회전/반동과 포구 소켓을 우선한다. 몬스터는 이동4포즈·피격1포즈 표본의 동일 피벗·접지·다리 교대를 확인한 후 확대 제작한다. 두 포즈와 절차적 흔들림을 사용한 현재 표본은 최종 보행 에셋 인수 완료가 아니다. UI의 한국어·숫자는 항상 DOM 또는 런타임 텍스트다.

에셋 누락은 비공개 개발에서만 눈에 띄는 placeholder를 허용한다. 공개 빌드에서는 필수 자산 누락/미승인 콘텐츠를 빌드 단계에서 차단한다. 장식 효과 실패는 간편 모드로 낮출 수 있으나 성문/적/타워/문항이 없으면 실행을 시작하지 않는다.

pause reason은 USER/HIDDEN/PERFORMANCE/STORAGE/CONTEXT_LOST/OWNERSHIP을 집합으로 관리한다. 사용자 정지 해제만으로 저장 실패나 소유권 오류가 풀리지 않는다. `RECOVERY_REQUIRED`는 실패 원인과 재시도/개인 기록 보존 종료를 구분한다. 자동 복구 뒤에도 수동 재개를 요구한다.

원문 다운로드·FPS 목표를 유지한다. 20타워×64적×상한 효과에서 frame p95, 입력응답 p95, 30분 메모리 변화, 홈 왕복20회 자원 수를 측정한다. 수치 예산은 목표이지 이번 문서의 실측 결과가 아니다. Playwright WebKit 통과와 iPhone Safari 실기기 통과를 구분한다.

## 23. 제작 속도를 높이는 변경 관리

1. 먼저 순수 규칙 엔진과 승인 은행의 작은 완주 흐름을 만든다. 서버/최종 아트/4학년 전량을 기다리지 않는다. 미승인 데이터는 내부 fixture로만 사용한다.
2. 각 수직 기능은 규칙→UI→저장→복원→오류 경로까지 닫고 다음 기능으로 이동한다. 모든 화면을 먼저 꾸미고 저장을 나중에 붙이지 않는다.
3. 튜닝은 버전 설정 파일, 스타일은 토큰/에셋 manifest, 문항은 은행 데이터로 변경한다. 같은 변경을 코드 여러 군데에서 반복하지 않는다.
4. 업무 단위를 1~2개 명확한 완료 조건으로 나누고 변경마다 검증 결과를 남긴다. AI가 한 번에 전체 프로젝트를 새로 생성해 기존 계약을 덮지 않는다.
5. Codex가 Gemini 결과를 자동 검사·정리하고 Claude/Argon 검수 결과를 수합한다. 사용자에게 아틀라스 패킹·파일명 변경·JSON 교정 작업을 떠넘기지 않는다. 사용자는 베타테스트와 최종 취향/공개 판단을 맡는다.

## 24. 현재 증거와 다음 결정
