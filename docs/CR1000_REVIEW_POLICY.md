# CR-1000 실용 검수 정책 — cr1000-practical-v1

2026-11-06 사용자 지시: 판정 기준을 대폭 완화하고 중간 과정을 간소화하되, 학습 품질과 자연스러운 한국어를 지킨다. 앞선 계획서의 취향 중심 반려·추가 검수 의무보다 이 정책을 우선한다.

## 1. 수정이 필요한 오류와 권고

| 수정·격리 대상 | 통과 가능하며 필요하면 권고만 기록 |
|---|---|
| 실제 복수 정답, 정답 없음, 키 불일치 | 문맥에 없는 상황을 가정해야만 가능한 다른 해석 |
| 사전의 표제어·품사·뜻 불일치, 근거 부족 | 표현을 사전 문구와 똑같이 맞추자는 취향 |
| 해설·오답 이유의 오류, 모순, 이유 없는 동어반복 | 정확하고 자연스러운 짧은 해설에 부연을 추가하자는 제안 |
| 비문, 틀린 맞춤법·조사, 이해 불가능한 상황 | 자연스러운 다른 표현, 허용 표기, 통상적인 생략 |
| 문맥으로도 해결 못 하는 전문 지식, 부적절한 내용 | 목표 어휘를 아직 모른다는 사실, 교과서 출현 시기 미확인, 미세한 tier 차이 |
| 뜻을 몰라도 형식만 보고 답이 드러나는 단서 | 목표 낱말을 뜻 묻는 발문에 쓰기, 보기 길이의 작은 차이 |

`fail`은 구체적인 오류에, `uncertain`은 판정에 꼭 필요한 정보가 없어 실질적 오류를 배제할 수 없을 때 쓴다. 취향만 남으면 `pass`와 선택적인 `[권고]`를 쓴다. **기존 fail/uncertain을 코드가 일괄 pass로 바꾸지 않는다.** 새 판정 요청부터 같은 기준을 Codex·Claude에게 적용한다.

통과 findings는 `[]`로 충분하다. 지적은 문제 구절 또는 대안 정답과 최소 수정 한 가지만 쓴다. 긴 칭찬·전체 문항 재작성·반복 지적은 생략한다.

## 2. AI SLOP 금지

어색한 직역, 억지 인과관계·교훈, 불필요하게 거창한 추상 표현, 내용 없는 상투 문장을 구체적인 문제 구절로 판정한다. 특정 단어가 있다는 이유만으로 반려하지 않는다.

제작·수정은 아이가 겪을 만한 구체적인 상황과 짧고 분명한 말을 쓴다. 한 문장에 조건을 욱여넣는 대신 필요한 경우 짧은 두 문장으로 쓴다. 읽기량 상한은 유지한다. 해설은 정답 이유, 오답 이유는 그 뜻이 상황과 다른 이유를 말한다. 이미 자연스럽고 정확한 부분은 다시 쓰지 않는다.

## 3. 간소화한 실행

- `content-loop --gate --stage-only --until S3`로 대기 파일 위에서 여러 배치의 수준 판정 → Codex 검수 → 수정·재검수를 자동 진행한다. 단계마다 수동 실행기·인계 커밋을 만들지 않는다.
- `--skip-level-spotcheck`: 두 독립 수준 판정과 합의 계산은 유지한다. 결과 합의에 반영되지 않는 rule 4 참고 표본 재호출만 생략한다. 기존 `spotCheck` 표지는 남긴다.
- `--skip-argon-fresh`: 보충 제작자의 추가 새 문맥 검수만 생략한다. 제작 자체 반박과 독립 Codex·Claude 검수는 유지한다. 이미 있는 Argon 실패 기록은 무시하거나 지우지 않는다.
- 완료한 동일 revision·해시 판정은 재사용한다. 정답 뜻풀이가 노출됐던 예전 Codex 검수는 독립 풀이로 승격하지 않고 D3 재검수를 유지한다.
- 학습 과제가 바뀐 수정판의 수준 점수를 추측으로 승계하지 않는다. 새 판을 읽었다는 근거를 만들지 않는다.
- 추적 콘텐츠는 `commit-lock`에서만 반영한다. `--stage-only` 결과는 `awaitingApply`이며 공개 승인으로 세지 않는다. 서버 시험·최종 은행 검증은 반영 시 실행한다.
- 배치 단위로 소유권을 나누고 같은 배치를 두 실행기가 수정하지 않는다. 기본 요약 파일과 별개로 `--summary-file`을 사용한다. 신규 staging 전용 배치는 이 모드에서 아직 지원하지 않으며 먼저 잠금 반영이 필요하다.
