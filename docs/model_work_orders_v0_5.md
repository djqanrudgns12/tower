현재 기준: [PRD v0.5](../vocabulary_td_prd_v0_5.md) §18~19. 프로젝트 루트는 `/Users/bodyking/Desktop/vibecoding/tower`. 다른 컴퓨터에서는 실제 checkout 경로로 바꾼다. 사용자가 구현을 지시한 후 총괄이 job별 빈 값을 채워 발행한다. 빈값/추정 hash를 채운 것처럼 보고하지 않는다.

## 1. 운영 방식

**작업 묶음은 병렬, 총괄은 한 명, 교대는 인계서 한 번**이다. Codex(Astra)와 Claude(Opus)가 전체 지휘를 교대하고, Argon 4는 한정된 UI/UX·소규모 구현·문항 작업을 맡는다. Codex는 이미지 생성 수단도 운용한다. Claude는 리깅/애니메이션과 어려운 구현을 맡을 수 있다. 역할은 모델의 서열표가 아니다.

같은 기능을 세 모델에게 각각 만들게 하지 않는다. 동일 파일의 동시 작성, 수정 파일을 모른 채 덮어쓰기, 모델 간 장시간 토론을 하지 않는다. 공통 계약은 총괄이 잠그고 작업자는 정해진 입력→출력만 만든다. 질문은 계약 변경 요구/국소 보류로 반환하며 다른 독립 작업은 계속한다. 사용자가 통합용 파일명 수정·아틀라스 패킹·JSON 교정을 직접 수행하는 흐름으로 넘기지 않는다.

## 3. 작업 요청서 양식

패키지 경로 출발안: `docs/work-packages/<jobId>/REQUEST.md`, `RETURN.md`, `evidence/`. 실제 발행 때만 만든다. manifest/계약 파일은 상대경로+실제 SHA-256으로 지정한다.

```yaml
jobId: UI-Q-001
status: READY
owner: Argon 4
commander: 실제 현재 총괄
baseCommit: 실제 commit
contractVersion: 실제 version
contractHash: 실제 입력 계약 hash
inputFiles:
  - 실제 PRD 해당 절과 contract/fixture 경로
allowedPaths:
  - src/ui/question/**
  - tests/ui/question/**
forbiddenPaths:
  - src/domain/**
  - src/contracts/**
  - package.json
  - package-lock.json
deliverable: 문항 패널과 정답/오답/긴보기/키보드 상태
acceptance:
  - PRD V02/V04와 문항 전환 유령 입력 방지
  - 320px·큰글자·24px에서 잘림 없는 모든 보기
dependencies: 고정된 QuestionPanelProps와 fixture 제공
returnPath: docs/work-packages/UI-Q-001/RETURN.md
```

실제 파일이 아직 없으면 총괄이 선행 계약을 먼저 만든다. 작업자가 repo 전체를 임의 설계하여 빈 계약을 메우게 하지 않는다. allowedPaths를 맞추기 위해 새 공용 타입의 복사본을 만들지 않는다.

## 8. 코드/미술 작업 RETURN 형식

```text
jobId / 실제 작업자와 모델 / 완료일
상태: RETURNED 또는 HOLD (최종 ACCEPTED는 총괄만 부여)
입력 baseCommit / contractHash / 사용 원본 hash
변경 파일: 경로, 목적, 실제 diff 또는 산출물 hash
구현된 행동: REQUEST의 인수 조건별 결과
실행 검사: 명령, 환경, exit/result, 증거 파일
재사용 검사: 어느 파일 상태에서 통과했는지
미실행: 사유와 필요한 입력
알려진 결함: 재현 단계, 영향 범위
REQUESTED_CONTRACT_CHANGE: 있으면 최소 예시와 영향
통합 방법: 적용 대상, 의존, 충돌 예상, 롤백 경로
다음 첫 행동: 실제 실행할 작업 하나
```

## 9. 총괄 교대용 인계서

```text
인계하는 총괄 / 인수할 총괄 / 이전 총괄 작성 잠금 해제 시각
현재 구간 P1/P2/P3 / 실제 통과한 게이트 / 공개 승인 여부
기준 commit / dirty 상태 / 보존할 사용자 변경 / 로컬 원본 위치
PRD·계약·버전·hash와 이번에 변경된 결정
완료한 실행물과 실제 동작 경로
통과 검사와 해당 작업 트리/해시, 실패 재현, 미실행 기기
RUNNING/RETURNED/HOLD job 목록: 담당·소유파일·계약hash·RETURN 위치
수신했으나 아직 통합하지 않은 패치/이미지/문항
현재 미해결 blocker와 독립적으로 계속할 작업
다음 첫 실행 명령 또는 수정 파일
금지 범위: 미승인 공개/DB/commit/push, 보존 원본/과거 시안 재생성
```

새 총괄은 이 인계서·작업 게시판·현재 diff를 읽고 첫 미완료 단위를 수행한다. 읽었다는 보고만 남기고 끝내지 않는다. 테스트 재사용은 같은 입력/파일 상태가 입증될 때만 한다. 이전 총괄의 판단을 비판하기 위해 전부 다시 만드는 작업은 발행하지 않는다.

## 10. 문항의 독립 검토 묶음

Argon의 정답키/해설이 보이지 않는 별도 `blind-input.json`을 총괄이 만들고 Codex와 Claude의 **새 검토 문맥**에 각각 제공한다. 먼저 선택/복수답/근거부족을 기록한 반환물을 받은 뒤 source/해설과 대조한다. 이미 정답을 본 같은 문맥에서 ‘독립 풀이’라고 쓰지 않는다. 보고서에는 questionId/revision/contentHash, 실제 model/tool, blindChoice, source/uniqueness/grade/language/explanation verdict, findings/evidence를 넣는다.

세 보고서 중 fail/uncertain이 하나라도 있으면 격리한다. 두 번 수정 후에도 해결되지 않으면 제외한다. 동일 revision의 통과 보고서를 다시 요청하지 않는다. 규칙은 유지하되 개별 모델끼리 설득 대화를 주고받는 방식으로 운영하지 않는다.
