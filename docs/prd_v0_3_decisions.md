## 25. 최종 인계 결정: 41번 화풍·웨이브 무드·5배수 고비

2026-10-27 사용자 확정. **이 절은 이전 시안·선택 대기 문구와 충돌할 때 우선한다.** 이번 작업은 문서 정리와 GitHub 인계이며 제품 구현을 시작하지 않는다.

### 25.1 화풍 확정: 왕국 원정대

선택은 **41번 왕국 원정대**다. 유일하게 보존하는 그림은 `docs/assets/design-41-kingdom-expedition.png`이며 `docs/style-lock-v1.md`가 제작 기준이다. 42–50번이나 ‘숲의 파수대’ 등의 이전 UI 선택 이벤트는 승인 사항이 아니다. 41번의 **화풍**을 선택한 것이며 이미지 속 가격·타워 수·정답 강조·맵 연결·버튼 배치 세부를 게임 규칙으로 확정한 것은 아니다.

밝은 모험 판타지, 둥글고 선명한 캐릭터 윤곽, 절제된 면 채색, 목재·석재·청동의 읽기 쉬운 큰 형태를 따른다. 장비함 홈·방패 초상화·누르는 답안 키를 UI 소재로 삼되, 과한 금장·그림자·나뭇결·꽃무늬·발광은 줄인다. 일반 웹페이지처럼 설명 카드와 텍스트만 쌓는 구성을 피한다. 에셋은 자체 제작하며 기존 게임의 그림을 가져오지 않는다.

한글·훈민정음·세종대왕 모티프는 **일부 영구 배치 장식물**에만 사용한다. 나무·수풀·바위 등 자연물과 함께 배치한다. 전투 타워·몬스터·투사체까지 학자·붓·활자로 통일하지 않는다. 장식은 실제 점유 칸을 막되 공격·강화·판매 대상이 아니다.

### 25.2 같은 맵에서 웨이브별 분위기 변화

**확정 방향:** 같은 맵을 사용하더라도 웨이브마다 배경의 분위기와 전투 긴장감이 조금씩 달라진다. 매 웨이브마다 별도 맵이나 고해상도 배경을 새로 만드는 요구가 아니다. 원래 4개 맵 범위도 유지한다.

고정하는 것: 경로 좌표, 설치 가능 칸, 영구 장식 점유, 이미 설치된 타워, 발사점·클릭 판정, 저장된 진행 상황. 바꿀 수 있는 것은 지면/하늘의 제한된 색 보정, 배경 가장자리의 바람·잎·먼지, 깃발·횃불 상태, 얕은 원경·앰비언스와 음악 강도다. 변화가 적·길·문항을 가리지 않아야 한다. 밤·안개를 표현해도 화면을 어둡게 덮지 않는다.

아래는 **연출 제안**, 확정 날씨표가 아니다.

| 5웨이브 묶음 안의 위치 | 무드 제안 | 전투 가독성 |
|---|---|---|
| 1 | 밝고 안정적인 낮, 새 구간의 숨 고르기 | 기존 타워·길·설치 칸 그대로 |
| 2 | 바람·풀색의 미세한 변화 | 움직이는 장식은 가장자리에 한정 |
| 3 | 따뜻한 빛 또는 얇은 구름 | 전체 화면 광량 변화 제한 |
| 4 | 깃발·먼지·배경음으로 고비 예고 | 문항 입력 중 번쩍임·가림 없음 |
| 5 | 보스 예고와 대비가 선명한 긴장 무드 | 암전·시야 축소·경로 변경 없음 |

6/11/16/21에서는 밝은 기준으로 돌아오되 묶음별 팔레트/환경 조합을 조금 바꾸는 방향을 제안한다. 실제 무드 ID·변화 폭·전환 시간·음악은 원화 표본과 실기기 검증 뒤 잠근다. 무드가 적 능력치를 직접 바꾸지 않는다.

### 25.3 5/10/15/20… 웨이브의 강한 적과 보상

**확정 방향:** 5의 배수는 강한 적과 더 큰 보상을 체감하는 고비다. 20에서 끝내지 않고 무한 웨이브에도 계속 적용한다. 원문 §8.2의 ‘총 적 수 안에 보스 1마리’ 규칙을 출발점으로 삼는다. 기존 보스 배율에 별도 배율을 무심코 한 번 더 곱하거나 보스를 추가로 중복 생성하지 않는다.

`isMilestone = wave % 5 == 0`, `milestoneIndex = floor(wave / 5)`를 기준으로 편성·보상·연출을 서로 다른 데이터로 연결한다. 일반 성장곡선 위에서 보스·정예 비중·조합·체력 가운데 무엇으로 압박을 줄지 버전 있는 밸런스 설정에 명시한다. 초기 5웨이브가 회복 불가능한 난도 벽이 되거나, 6웨이브가 앞선 투자와 무관하게 붕괴하지 않도록 4→5→6, 9→10→11, 19→20→21을 함께 검증한다.

보상 **강화 방향은 확정**, 지급 종류·금액·배율·적용 조건은 아직 미정이다. 제안은 기존 보스 처치 보상과 구간 완료 보너스를 구분하고, 첫 비공개판에서는 골드 중심으로 검증하는 것이다. 새 성장 재화·장비 뽑기·영구 메타 성장은 자동으로 범위에 넣지 않는다. 학습 PT의 의미와 기존 웨이브 일반 처치 PT 상한을 임의로 바꾸지 않는다.

구현 전 다음을 닫아야 한다.

- 보스 처치 보상과 고비 생존 보너스의 각각 지급 여부/금액. 보스 누출 시 기존 처치 보상은 0이며, 생존 보너스 지급 조건은 별도로 정한다.
- 성문 0HP 패배는 회복·다음 웨이브·고비 클리어 보너스보다 우선한다. 이미 적법하게 확정된 처치 보상을 뒤늦게 중복 지급하거나 취소하지 않는다.
- 보너스가 있다면 `runId + wave + rewardType` 멱등키와 지급 장부를 상태 전이에 포함한다. 저장·재개·연타·애니메이션 재생으로 재지급하지 않는다.
- 보상 알림은 전장 정리 후 짧게 보이고 문제를 가리지 않는다. 지급은 도메인 이벤트에서 결정하며 상자 애니메이션 완료 콜백에서 돈을 만들지 않는다.
- 5/10/15/20 이후에도 난도·수치·효과 상한이 유지되는지 검사한다. 새로운 배율을 정하기 전 기존 보스/난이도/정예/보상 배율과의 곱셈 순서를 문서화한다.

### 25.4 동작·배치·반응형의 필수 기준

타워는 격자 중심에 맞추고, 기물의 존재감이 작아지면 칸 수·배치 밀도를 조정한다. 긴 우회 경로와 충분한 설치 공간을 갖는 한눈에 들어오는 전장을 유지한다. 곡선처럼 보이는 길 가장자리가 좌표나 충돌 판정을 바꾸면 안 된다. 생성 이미지 자체를 맵 좌표로 간주하지 않는다.

발사 준비→포구/손 소켓 발사→탄 이동→명중→피격 반응을 실제 이벤트로 연결한다. 몬스터는 독립적인 보행 위상·작은 몸 동작·방향 전환을 갖고, 고정된 그림을 일정 간격으로 미는 느낌을 피한다. 피격 시 짧은 눌림/윤곽/파편을 주되 실제 넉백 효과 없이 경로 진행도를 바꾸지 않는다. 도메인 30Hz와 시각 보간을 분리한다. 과거 동작 표본의 60Hz는 제품 규칙 변경이 아니다.

문제는 하단, 기물 관리는 우측을 기본으로 한다. 작은 화면은 관리를 접고 문제와 보기를 충분한 크기로 남긴다. 전체 맵 확인과 확대 배치 조작은 함께 제공할 방안을 검증한다. 기존 동작 표본의 중앙 확대 잘라보기는 최종 모바일 UX가 아니다.

### 25.5 이전 컴퓨터의 작업 인계와 완료 범위

지원 대상은 태블릿·iOS·Android·데스크톱, 개발 확인은 데스크톱이다. 한 학년 비공개 검증 후 3–6학년·4맵·10타워/20분기 등 원문 전체 범위로 공개한다. 독립 사이트·독립 DB를 유지하며 쌤유니버스는 나중에 메뉴/일반 링크로 연결할 수 있다. DB 통합은 요구하지 않았다.

Codex는 설계·구현·통합·자동 검사를 맡고, Gemini Argon은 문항 초안·최종 에셋 제작에 분담한다. 문항은 Argon·Codex·Claude의 실제 공동검수 기록을 수합하고 사용자가 베타테스트한다. 외부 AI 검수·교사 승인·교육적 검증이 이미 완료됐다고 표시하지 않는다.

완료: 원문 보존, 도메인/콘텐츠/에셋/저장/운영 계약 초안, 단계별 계획, 디자인 탐색, 41번 화풍 결정, 브라우저 동작 표본의 제한적 검증, 문서 인계. 미완료: 실제 제품 앱, 승인 문항 은행, 최종 제작용 에셋, 최종 맵·보상 밸런스, 실기기 성능, 외부 공동검수, 서비스 배포. 과거 예시 코드·검사 결과는 `docs/archive/`의 이력이며 실행이나 통과를 현재 게임의 완성으로 해석하지 않는다.

다음 컴퓨터에서는 `README.md` → `docs/HANDOFF.md` → 이 통합 PRD → `docs/style-lock-v1.md` → 상세 계획 순으로 읽는다. **새 지시가 오기 전 구현을 시작하지 않는다.** 후속 구현 지시가 오면 디자인 10안을 다시 생성하지 말고 41번 기준의 작은 제작 표본과 규칙 엔진부터 시작한다.
