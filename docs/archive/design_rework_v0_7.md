# 게임 화면 41–50안과 동작 표본

2026-10-27 · 스타일 선택 전 · 최신 사용자 정정 반영

## 이번에 바로잡은 범위

한글·훈민정음·세종대왕은 **처음부터 배치된 일부 고정 장식물**의 소재다. 전투 타워·몬스터·투사체 전체를 그 소재로 통일하지 않는다. 수풀·나무·바위 등 자연물과 문화 장식을 함께 사용한다. 문화 장식은 전투 능력·정답 힌트·구매·강화 기능을 갖지 않는다. v0.6의 학자/붓/활자 중심 전투 에셋 확장은 사용자의 요구가 아니었으며 채택하지 않는다.

사용자가 긍정적으로 평가한 에셋 복잡도는 유지하되, 화면 전체를 밋밋한 바탕·텍스트·동일한 카드로 만드는 방식을 바꾼다. UI의 외곽, 기물을 끼우는 방식, 선택 상태, 눌림, 초상화 위치, 재료를 세계관과 함께 설계한다. 어두운 화면이나 과밀한 장식을 기본값으로 두지 않는다.

## 산출물과 범위

- `design-v0.7/index.html`: 41–50번 정지 콘셉트 10개 비교. 각 화면을 별도 이미지로 생성했다. 원본 확대, 번호 이동, 전체 비교를 제공한다.
- `design-v0.7/motion.html`: 별도 실행 표본 1개. 발사·비행·명중·보행·정지·기물 선택·예시 답안 입력을 확인한다. 10개 화면 모두가 실행되는 게임이라는 뜻이 아니다.
- `design-v0.7/manifest.json`: 실제 사용하는 10개 이미지와 표본 아틀라스의 출처. `prompts.json`은 최초 지시문, `prompt-revisions.json`은 최종 45·48번 재작업 지시문이다. 내장 imagegen 사용. 생성 원본은 보존했다.
- `design-v0.7/inspection.json`: 브라우저 구조·동작 검증 기록. 실기기 성능이나 정식 게임 검증 결과가 아니다.

생성 화면의 글자·가격·버튼 개수·맵 연결·슬롯 수는 **화풍 비교용 표현**이다. 최종 스프라이트, 9-slice UI, 좌표 맵, 문항 데이터가 아니다. 실제 구현은 정수 좌표와 DOM/런타임 텍스트로 다시 구성하며, 이미지 속 버튼이나 길을 그대로 클릭 판정에 쓰지 않는다. 정지 그림의 곡선이 기존 격자 규칙을 바꾸지 않는다.

## 공통 UI 계약

1. 전장과 문제를 동시에 읽는다. 데스크톱은 우측 기물 관리·하단 전체 폭 문제. 모바일은 아래 문제를 유지하고 관리를 별도 펼침 영역으로 전환한다. 관리창이 답안을 덮지 않는다.
2. 전투 HUD에는 생존·웨이브·재화·배속/정지만 우선 노출한다. 설명문은 선택된 기물의 정보에서 펼친다. 장식 테두리가 문항보다 많은 시선을 차지하지 않는다.
3. 기물 선택은 장착 홈의 밝기/윤곽, 전장의 선택 바닥, 큰 초상화가 함께 변한다. 눌린 답안은 짧은 높이 변화로 입력을 확인한다. 색만으로 상태를 구분하지 않는다.
4. 미선택 답안은 같은 시각적 우선순위다. 정답을 유추할 수 있는 삽화·색·장식 차이를 넣지 않는다. 생성 이미지의 답안 색은 최종 규칙이 아니다.
5. 강화는 가격·전후 능력·불가능한 이유를 해당 조작부에서 바로 읽게 한다. 판매는 실수 방지를 위한 2단계 확인을 둔다. 이 두 경제 조작은 현재 동작 표본에 연결하지 않았다.
6. UI 그림에는 글자를 구워 넣지 않는다. 9-slice 바탕·테두리·아이콘과 DOM 텍스트를 분리한다. 모바일 긴 보기의 줄바꿈, 글자 확대, 44px 이상의 실측 터치 크기를 검사한다.

## 공간과 배치 계약

- 경로, 설치 가능, 영구 점유 장식은 각각 분리한 좌표 집합이다. 타워의 기준점은 `(col + 0.5, row + 0.5)`다. 전체 바둑판 선은 평소 숨기고 설치/확인 시 필요한 셀만 표시한다.
- 맵 내부 경로는 여러 번 지나가며 다양한 교차 사거리를 만든다. 정확한 칸 수·체류 시간·배치 수는 선택된 화풍과 별개로 밸런스 검증한다. 생성 그림의 막힌 분기·겹친 소품은 확정 맵에 반영하지 않는다.
- 길의 논리 중심선은 고정하되, 외곽 흙색·잔돌·풀의 뭉침과 낮은 지형 높이로 반복감을 줄인다. 콜라이더나 이동 속도를 무작위 노이즈로 흔들지 않는다.
- 문화 장식은 맵마다 작은 기념 공간 1–2곳을 후보로 두고 자연물과 섞는다. 수량은 확정 밸런스가 아니다. 세종상·훈민정음 모티프는 전투 기물의 기본 소재로 확장하지 않는다.
- 모바일 전체 맵은 항상 확인 가능하게 설계한다. 작은 셀 입력은 확대 배치 모드/슬롯 목록/설치 확인으로 보완한다. **현재 동작 확대 표본은 모바일에서 중앙 일부를 확대**하므로 전체 맵 UX의 완료 증거가 아니다.

## 동작 표본에서 확인하는 것

표본은 14×7 격자, 기물 2개, 고정 장식 8개, 몬스터 11개를 사용한다. 최종 맵·편성 제안이 아닌 확대 동작 관찰용이다. 기물·적·장식을 새로 생성한 투명 아틀라스에서 읽는다. 알파 측정은 PNG를 수정하지 않고 원본 영역을 구한다. 두 고블린 포즈의 프레임 경계와 발 기준점을 통일해 그림 교체 때 크기가 튀지 않게 했다.

| 단계 | 표본 구현 | 정식 제작 계약 |
|---|---|---|
| 발사 준비 | 대포 약 100ms, 마법사 약 180ms | 실제 공격 주기 내부에 포함. 시각 준비 시간 때문에 공격률을 중복 지연하지 않음 |
| 발사 위치 | 이미지의 포구/손 로컬 소켓을 좌우 반전·기울기와 함께 월드 변환 | sourceSize, trim, pivot, muzzle, facing을 manifest에 저장. 애니메이션별 소켓 위치 검수 |
| 투사체 | 280–680ms 비행. 포탄은 고정 지점, 마법탄은 지정된 적 추적 | PRD의 공격 종류별 도착틱·대상 소멸·범위 규칙 사용. 표본 속도를 정식 밸런스로 사용하지 않음 |
| 발사 반동 | 짧은 기물 후퇴·손 시전·포구 점멸 | 기물의 점유 셀·충돌 좌표는 움직이지 않음. 포신/몸 분리 원화로 제작 |
| 보행 | 두 포즈 + 독립 위상 + 작은 높이/기울기, 벌레는 더 낮은 흔들림 | 최소 이동 4포즈 표본을 먼저 검수. 실제 다리 교대·발 접지·동일 피벗을 확인한 뒤 확장 |
| 회전 | 모서리의 짧은 곡선, 좌우 방향 반전 | 경로 진행도와 시각 방향 전환을 분리. 위/아래/좌우 방향 원화의 필요량은 최종 화풍에 맞춰 결정 |
| 명중 | 도착 시 피해 + 140ms 몸 반응 + 300ms 국소 파편 | 렌더가 피해를 다시 발생시키지 않음. 치명타/방어/면역도 각 상태와 같은 틱을 참조 |
| 피격 | 잠깐 눌림·기울기·작은 흰 윤곽 | 화면 전체 점멸/상시 흔들림 금지. 넉백 효과가 없는 적의 경로 진행도를 뒤로 옮기지 않음 |
| 정지 | 시간·발사·이동 동결, 문제 숨김, 재개 버튼 | 정식 엔진의 pause reason 집합 및 저장 규칙으로 연결 |
| 동작 줄이기 | 보행 상하 이동·반동·과한 파편 제거, 비행과 명중 표시는 유지 | 설정 변경이 전투 결과를 바꾸지 않음 |

현재 두 고블린 포즈의 실루엣 차이는 작다. 이 표본은 가벼운 움직임의 인상과 이벤트 연결을 확인하며, 최종 보행 프레임 검수를 통과한 에셋이 아니다. 표본 적은 관찰을 위해 순환하고 체력이 낮아지면 회복한다. 처치·보상·웨이브·문항 점수·저장·판매·강화는 구현하지 않았다. 소리도 아직 없다.

정식 엔진은 고정 틱으로 공격·피해를 판정하고 렌더는 이를 보간한다. 표본도 60Hz 고정 스텝으로 동작하지만 이미 정해둔 전체 게임 규칙을 대체하는 엔진이 아니다. 명중 이벤트에만 적의 반응을 연결해 탄이 도착하기 전에 체력이 줄거나 맞지 않은 적이 움찔하는 오류를 막는다.

## 선택 후 제작 순서

1. 선택 번호의 화풍·UI 외곽·재료·기물 비율을 `style-lock-v1`에 잠근다. 다른 번호의 UI 일부를 조합하려면 결합 위치를 명시한다. 단순히 섞어서 다시 10안으로 늘리지 않는다.
2. Argon에 **전투 기물 1종, 몬스터 1종, 자연 장식 1종, 문화 장식 1종, UI 외곽 1세트**를 요청한다. UI와 캐릭터의 윤곽선 두께/광원/음영 단계를 같은 규격으로 고정한다.
3. 기물은 몸·포신/팔·바닥을 분리하고 포구 좌표를 제공한다. 몬스터는 이동 4포즈·피격 1포즈·처치 표본부터 검수한다. 프레임마다 다른 캐릭터가 나오는 문제를 먼저 차단한다.
4. Codex가 알파·크기·피벗·소켓·명명·누락 검사, 아틀라스 패킹, 런타임 연결을 맡는다. 무결성 검사를 통과한 뒤 전투 타워/분기/적 전체로 늘린다.
5. 하나의 긴 실제 좌표 맵에서 설치→공격→문항→웨이브 생존→회복→실패→재시작을 먼저 연결한다. 그 뒤 저장·복원 및 1개 학년 비공개 검증으로 진행한다.
6. 모바일 실기기에서 경로 전체 보기, 문제 가독성, 격자 선택, 입력 취소, 회전, 장시간 전투를 확인한다. 검수 주체와 전체 공개 범위는 기존 PRD 결정을 유지한다.

## 검증 기록

`node tools/inspect-game-directions.cjs`는 10개 이미지 로드/선택과 1440·1024·768·390·320px 화면의 가로 넘침을 확인한다. 별도 표본은 소켓 발사, 비행 중 무피해, 도착 시점 명중, 기물 셀 중심, 장식 겹침 및 배치 차단, 독립 보행 위상, 정지, 문제 숨김, 모바일 관리, 답안 반응, 동작 줄이기를 검사한다. 브라우저 오류는 검사 결과 파일에 기록한다. 생성 그림 자체의 정확한 격자·경로는 통과 항목이 아니다.

어떤 번호도 아직 승인되지 않았다. PRD의 최종 디자인 동결은 사용자의 선택 뒤 진행한다.
