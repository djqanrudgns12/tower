# 디자인 재작업 v0.3

2026-10-27 · 사용자 피드백 반영 · 이전10안 반려, 새로운 게임 아트10안 제작 완료·선택 대기

기존 v0.2 시안은 사용자가 반려했다. 파스텔 위주 배색, 학습 앱처럼 보이는 화면, 단순 도형 자산, 화풍 차이가 작은 후보 구성이 원인이다. 이전의 ‘설원 관측소’ 표시 상태는 스타일 승인으로 취급하지 않는다.

이번 우선순위는 **게임으로서의 매력과 전투 가독성 → 어휘 문제의 읽기/응답 → 장식**이다. 낮은 채도/파스텔/크림색을 깔끔함의 기본값으로 삼지 않는다. 색이 풍부해도 형태와 명도 위계를 정리하고, 학습 UI는 게임 HUD에 통합한다.

10안은 개별 이미지 생성으로 제작한다. 중세 수작업 일러스트, 픽셀, 산업 SF, 한국 도깨비 액션, 화산, 창공 모험, 먹빛 판화, 해적, 기하 아케이드, 지하 광산을 분리한다. 배경만 바꾸는 것이 아니라 타워/적/공격효과/재료/UI 프레임의 시각 언어를 함께 달리한다.

이번 이미지는 게임 아트 방향을 선택하는 콘셉트다. 실제 동작하는 게임 화면·승인 문항·분리된 최종 스프라이트로 표시하지 않는다. 선택한 방향을 게임에서 재현할 수 있도록 후속 Gemini 제작 계약에 레이어/기준점/실루엣/팔레트/효과 규격을 반영한다. 양산용 원본 제작 담당은 Gemini Argon으로 유지한다.

## 새 후보

| 번호 | 이름 | 비교할 특징 |
|---|---|---|
| 01 | 철벽 원정대 | 질감 있는 중세 전략, 석조/목재/강철의 구분 |
| 02 | 픽셀 방어전 | 픽셀 클러스터와 명확한 스프라이트, 고전 전략 게임 감각 |
| 03 | 리액터 방어선 | 기계식 터렛/드론, 산업 SF의 검정·노랑·청색 대비 |
| 04 | 도깨비 성문 | 한국 성곽/도깨비, 밤과 등불의 대비 |
| 05 | 잿불 요새 | 화산/금속/얼음, 강한 전투 압박감 |
| 06 | 창공 함대 | 단단한 윤곽선과 포화색의 밝은 셀 애니메이션; r2 채택 |
| 07 | 먹빛 공성전 | 흑백/주홍 판화형 실루엣, 강한 공격선 |
| 08 | 해적 포대 | 해안 포대/갑각류 적/해적 장비, 모험 활극 |
| 09 | 프리즘 전선 | 정사영 기하 전장, 진영별 강한 색 구분, 측면 명령 HUD; r2 채택 |
| 10 | 수정 광산 | 어두운 암반/구리 장비/수정, 지하 탐험 |

06과09는 첫 결과가 다른 후보와 비슷해서 각각 셀 애니메이션/정사영 아케이드로 재생성했다. 현재 비교 화면에는 r2만 노출한다. 최초 시도는 추적용으로 파일에 보존한다.

## 파일과 생성 기록

비교 화면: `design-v0.3/index.html`. 최종 선택 후보 PNG10개와 최초 시도2개를 함께 저장했다. `manifest.json`이 현재10개의 정확한 파일을 가리킨다. `prompts.json`과 `revision-prompts.json`에 실제 사용한 프롬프트를 기록했다. 생성은 내장 image_gen 도구로 수행했다.

이미지에 그려진 가격·HUD·문항·경로는 미술 콘셉트이고 PRD의 경제/좌표/문항 승인 규칙을 변경하지 않는다. 실제 게임에서는 글자·숫자를 DOM/런타임으로 구현하고, 타워/적/배경/효과를 별도 자산으로 받는다. 이 이미지를 통째로 전장 배경으로 깔아 실제 동작처럼 보이게 구현하지 않는다.

## 선택 후 제작 기준

1. 선택안에서 좋아하는 선·재료·실루엣·UI를 분리해 style-lock을 만든다. 여백이 많거나 채도가 낮다는 이유만으로 ‘깔끔하다’고 판정하지 않는다.
2. 기본 타워3종/일반 적2종/보스1종을 별도 원본으로 다시 요청한다. 실제32/48/64px에서 종류·진영·공격 역할을 식별해야 한다.
3. 지도는 기존 고정 경로/20슬롯에 맞춰 재구성한다. 원화의 투영이 달라지면 입력 좌표/겹침/가림을 검증한 뒤 채택한다.
4. 전투 효과는 국소적이고 짧게 유지한다. 강한 색을 쓰더라도 문제·적 실루엣·위험 표시를 가리지 않는다.
5. 모바일은 이미지 축소가 아니라 HUD 재배치로 해결한다. 생성 화면의 작은 글자를 그대로 사용하지 않는다.
