# 보드형 디자인 추가 10안 · v0.4

2026-10-27. v0.3의 밀도와 묘사가 과하고 어지럽다는 사용자 피드백을 반영했다. 기존 시안은 이력으로 보존하며 승인된 스타일이 아니다. 이번 후보는 `design-v0.4/index.html`에서 비교한다.

## 이번에 반영한 방향

- 게임 전장 전체가 하나의 보드로 한눈에 보인다. 기본은 사각 격자, 맵에 따라 보드 외곽을 변형할 수 있다.
- 가느다란 길 주변의 좁은 공간만 사용하는 구성을 피한다. 길은 보드 내부를 굽어 지나가며 양쪽에 여러 칸이 모인 배치 공간을 남긴다.
- 기물은 작은 크기에서도 구분되는 형태와 제한된 명암을 사용한다. 배경 풍경, 대형 보스 삽화, 과한 광원·입자·상시 사거리 표시는 제거한다.
- 장르가 드러나는 타워와 적은 유지한다. 문제 영역은 전장을 가리지 않고 하단에 고정하는 구도를 우선 비교한다.
- 모든 그림은 중반 전투의 혼잡도를 검증한 화면이 아니라, 화풍과 보드 구성을 고르기 위한 낮은 밀도의 콘셉트다.

## 구현에 연결할 때의 조건

1. **아직 화풍은 미확정.** 사용자의 선택을 받은 뒤 스타일을 고정한다. 8×8은 시작 후보이며 이미지의 실제 칸 수나 길 좌표는 구현 계약이 아니다. 기존 `contracts/maps.candidate.v0.2.json` 역시 승인 맵이 아니므로 새 보드 방향에 맞춰 별도 개정·검산해야 한다.
2. **보드 형태와 격자 형태를 분리한다.** 사각 좌표계에 `activeCells` 마스크를 두면 십자형·모서리를 자른 보드를 같은 코드로 만들 수 있다. 17번의 실제 육각 셀은 이웃/거리/입력 판정 규칙이 달라지므로 선택되지 않는 한 MVP에 추가하지 않는다.
3. **칸의 의미를 고정한다.** `inactive`, `path`, `buildable`, `blocked`를 분리하고 경로는 순서가 있는 좌표열로 관리한다. 이미지 색상에서 판정을 추출하지 않는다. 경로 칸에는 타워를 놓지 않으며 MVP에서 타워로 길을 막아 경로를 재탐색하는 규칙을 암묵적으로 추가하지 않는다.
4. **공간이 넓다는 것과 유효한 위치가 많다는 것은 다르다.** 배치 가능 칸의 75% 이상이 적어도 한 기본 공격 타워의 사거리로 경로에 닿는 것을 초기 검증 목표로 삼는다. 나머지 칸은 장거리/지원 타워 용도 등 이유가 있어야 한다. 경로 인접, 연속/중복 사거리, 입구·출구 집중도는 실제 좌표와 타워 사거리로 검증한다. 수치는 플레이 테스트로 조정한다.
5. **다양성은 배치 선택으로 확인한다.** 같은 보드에 초반 집중형·중앙 범위형·출구 방어형 등 최소 세 배치안을 만들어 비교한다. 모든 타워를 한 구역에 모으는 전략만 유효하면 길·사거리·경제를 재검토한다. 보드의 빈칸을 모두 채우는 것을 목표로 하지 않는다.
6. **모바일에서는 전체 보드를 먼저 맞춘다.** 390px 화면에 좌우 16px 여백과 8열이면 칸은 약 44.75px다. 320px에서는 약 36px이므로 작은 화면을 같은 입력 규칙으로 통과했다고 간주하지 않는다. 타워 선택→칸 선택→확인, 선택 칸 확대 피드백을 검토한다. 전체 보드 보기 상태에서 문제와 선택지가 접근 가능해야 한다. 가로/데스크톱은 정사각 전장 옆에 문제를 배치하는 방식도 비교한다.
7. **기물이 늘어나도 읽혀야 한다.** 승인 후 타워 12/20개, 적 10/30/60개 장면을 같은 모바일 크기로 비교한다. 최대 동시 객체 수는 엔진 시험에서 별도 결정한다. 상시 체력바/숫자를 남발하지 않고, 선택 사거리 한 개·짧은 피격 반응·낮은 입자 수로 혼잡도를 관리한다. 필수 위험/공격 예고를 효과 축소로 제거하지 않는다.
8. **에셋은 개별 납품한다.** 선택한 스타일로 타워 4종·적 3종·경로/땅 타일·투사체/타격 각 1종 표본을 먼저 Gemini Argon에 요청한다. 투명 배경, 같은 광원/외곽선, 셀 기준 크기, 접지점·회전축을 고정한다. 실제 화면에 얹어 보고 통과한 뒤 10종 타워와 분기·전체 적으로 확장한다. 이번 평면 스크린샷을 게임 배경 전체로 붙여 기능을 흉내 내지 않는다.

## 생성과 검수의 범위

내장 `image_gen`으로 개별 10장을 생성했다. 공통 프롬프트와 개별 스타일 지시는 `design-v0.4/prompts.json`, 원본 출처와 사본 목록은 `manifest.json`에 보관했다. 생성 이미지의 격자 수, 투시, 선택지 강조, 문항 표기는 실제 게임 요구사항보다 부정확할 수 있다. UI 글자/상태/정답 피드백은 구현에서 데이터로 렌더링한다. 표본 4개 타워는 원문의 10종 범위를 축소한 결정이 아니다. 실제 외부 공동검수나 게임 성능 시험을 수행한 산출물이 아니다.
