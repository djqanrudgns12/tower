- **PRD 근거:** §5 “웨이브 완료·패배 때 버닝과 전투 연속 카운트를 초기화한다.”
- **재현:** `tests/review/defeat-reset.test.ts` / `패배하면 전투 연속 정답 카운트도 0으로 초기화한다`.
- **절차:** 실제 전투 정답 1회 뒤 HP 1에서 마지막 일반 적을 누출시킨다.
- **실제/기대:** `GAME_OVER`이고 버닝은 꺼지지만 battleStreak는 **1 / 0**이다.
- **원인 위치:** `run.ts:229`의 `endRun()`은 버닝만 초기화한다. 완료 경로와 다르다.
- **학생 영향:** 종료 상태에 이미 끝난 연속 정답이 남는다. 현재 결과 UI에서 카운터가 직접 노출되는 것은 확인되지 않았으므로 즉시 보이는 점수 손실을 주장하지 않는다. 추후 종료 표시·재생 소비자가 잘못된 연속 상태를 읽을 여지가 있다.

## PRD 질문 — 결함 수와 분리

1. **Q01: 긴 프레임 폐기 규칙의 통합 (§13.3 vs §14).** §13.3은 “처리할 틱을 임의로 버려 실제 게임 속도를 기기마다 다르게 만들지 않는다”고 한다. §14는 한 프레임 간격이 250ms를 넘으면 시간을 버리고, 5초 안에 3회일 때만 정지하도록 명시한다. 이번 검토에서는 더 구체적인 §14를 예외로 읽어 그 동작을 대조했고 일치했다. §13.3에도 §14의 예외를 명시하는 것이 맞는가? 한 번의 251ms 끊김을 결함으로 보고하지 않았다.
2. **Q02: seed 0의 스트림 유도 순서 (§20.1).** “입력 0은 0x6d2b79f5로 매핑한다”와 “원래 seed와 각각 … XOR한 뒤 0 재매핑”을 함께 적용할 때, 원래 seed 0을 먼저 remap한 후 XOR하는가, 원래 0을 그대로 XOR하고 결과가 0일 때만 remap하는가? 두 방식은 0 시드의 모든 스트림이 다르다. 현재 구현은 전자다. 0 시드의 스트림별 golden vector를 문서에 확정하기 전에는 어느 쪽을 결함 증거로 고정하지 않았다.
