## 2. 정의와 판정 규칙 (PRD에 없던 해석)

- **도달 웨이브** = 마지막으로 지킨 웨이브(`completedWave`). 사망 웨이브 = 도달 + 1. "4개 맵 평균"은 **맵마다 중앙값을 구해 평균한 값**이다(셀당 32판: 4맵 × seed 8). 사망 폭 p10~p90은 맵을 합친 32판의 분위수다.
- **균형형** = 기존 `balanced10`(정확히 같은 판이 나온다: 시험 `gate.test.ts`). **초보형** = 기존 `novice`. **궁수만** = `mono-archer`(징집 없음, 장착함이 궁수 하나).
- **보스 웨이브 사망 비율**: PRD의 37%는 정원 맵 옛 5전략 × 정답률 60·80·95%를 합친 값이었다(`.orchestrate/balance`의 s16 자료에서 같은 값 0.367을 재현했다). 관문은 새 전략 5종(초보·균형·상성·최적화·궁수 집중) × 정답률 60·80·95%의 4개 맵을 합친다. 균형형 80%만 보면 3%다.
- **보스 처치율** = 그 보스 웨이브에 들어선 판 중 보스를 잡은 비율(보스가 나오기 전에 진 판은 실패로 센다). 보스가 나온 판만 센 값은 표 5의 JSON에 `event`로 있다.
- **직전 2웨이브**: 패배 웨이브 바로 앞 두 웨이브의 성문 피해(최대 체력 대비). W2 이전에 진 판은 뺀다.
- **강화 효율**: 타워 하나를 정원 기준 칸(8,2)에 놓고 일반·밀집·껍질 줄 평균 피해로 잰다. Lv7에서 가장 센 2차형을 대표 갈래로 쓰고, 구간(Lv1→6, Lv7→9)의 강화비 합 1골드당 늘어난 피해를 새 Lv1 설치 1골드당 피해로 나눈다(진화 도약 포함). 공격 타워 19종의 중앙값이 판정값이다. 레벨마다 값(표 8)은 진화 직후가 크게 튄다(Lv3→4 0.5~2.7, Lv6→7 1.1~8.3).
- **최적화형 선택률** = 전체 설치 명령 중 그 타워의 비율(표 11). PRD는 "선택률"의 분모를 정하지 않았다. 시작 4종(궁수·포탑·서리·마법)이 항상 쓸 수 있어 불리하지 않으므로, 징집 선택률(후보로 나온 횟수 대비 고른 횟수)과 보유율을 표에 같이 둔다. 분모를 바꾸려면 `tools/sim/gate.ts`의 `pickShare`만 고치면 된다.
- **유틸 시너지**: 표준 4종 = 궁수·석궁·포탑·마법(장착함 고정, 징집 없음)에 유틸 타워를 정확히 **1기**만 더한다(80%). 웨이브 차이는 맵 평균의 차, 성문 피해는 W1~15(핵심 4종 판이 지키는 구간)의 판별 평균이다.
- **상성표**: Lv1 기본형을 맵의 기준 칸에 하나 놓고 역할 줄을 한 번 통과시켜 100골드당 피해를 같은 칸 궁수와 견준다. 기준 칸은 정원 (8,2), 다른 맵은 정원 길목과 가장 닮은 칸이다. 분열 줄은 죽지 않는 줄이라 실제 분열이 안 일어나서 "몸통 1 + 새끼 2"를 섞어 흉내 낸다. 종족 특성 4열은 구현 전이라 N/A로 비워 뒀다.
- 엔진 수치 한계(`NUMERIC_LIMIT`)로 끊긴 판은 집계에서 빼고 개수를 센다(§6).

**측정 정의 보정(B2, 2026-11-04 총괄 결정).** 아래 수치 표는 보정 전 정의로 잰 기준선이라 그대로 둔다. 보정 뒤 판정은 `docs/balance/r4-b2.md`.
- **유틸 6종**(서리·바람·종각·깃발·약병·수호기사)은 '단일 타워 판 ≥ W6'과 '강점·약점(≥1.35·≤0.8)' 줄에서 빼고 유틸 시너지 줄로만 판정한다. **덫**은 상성표(한 번 지나가는 줄)가 미리 깔린 덫·웨이브 이월을 못 보므로 상성표 줄(역할별 1.4배·강점·약점)에서 빼고 실제 판 지표(단일 판·선택률)로만 본다.
- **최적화형 선택률**은 설치 점유가 아니라 **징집 후보로 나왔을 때 고른 비율**로 잰다(시작 4종은 후보에 안 나와 뺀다, 후보 10회 미만은 표본 부족). 기준은 모두 **≥ 10%, ≤ 60%**. 설치 점유는 보고서 표에만 남긴다.
- **최적화형** 롤아웃은 빠른 모드에서 **3웨이브**(틱 상한 21만)다. 빠른 관문이 5분 안(이번 77초)이라 최적화형 95% 22~26·전략 효과(궁수만 → 최적화형 ≥ 6) 목표는 그대로 둔다. 5분을 넘게 되면 2웨이브로 되돌리고 목표를 '최적화형 95% ≥ 균형형 95%', '전략 효과 = max(상성형, 최적화형, 균형형) − 궁수만 ≥ 6'으로 바꾼다.

**측정 정의(B3, 2026-11-04, 총괄 확인 전).** 자세히는 `docs/balance/r4-b3.md` §3.
- **원정 보물 선택률**은 징집과 같이 최적화형 판에서 **후보로 나왔을 때 고른 비율**(후보 10회 미만 표본 부족), 상승폭은 균형형 80%가 W10에 그 보물 하나만 가진 판(`relic-<id>`) − 보물을 받지 않은 판(`norelic`)이다.
- **종족 특성 4열**은 특성 표지를 가진 적 줄(하늘 떼는 하늘유랑단 비행 줄)을 특성이 1웨이브부터 붙는 밸런스 사본으로 Lv1 기본형에 잰다. 덫은 역할 줄과 같이 뺀다.

## 4. 실행 방법·소요 시간

```
npm run simulate:gate                    # 빠른 모드: seed 8, 최적화형 K=6(80·95%), 4개 맵 → 이 파일의 표를 만든다
npm run simulate:gate -- --full          # 전체 모드: seed 24, K=10, 최적화형 네 정답률, 단일 타워 60·80·95%
npm run simulate:gate -- --out .orchestrate/balance/gate.json --report .orchestrate/balance/gate.md   # JSON(생존 곡선 전체 포함)·읽는 글 저장
npm run simulate:gate -- --set draft.afterWaves=[3,6,9,12] --set waves.hpGrowthPercent=114          # 조정 후보를 계약 파일 수정 없이 잰다
npm run simulate:gate -- --bots balanced,optimizer --seeds 4   # 일부 봇만(mono·core4는 접두어). 빠진 봇의 줄은 N/A
npm run simulate:towers                  # 20종 × 역할 9종 상성표 + 형태 비교(-- --map all, -- --no-forms)
```

- 종료 코드는 항상 0이고(보고서), 끝에 `PASS n · FAIL n · N/A n`을 센다. `--raw`를 주면 판별 요약도 JSON에 담는다.
- **소요(이 Mac, 10코어 워커):** 빠른 모드 **102초**(판 1,536개, 판 합계 CPU 1,011초). 최적화형이 약 60%를 차지한다. 전체 모드는 seed 24 × K=10이라 약 8~10분으로 추정한다(1 seed × 2 맵으로 13.5초를 재서 환산한 값이며 전체는 아직 돌리지 않았다).
- 최적화형은 웨이브마다 미리 돌려 볼 틱 수 상한(빠른 모드 14만 틱)이 있어서, 곡선을 올린 뒤 W26까지 가는 판이 생겨도 한 판 시간은 웨이브 수에 비례해서만 늘어난다. 상한을 다 쓰면 그 웨이브의 남은 결정은 균형형 선택을 따른다(결정적이다).
- 실제로 W30까지 가는 최적화형 판(성장률 110% 시험)은 한 판 약 15초였다.

## 5. 가상 플레이어의 알려진 한계

1. **최적화형은 균형형 위에 얹은 2웨이브 롤아웃이다.** 결정마다 후보 K개(균형형의 선택, 종류별 최적 칸의 설치, 진화 두 갈래, 강화, 칸이 가득 차면 판매 후 재배치, 징집 3장)를 복제한 판에서 2웨이브(징집은 3웨이브) 돌려 `성문 피해 → 적이 경로 깊이 들어온 정도 → 남은 골드` 순으로 고른다. 전체 판을 계획하지는 못한다. 균형형의 선택을 후보 맨 앞에 두므로 균형형보다 크게 나빠지지는 않는다.
2. **지금 밸런스에서는 최적화형이 균형형과 같다**(95%에서 17.8 대 17.8, 80%에서 17.0 대 16.5). 성장률 110%로 낮춰 본 일회성 검증(정답률 95%, 맵 2개 × seed 4)에서도 같았다(최적화형 30, 균형형 30, 궁수만 29, 초보형 25). 곡선이 벽이고 타워 효율 차가 작아서 선택이 결과를 못 바꾸는 상태다. 그래서 "최적화형 22~26"과 "전략 효과 ≥ 6"은 B1·B2에서 수치를 고친 뒤에야 의미 있게 재볼 수 있다. 이 도구가 목표를 이길 수 있는 상한인지는 아직 증명되지 않았다.
3. **칸 선택이 단순하다.** 설치 칸은 종류마다 "그 타워 하나를 놓았을 때 엔진 피해가 가장 큰 빈칸" 하나뿐이다. 한 종류를 같은 칸 근처에 몰거나 깃발·서리를 일부러 이웃에 붙이는 배치는 후보에 없다. 깃발의 가치는 이웃한 공격 타워 가치 × 오라 비율로만 본다.
4. **판매·재배치는 20칸이 다 찰 때만 후보가 된다.** 지금 밸런스에서는 판이 끝나기 전에 칸이 안 차서(단일 궁수만 예외) 거의 쓰이지 않는다.
5. **결정 간격**: 거래는 웨이브 시작(BUILD)과 전투 중 20초마다(초보형은 30초)다. 학생이 전투 중 훨씬 자주 바꿀 수 있다.
6. **사람의 읽기·정답**: 문항을 읽는 시간은 12초 ±25%, 정답은 문항과 무관한 고정 확률이다. 어려운 문항에서 더 틀리는 효과·'모르겠어요'·학생의 지침이나 실수는 없다. 오답은 최소 4초 피드백을 보고 1초 뒤 넘긴다.
7. **상성형은 미리보기만 본다**: 다음 웨이브의 역할 수(체력 가중)와 정원 기준 칸의 단일 타워 효율표로 가치를 곱한다. 시너지·위치는 안 본다.
8. **단일 타워 봇은 징집이 없고 한 종류만 짓는다.** 깃발은 공격하지 않아 W1에 진다(판정에서 제외, 표 10에는 보인다). 수호기사는 동시에 1기라 그 1기만 키운다.
9. **상성표는 Lv1 기본형·단일 타워**다. 형태·레벨·시너지·사거리 겹침은 안 본다. 특성(종족) 열은 없다.
10. **표본**: 셀당 32판이라 중앙값의 해상도가 0.5웨이브다. 목표 근처의 줄(예: 초보형 60% 12.4, 웨이브 길이 1.45분)과 형태 선택률(갈래당 10회 미만은 판정에서 빼서 fast에서는 9갈래만 판정된다)은 `--full`로 다시 확인한다.
11. **보스 처치율·사망 직전 성문 피해는 균형형 80% 한 셀**의 값이다. 다른 봇·정답률 값은 표 4·5에 있다.
12. 맵마다 주력 종족이 달라 같은 웨이브 번호라도 역할 등장 순서가 다르다(`campaigns.roleOrder`). 그래서 맵 평균을 쓰며, 맵 사이 차(최대 0.5웨이브)는 지금은 작다.

## 6. 측정 중 발견한 엔진 문제 (`src/` 밖이라 고치지 않았다)

**`combat.ts`의 `inLine`(선분 판정)이 큰 맵에서 `NUMERIC_LIMIT`을 던진다.** `lineTargets`는 살아 있는 모든 적(사거리 밖 포함)에 `inLine`을 부르고, 거기서 `safe(4 * cross * cross)`를 계산한다. `cross`는 "타워→첫 표적 벡터(≈ 사거리 3,800)"와 "타워→그 적 벡터"의 외적이라, 적이 12,000 milli(12칸)쯤 떨어져 있으면 4×cross²가 안전 정수(9.0×10¹⁵)를 넘는다. 실패한 값이 모두 9.1~10.3×10¹⁵이다(원인은 코드와 숫자로 추정했고 `src`를 고쳐 확인하지는 않았다).
- 재현: `mono-ballista` × `courtyard` × 정답률 80% × seed 1~8 **전부**, `novice` × `courtyard` × seed 3. 기존 `npm run simulate:balance -- --map all`도 같은 오류로 끊긴다. 거대노포(`ballista`, 선분 `lineWidth` 350, 사거리 3,800)가 걸린다. 같은 방식으로 긴 사거리 선분 타워는 모두 의심해야 한다.
- 실제 게임에서는 5학년 맵(courtyard)에 거대노포를 지으면 수치 복구 정지가 걸릴 수 있다. 사거리 밖 적을 먼저 거르거나(거리 제곱 비교) 곱 대신 나눗셈 비교로 바꿔야 한다. 이 시뮬레이터는 그런 판을 집계에서 빼고 개수를 센다(표 15, 이번 측정 9판).

## 7. 변경한 도구 (B0)

- `tools/sim/balanceSim.ts`: 한 판을 틱 단위 상태 기계(`createPlayer`·`stepPlayer`·`clonePlayer`)로 쪼갰다. 기존 `simulateRun`은 같은 결과를 낸다(고치기 전 43판과 일회성으로 비교해 모두 같았고, 시험 `gate.test.ts`는 균형형 한 판을 옛 `balanced10`과 비교한다). 웨이브별 성문 피해·수입·행동·타워별 피해 기록(`telemetry`)을 더했다.
- `tools/sim/bots.ts`(신): 상성형·최적화형·단일 타워·조합 봇과 판 요약. `tools/sim/gate*.ts`, `tools/sim-gate.mjs`, `tools/sim/gate-worker.mjs`: 관문.
- `tools/sim/towerEfficiency.ts`: 옛 `COMPARISONS`(손으로 고른 10종, 필수 5)를 없애고 20종 × 역할 9종 상성표(`runMatrix`)로 바꿨다. 깃발 `banner-group` 검사는 유틸 시너지(표 13)로 옮겼다. 형태 비교(`runFormComparisons`)는 20종 모두를 본다.
