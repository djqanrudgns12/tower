# 구현 상세 계획 v0.2

2026-10-27 · 계획 상태: 설계 인계, 41번 화풍 결정 완료 · 제품 구현 미착수

## 1. 목표와 완료 단위

최종 공개 MVP는 원문 전체 범위다. 한 학년 비공개 프로토타입, 한 학년 완성 샘플, 전체 비공개 베타, 공개 MVP를 구분한다. 매 단계 결과는 **실행물 + 테스트 결과 + 알려진 제한 + 다음 입력물**로 전달한다. 일정은 인수 게이트로 관리하며 아래 작업량은 구현 후 성과가 아니다.

사용자는 방향 결정·베타테스트·공개 판단을 맡고, Codex가 코드·설정·파일 정리·수치/스키마 검사·불량품 목록·통합을 책임진다. 문항은 Argon·Codex·Claude 공동검수로 확정했다. Gemini/Claude 도구를 실제로 사용할 수 있는지 확인되지 않았으므로 이번 문서는 전달용 작업 명세를 제공하며, 이미 외부 AI에 작업을 보냈다고 간주하지 않는다. 공동검수는 `joint_review_protocol_v0_2.md`를 따른다.

## 2. 기술 선택과 설치 정책

| 영역 | 제안 선택 | 이유·범위 |
|---|---|---|
| 언어 | TypeScript strict | 게임 규칙·콘텐츠·UI 계약 공유 |
| 화면 | React DOM + CSS Modules + CSS 변수 | 한국어 줄바꿈/접근성/반응형; 게임마다 맞춘 UI |
| 전장 | Phaser 어댑터 | 스프라이트·입력·오디오·렌더링만 담당 |
| 빌드 | Vite + npm lockfile | 단일 웹앱. 현재 폴더를 덮는 생성 명령 금지 |
| 검증 | Zod 런타임 스키마 + JSON Schema 배포 | Gemini는 JSON만 제출, 스키마 변환 단일 원천 |
| 저장 | IndexedDB + idb 얇은 래퍼 후보 | 원자적 여러 저장소 갱신, 스키마 마이그레이션 |
| 단위/속성 검사 | Vitest + fast-check 후보 | 틱/경제/효과/재생 불변식 검사 |
| 브라우저 | Playwright + axe-core 후보 | Chromium/Firefox/WebKit, 실제 터치는 별도 |
| 운영 | 정적 호스팅 + 결과 API + 전용 DB | 게임 루프는 네트워크 없이 지속 |
| 공개 랭킹 DB | 독립 Supabase 후보 | 쌤유니버스 DB·계정과 결합하지 않음 |

실시간 엔진 상태를 React 전역 스토어에 복사하지 않는다. UI는 `useSyncExternalStore` 기반 요약 구독 또는 같은 목적의 작은 어댑터를 사용한다. 처음부터 Redux·Zustand·XState·React Query·애니메이션 라이브러리를 전부 설치하지 않는다. 상태 기계는 discriminated union과 명시적 전이표로 시작한다. CSS 전환과 Phaser tween으로 충분한 효과에 별도 라이브러리를 넣지 않는다. DOM 아이콘은 한 세트만 쓰며 게임 타워 이미지는 Gemini 자산을 사용한다.

### 버전 확인 결과와 착수 게이트

2026-10-27 확인한 [Phaser 공식 React TS 템플릿](https://github.com/phaserjs/template-react-ts)의 [package.json](https://raw.githubusercontent.com/phaserjs/template-react-ts/main/package.json)은 Phaser **4.0.0**, React **^19.0.0**, Vite **^6.3.1**, TypeScript **~5.7.2**를 기록한다. 템플릿 설명의 Phaser 3 표기와 다르다. 이것은 해당 템플릿의 관측값이며 전체 최신 권장 조합을 뜻하지 않는다.

[Vite 공식 안내](https://vite.dev/guide/)의 Node 최소 버전은 20.19+/22.12+이고, [Node 릴리스 안내](https://nodejs.org/en/about/previous-releases)는 24를 LTS로 표시한다. 작업 PC에서는 Node 24.14.1, npm 11.11.0을 확인했다. 구현 착수 시 지원 중인 Node 24 LTS의 보안 패치를 확인하고 CI·로컬에 같은 정확한 버전을 기록한다. [Zod](https://zod.dev/)는 TS 5.5 이상을 시험 대상으로 안내한다. 템플릿의 의존성 목록을 최신 도구와 무조건 섞지 않는다.

착수 순서:

1. npm registry와 공식 릴리스에서 stable 버전·peer dependency·엔진 요구를 확인한다.
2. Phaser 4 후보로 스프라이트/아틀라스/포인터 좌표/리사이즈/음소거/컨텍스트 복구/React 재마운트 샘플을 만든다.
3. 모바일 WebGL이 실패하면 원인을 기록한다. Phaser 3 유지보수 버전 또는 다른 렌더러 선택은 어댑터 교체 결정으로 남기고 규칙 코드에 영향이 없게 한다. 지원하지 않는 Canvas fallback을 있다고 가정하지 않는다.
4. 후보 조합의 typecheck/build/test/browser smoke가 통과한 **정확한 버전**으로 `package.json`과 `package-lock.json`, `.node-version`을 기록한다. 설치 명령에 `latest`를 남겨 반복 실행하지 않는다.
5. CI 설치는 `npm ci`. 엔진 업데이트는 기능 구현과 별도 변경으로 검증한다.

### 최초 설정 체크리스트

`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`를 켠다. 브라우저 앱과 Node 검증 도구 tsconfig를 분리한다. ESLint 경계 규칙으로 domain→React/Phaser/DOM import를 막는다. formatter 설정, 줄 끝, UTF-8, 파일명 소문자 규칙을 고정한다. React StrictMode를 유지하고 중복 장면/리스너 결함을 고친다([React 공식 설명](https://react.dev/reference/react/StrictMode)).

최소 scripts: `dev`, `build`, `preview`, `typecheck`, `lint`, `test`, `test:e2e`, `validate:content`, `validate:assets`, `simulate:balance`. 현재 문서 검산용 `node tools/validate-plan.mjs`는 게임 테스트가 아니다.

`VITE_*`에는 공개 주소·릴리스 ID·기능 표지만 둔다. 사전 키·Gemini 키·DB secret은 생성/서버 환경에만 둔다. `.env.example`에는 값 없는 이름과 용도만 기록한다. 브라우저 빌드 산출물의 비밀 키 스캔을 출시 검사에 포함한다.

## 3. 구현 디렉터리와 인터페이스

```text
src/
  domain/       # 정수 계산, PRNG, 공격/웨이브/문항/거래 reducer
  application/  # RunController, 명령 순번, UI 구독, 저장·오류 조정
  contracts/    # Zod 스키마, 직렬화, 타입
  content/      # 버전 있는 난이도·타워·적·맵, 은행 로더
  game/         # PhaserAdapter, 장면, 스프라이트/오디오/좌표 변환
  ui/           # 홈/문항/상점/설정/결과/안내/기록
  persistence/  # IndexedDB repository, checkpoint, migration
  services/     # ranking client, 콘텐츠 manifest/철회 fetch
server/         # 순위 API·검증·소유권, 공개 단계에 추가
tools/          # content lint, asset pack, simulator
tests/          # unit, property, integration, e2e, fixtures
content-source/ # 공동검수 근거·승인, 배포 번들에서 제외
asset-source/   # Gemini 원본/제작 조건, 배포 번들에서 제외
public/content/ # 승인·해시 파일만 빌드 도구가 생성
```

한 리포지터리·단일 앱으로 시작한다. 멀티패키지 모노레포와 플러그인 플랫폼은 만들지 않는다. `reduceCommand(state, command) → {state, events}`, `advanceOneTick(state) → {state, events}`는 렌더러와 독립이다. `RunController`가 검증된 명령에 순번/적용 틱을 부여하고 유일한 작성자가 된다. 렌더러의 animation-complete는 도메인 명령을 만들 수 없다.

검사 구성: domain 단위 검사 → 속성 검사 → 실제 DB 없이 IndexedDB 통합 → 브라우저 흐름 → 사람/기기/문항 검수. 스냅샷만 늘려 논리 검증을 대신하지 않는다. 수치 변경 때 관련 seed의 결과와 기대값을 재검토하고 무조건 새 스냅샷으로 덮지 않는다.

속성 검사: gold≥0, 빈칸 외 설치 불가, HP≤0 상태는 전회복 불가, 지급 장부 합=현재 PT/골드, enemy마다 kill XOR leak, encounter마다 제출≤1, 동일 입력의 저장 중단/재생 해시 일치. 실패 seed와 최소 재현 명령을 보관한다.

## 6. 밸런스 실험 계획

첫 실험은 3학년/Normal/고정10seed, 정답률 60·80·95%, 읽기6·12·20초, 전략 3개(근접 배치/균형/감속 집중)로 270판이다. 봇은 미래 정보를 사용하지 않고 제한된 전략임을 표시한다. 안정화 후 4맵×4난도×3정답률×3읽기×3전략×10seed=4,320판으로 확장한다. 자동 정답/오답 피드백 1초/4초는 읽기와 별도로 더하고 오답 다음 버튼 반응 시간도 기록한다.

결과 CSV에는 seed/config hash, 종료/완료 웨이브, 단계별 시간, 정답/처치 점수, 웨이브별 지출, 첫 진화, 누출, 보스 처치, 최대 체류 시간을 둔다. 통과 가설: 느리지만 정확한 Easy 플레이어의 초반 생존 경로, Normal 목표 시간대, 한 타워만 쓰는 전략의 압도 여부. 숫자 문턱은 첫 관찰 후 근거와 함께 정하며 문서 작성자가 성공 결과를 미리 채우지 않는다.

학생 비공개 관찰은 소수 사용성 파일럿으로 시작한다. 초반 5분의 타워 구매/정답 보상 이해, 멈춤 찾기, 해설 읽기, 저장 복귀를 관찰한다. 표본 수가 작으면 교육효과를 일반화하지 않는다. 학습 향상 검증은 동등 난도의 다른 문맥 재검사 등 별도 연구 설계가 필요하다.

| 환경 | 자동 확인 | 실제 기기 확인 |

| iPhone Safari | WebKit 레이아웃·키보드 흐름 | 주소창, safe-area, 홈 이동/잠금, 오디오 재개 |
| iPad Safari | 768/1024 폭·가로세로 | 분할 화면·다중 터치·회전·저메모리 복귀 |

| PC Chrome/Edge/Firefox | Chromium/Firefox·마우스/키보드 | 고DPI·125/150/200% 확대·탭 전환 |

자동 브라우저 에뮬레이션을 실제 iOS 기기 통과로 표시하지 않는다. 지원 최소 OS는 접근 가능한 실제 기기와 선정 엔진의 요구를 확인한 뒤 결정하고, 출시 문서에 시험 모델/OS/브라우저/날짜를 적는다.

원문 성능 목표 외에 제안: 최악 전장에서 모바일 frame p95≤33.3ms, 입력→UI 피드백 p95≤100ms, 로컬 명령 반영은 다음 논리 틱. 로딩은 네트워크 조건과 함께 기록한다. 고해상도 기기 렌더 DPR은 초기 최대2, 필요 시1.5로 낮추되 DOM 글자는 유지한다. 실패 기기의 지원 제외는 사용자 결정 없이 하지 않는다.

## 8. 저장·운영 세부 구현

IndexedDB transaction 하나에 run generation, snapshot/journal sequence, score event를 연결한다. 도메인 상태 변경과 저장은 별개 단계이므로 저장 완료 전 화면에 ‘저장 완료’를 표시하지 않는다. 중요한 명령 후 지연 저장 실패 시 최신 메모리 상태를 정지 보존한다. 마지막 두 개의 정상 checkpoint와 그 이후 저널을 유지한다. 체크포인트 commit 이후에만 이전 저널을 정리한다.

`lastCommittedTick`까지 명령 없는 전투 시간도 재생할 수 있게 기록한다. 로드 시 snapshotTick부터 명령 tick까지 재생 후 commit tick까지 진행한다. 저장 범위를 넘어선 메모리 변경은 복원되었다고 주장하지 않는다. 브라우저 저장도 OS/저장공간 상황에 따른 손실 가능성이 있으므로 성공 메시지는 완료된 transaction 경계를 뜻한다([IndexedDB durability](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/durability)).

다중 탭은 지원 시 [Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) + BroadcastChannel 안내. 미지원이면 IDB lease와 generation을 한 transaction에서 검사하고 모든 쓰기에 generation을 요구한다. lease 만료는 악의적 시계 변경 방지책이 아니며 기존 소유자가 저장할 때 실패하도록 fencing한다. 사용자 동작 없는 잠금 강탈 금지.

고정 틱은 30Hz. 화면 프레임에서 누적된 논리 시간을 최대5틱씩 처리하고 잔여량을 유지한다. 가시 화면의 지연 누적이 250ms를 넘으면 `PERFORMANCE` 정지 이유를 추가하고 재개 때 새 기준 시각으로 시작한다. 이때 버린 벽시계 구간은 정지 시간으로 기록하고 논리 게임 시간을 진행한 것처럼 주장하지 않는다. 숨김은 별도 `HIDDEN` 이유이며 수동 재개한다([Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)). 복구/소유권 이유가 남아 있으면 일반 재개 버튼으로 우회하지 못한다.

## 9. 공개 랭킹과 독립 서비스

웹게임 주소, 콘텐츠 배포, 게스트 신원, DB를 독립 운영한다. 쌤유니버스에서는 추후 일반 링크/메뉴 항목만 추가하면 된다. 별도 도메인이나 하위 도메인은 호스팅·DNS 설정으로 결정하고 현재는 필수가 아니다. URL로 playerId나 권한을 신뢰하지 않는다. iframe은 첫 연결 방식으로 채택하지 않는다.

제안 신원 방식: 동일 origin의 서버 발급 HttpOnly/Secure/SameSite 세션. 서버가 플레이어 소유권을 검사한다. 학생 기기 교대 시 새 게스트 프로필을 시작하며 기존 run을 숨기거나 저장 후 교대한다. 계정 없는 기록은 다른 기기에서 자동 복구할 수 없다는 문구를 둔다. 닉네임은 인증 키가 아니다.

DB 후보에 Supabase를 사용하면 점수·답안·실행 테이블은 서버 전용 접근을 기본으로 하고 공개 순위는 허용 필드만 API가 반환한다. 노출 schema에는 GRANT와 RLS를 모두 검사한다. 실제 프로젝트의 자동 노출 설정을 추측하지 않는다([공식 API 보안](https://supabase.com/docs/guides/api/securing-your-api)). DB 변경·계정 생성은 현재 계획 작업에 포함하지 않는다.

API 구체화: create/finish/checkpoint에 idempotency key, run 소유권, schemaVersion, 요청 크기 제한, 순번 연속성, 충돌 409, 검증 실패 422, 빈도 제한 429, 재시도 가능한 5xx를 정의한다. 서버 응답만 성공으로 표시. checkpoint별 답안과 처치 합계를 재구성하고 단계 위반·철회 문항·음수점수·큰 정수를 처리한다. 완전 전투 재생 검증은 MVP 이후이며 참고 랭킹임을 표시한다.

정확한 무한 정수 순위: DB numeric 최대 범위를 넘는 값까지 저장해야 한다면 부호/십진 문자열/자릿수/숫자 문자열 정렬 키를 사용한다. 양수는 자릿수↓·문자열↓, 0, 음수는 절댓값 자릿수↑·문자열↑ 순이다. 컬레이션·동점 키까지 테스트한다. DB `bigint`가 JS BigInt와 같은 임의 정밀도라고 가정하지 않는다. 정상 제품 범위의 합리적 payload 상한은 API 자원 보호로 문서화하고 초과 기록은 로컬 유지·공개 불가 사유를 표시한다.

공개 게이트: 신고/닉네임 숨김/문항 철회/기록 삭제 절차와 담당자, 운영 목적·필요 데이터·보존 기간 고지, 출시 지역의 개인정보 요구 확인. 법률 준수 완료를 이번 설계만으로 선언하지 않는다. 학습 상세 로그는 공개 API에 넣지 않는다. 브라우저 세션 replay 녹화는 기본 제외한다.

## 10. 릴리스·복구와 완료 증거

정적 파일은 content hash, manifest는 버전, 진행 중 run은 rules/bank/assets 버전에 고정한다. 구버전 보존 기간 제안은 배포 후90일이며 UI에 이어하기 호환성 정책을 표시한다. 보존 종료 시 개인 결과로 안전 종료할 수 있어야 한다. 철회 오버레이는 구은행에도 적용한다. 오프라인 중 새 철회 목록을 수신할 수 없다는 제한을 기록한다.

배포 전 preview에서 migrate/rollback을 시험하고 이전 manifest로 되돌릴 수 있게 한다. 완료 보고에는 실제 commit 또는 파일 버전, 설치 버전, 검증 명령/결과, 기기 표, 승인 콘텐츠 집계, 에셋 결함 0 목록, 잔여 제한, 배포 URL을 넣는다. 빌드만 통과한 상태는 ‘MVP 완료’가 아니다.

무료 요금제 수치는 출시 시 재확인한다. [Vercel Hobby](https://vercel.com/docs/plans/hobby)의 사용 조건과 [Supabase 가격](https://supabase.com/pricing)의 전송/DB/휴면 제한을 실제 사용량과 비교한다. 무료 이용을 보장하지 않는다. Supabase changelog는 이번에 읽었으며 TLS/DB 변경 항목은 기존 DB가 없는 현재 설계에 직접 마이그레이션을 요구하지 않는다. 실제 생성/연결 시 다시 확인한다.
