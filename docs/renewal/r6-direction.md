## 1. 왜 지금 화면이 AI slop으로 보이나

근거 캡처: `docs/renewal/qa/r5/02-battle-desk.webp`, `01-home-cb.webp`, `03-cards-desk.webp`.

1. **낱장으로 뽑은 소품의 콜라주.** 나무·덤불·돌·연못이 제각각 빛 방향·크기·세부 밀도로 그려져 들판에 흩뿌려져 있다. 하나씩 따로 생성한 그림을 붙인 티가 난다.
2. **어디나 같은 세부 밀도.** 길·풀·소품·타워가 같은 정도로 그려져 시선이 머물 곳(초점)이 없다. 타워가 작아 전장에 묻힌다.
3. **탁한 안전 색.** 갈색 틀 + 올리브 풀 + 구리색 타워. 명도 대비가 약하고 타워끼리 색으로 구별되지 않는다.
4. **체계 없는 재질 흉내.** 나무·양피지·놋쇠 9-slice 틀이 판타지 서식처럼 보인다. 재질이 정보를 돕지 않고 무게만 더한다.
5. **정지 화면.** 손맛(입력 반응·기대·보상 연출)이 약하다. 도파민은 정지 그림이 아니라 움직임과 소리에서 나온다.
6. **글이 많은 홈.** 입력칸·작은 라벨·베이지 상자 반복. 첫 화면에 반할 대표 그림이 없다.

## 2. R6 원칙 (모든 시안이 지켜야 할 것)

| # | 원칙 | 구체 기준 |
|---|---|---|
| P1 | **한 화면에 주인공 하나** | 전투 화면의 70% 이상이 전장. UI는 조용한 중립색 틀로 물러나고, 채도 높은 색은 게임 속 기물에만 쓴다. |
| P2 | **실루엣 → 색 → 세부 순서** | 타워 20종은 실루엣만으로 구별되고, 계열별 대표색을 가진다. 세부 묘사는 지붕·무기 같은 위쪽 30%에만 둔다. 48px로 줄여도 판독, 몬스터는 32px로 판독. |
| P3 | **명도 구조로 길 읽기** | 길은 밝게, 땅은 중간, 가장자리는 어둡게. 고저(벼랑·물가 경계)와 접지 그림자로 깊이를 만든다. 빛은 왼쪽 위 하나. 소품은 가장자리에 무리 지어 화면을 감싸고, 흩뿌리지 않는다. |
| P4 | **움직임이 보상이다** | 모든 입력에 100ms 안에 반응한다. 정답이면 빛구슬이 HUD 게이지로 날아가 차고, 게이지가 차면 타워가 강해진다. 처치하면 동전이 포물선으로 날아와 숫자가 올라간다. 진화는 1.2초 변신 연출(번쩍임·실루엣 교체), 웨이브 승리는 배너와 꽃가루. 연속 정답 콤보는 소리 높이가 점점 오른다. |
| P5 | **고요함과 폭발의 대비** | 문제를 읽는 동안은 차분하게(18~24px 큰 글자, 강한 대비), 정답이 확정되면 폭발한다. 학습 순간의 가독성은 연출보다 앞선다. |
| P6 | **글꼴 체계** | 제목용 굵은 한글 글꼴 1종 + 본문 Pretendard 계열 1종. 크기는 4단계만 쓴다. |
| P7 | **일관성은 프롬프트가 아니라 공정에서 나온다** | 생성 그림을 그대로 싣지 않는다. ① 3D: Tripo 기본형 → 손질 → 통일 셰이더 + 고정 카메라·조명 장치(Blender) → 스프라이트·동작 프레임 렌더. ② 2D: 스타일 프레임 → 제한 팔레트 견본 → 고정 규칙으로 제작. 두 공정 모두 빛·원근·축척이 기계적으로 같아진다. |

## 3. 시안 판정표 (시안 5종을 이 표로 채점, 항목당 1~5점)

| 항목 | 질문 |
|---|---|
| 첫인상 | 3초 안에 "와" 하고 시선이 가는가 |
| 위계·가독성 | 문제 글과 핵심 수치가 한눈에 읽히는가 |
| 실루엣 판독 | 48px 타워·32px 몬스터를 모양만으로 구별하는가 |
| 양산 일관성 | 타워 140형태·몬스터 96형태·맵 4종을 같은 품질로 찍어 낼 수 있는가 |
| 손맛 잠재력 | 정답·처치·진화·승리 연출이 이 화풍에서 살아나는가 |
| 독창성 | 기존 유명 게임을 닮지 않았는가 |
| 대상 적합 | 3~6학년이 좋아하고 교사가 수업에 믿고 쓰는가 |
| 성능 | 학교 크롬북에서 60fps, 첫 진입 전송량 예산 안에 드는가 |
| 제작 비용 | 사람·도구·기간이 감당되는가(Tripo 비용 포함) |
| slop 위험 | 생성 도구의 버릇(빛 번짐·과한 질감·글자 뭉개짐)이 드러날 위험이 낮은가 |

## 4. 총괄의 현재 가설 (시안을 본 뒤 확정)

- 양산 일관성과 애니메이션을 함께 얻는 가장 확실한 길은 **사전 렌더 3D 공정**이다. 고정 카메라·조명·툰 셰이더로 타워 140형태와 몬스터 96형태의 빛·원근·축척을 기계적으로 맞추고, 걷기·공격·피격 프레임도 같은 장치에서 뽑는다. 낱장 생성 2D는 바로 이 일관성에서 무너졌다.
- UI는 반대로 **평면적이고 또렷하게** 간다. 재질 흉내를 걷고 굵은 모양·큰 글자·한 가지 강조색으로, 게임 그림이 돋보이게 한다.
- 도파민은 그림보다 **연출 명세(P4)**에서 나온다. 화풍을 정하면 손맛 명세와 소리를 함께 짠다.
- 2D 방향이 판정표에서 이기면 그쪽을 택한다. 가설은 시안 비교 뒤 바꿀 수 있다.

2. 고른 안으로 수직 단면(맵 1종 + 타워 4종 진화 + 종족 1개 + 전투·홈 UI + 손맛 연출)을 먼저 만들어 실제 게임에서 확인한다.
3. 통과하면 양산 계획(에셋 수·공정·비용·일정)을 세우고 단계별로 교체한다.
