## 0. 목적과 원칙

**목적**
1. **UI:** 화면이 "웹 관리자 화면·폼"이 아니라 **게임**으로 보이게 한다. AI 템플릿 느낌을 없앤다. 초등학생이 어느 화면에서든 **1초 안에 지금 할 일**을 찾는다.
2. **밸런스:** 처음에는 누구나 웨이브를 쌓아 올리고, 뒤로 갈수록 점점 깨기 어려워진다.
   - 정답을 많이 맞힐수록, 타워를 잘 고를수록 확실히 더 멀리 간다.
   - 모든 타워는 합리적인 강점과 약점을 가진다. 한 타워만 짓는 판은 섞어 짓는 판을 이기지 못한다.
   - "한 판 더"를 부르는 장치를 둔다.
3. **학습:** 틀린 낱말은 다음 판에 다시 나오고(오답 노트), 문제 난이도는 학생 실력에 맞춰 움직인다.

**원칙**
- **빼는 것이 먼저다.** 새 요소를 더하기 전에 중복·설명문·빈 칸·장식을 걷어낸다(§3).
- 게임 원화(41번 화풍: 타워·몬스터·맵)는 바꾸지 않는다. 바꾸는 것은 원화를 감싸는 UI다.
- **수치로 관리한다.** 화면은 버튼 수·상시 문장 수·글자 크기 종류·겹 수를 자동으로 센다(U0). 밸런스는 가상 플레이어 시뮬레이션의 목표표(§7.1)로 판정한다. 관문 수치를 넘으면 반려한다.
- **사용자 확정값은 건드리지 않는다.** HP 성장 115%, 웨이브 생존 시 성문 전회복, 배속 없음, 보통 한 판 15~25분, '모르겠어요' 0점이 그렇다.
  - 확정값 밖의 수단으로 목표를 못 맞추면 측정값·대안·영향을 정리해 사용자에게 결정을 받는다(PRD v0.5 §8 원칙).
- 작업은 원래 폴더 브랜치에서 하고 단계마다 커밋한다. 단계가 끝나면 묻지 않고 push한다.
- 검증은 바뀐 범위만 한다. 넓은 검사(verify·e2e·밸런스 관문)는 마감에서 한 번 한다. 캡처는 단계별로 지정한 장면만 찍는다.

## 1. 진단

### 1.1 화면 — 왜 AI slop처럼 보이나

기준 원화(`docs/assets/design-41-kingdom-expedition.png`)의 UI는 그림으로 그린 판·종이·답안판이다. 지금 화면은 **평평한 웹 상자에 갈색을 칠한 폼**이다. Antigravity 평: "커피색으로 칠한 부트스트랩 폼".

| 화면 | 결함(캡처에서 확인) |
|---|---|
| 홈 | 상단 통계 4칸(실시간 접속·오늘 플레이·누적 접속·누적 플레이)이 관리자 KPI 카드다. 오프라인이면 "내 기기 0판"이 두 번 나온다. 랭킹에 탭 4 + 학년 4 + 난이도 4 = 버튼 12개가 있다. 한 화면에 버튼 약 23개와 입력칸 2개가 있다. 시작 버튼이 왼쪽 아래에 묻힌다. 폰에서는 첫 화면에 시작 버튼이 없다. 1440×900에서 세로로 41px 스크롤된다 |
| 새 게임 | 같은 직사각형 라디오 카드가 반복되고 선택 표시는 얇은 파란 웹 테두리다. 난이도 설명이 세 번 나온다. 닉네임 바가 홈과 겹친다. 닫기와 뒤로가 중복이다. 지도 미리보기가 회색 네모 디버그 그림이다. 준비 중인 4~6학년 칸이 활성 칸과 같은 크기다 |
| 전투 | 전장이 고동색 틀에 갇혀 있다. 오른쪽 칸 아래가 300px 넘게 빈 갈색 벽이다. 빈 타워 칸 4개를 늘 그린다. 웹 `<select>` 모양의 "설치 자리 목록"이 늘 보인다. 문제판 오른쪽 상자에 보상 칩(+22 +15 −8)을 가둬 두었다. 의미를 알 수 없는 `○○○`(연속 정답)이 있다. 대장 웨이브에는 웨이브 번호가 네 번, 골드 획득이 네 방식으로 나온다. 대장이 계속 맞으면 흰색 점멸이 이어져 하얀 실루엣으로 깨져 보인다(`EnemyLayer.ts:221`) |
| 징집·진화 | 모달 > 카드 테두리 > 검은 그림 상자 > 알약 태그로 네 겹이다. 카드를 고른 뒤 "고르기"를 한 번 더 눌러야 한다. 진화 능력치를 소수점 문장(`11.2 → 14.4`)으로 읽게 한다. 진화 창 뒤에 이전 팝오버가 열린 채 겹친다 |
| 일시정지 | 브라우저 기본 라디오·체크박스·`fieldset`·밑줄 링크가 그대로 보인다. "잠시 멈췄어요."는 제목과 같은 말이다 |
| 결과 | 연출 없는 8줄 표(영수증)다. 그 아래 각주가 합계를 한 번 더 적는다. 1366×650에서 "다시 하기"가 반쯤 잘린다 |

### 1.3 밸런스 — 지금 수치(보통 난이도, 정원 맵, 가상 플레이어 정답률 80%, seed 16)

| 문제 | 근거 |
|---|---|
| **곡선이 오르막이 아니라 벽이다** | 웨이브 총 HP는 5웨이브마다 약 2배가 된다(W10 3,144 → W20 16,635 → W30 75,826). 수입은 웨이브당 약 160골드로 거의 일정하다(판당 약 2,500). 사망이 W14~16에 몰리고(균형형), 보스 웨이브 사망이 37%다 |
| **실력이 결과를 거의 바꾸지 못한다** | 정답률 60→95%의 효과가 2.5~3웨이브다. 전략별 중앙값은 초보형 14, 균형형 15, 궁수만 16, 균형10 17, 키우기형 9. **궁수만 지은 판이 섞어 지은 판보다 멀리 간다** |
| **넓게 짓기가 키우기를 늘 이긴다** | 강화의 1골드당 효율은 새 타워 설치의 9~50%다(Lv7→8 0.15, Lv9→10 0.09). 판 끝 타워의 약 80%가 Lv1~3 기본형이라 진화 그림 120장이 잘 안 보인다 |
| **상성이 얕다** | 피해 유형은 물리·마법 2종이고, 일반 적에 재생·보호막이 없다. 석궁은 모든 적 역할에서 궁수의 1.10배 이상이라 사실상 상위 호환이다. 빠른 적을 직접 잡는 타워가 없다 |
| **쓸모가 의심되는 타워** | 화차는 모든 줄에서 최저 효율이고 단독으로 W10까지 간다. 서리·약병·바람은 단독이면 W1에 진다. 깃발은 한 번도 안 골라지고 효율 검사도 계속 실패한다. 종각은 약 1%만 골라진다. 징집의 약 50%가 노포·석궁·덫·박격포에 쏠린다 |
| **후반에 새로움이 없다** | 새 적 유형은 W17(분열)이 마지막이다. W21 침입 종족은 이름·그림·보스 기믹만 바꾸고 역할 수치는 같다. W14 이후 새 타워가 없다(장착 8칸) |
| **새 적이 너무 늦게 나온다** | 비행은 W14, 마법저항은 W12, 분열은 W17에 처음 나온다. 중앙값이 15라서 상성이 중요해지는 순간 판이 끝난다 |
| 문서 불일치 | `progression.md` §3 배율표(Lv4 2.30)가 계약(1.80)과 다르다. `simulate:towers`의 필수 비교가 옛 10종만 본다(`towerEfficiency.ts:79`) |
| 시뮬레이터 한계 | 봇이 고정 순서로 짓는다. 시너지(깃발·종각·서리)를 못 보고, 정원 맵 하나만 보며, 판매·재배치를 하지 않는다 |

### 1.4 학습 로직 — 오답 노트·난이도 조절의 전제

- 공개된 문제은행은 3학년 51문항이고 **난이도 단계(`difficultyTier`)가 하나도 없다.** 그래서 지금의 단계 일정은 실제로 아무 일도 하지 않는다. 후보 은행(817문항)에는 단계가 있다.
- 판 진행은 결정적이다(같은 씨앗과 명령이면 같은 상태, 시험 A18). 판 밖 자료는 `createRun` 때 RunState에 복사해야 하고, 문항 선택은 RunState와 ctx만 보는 순수 함수여야 한다.
- 선택 규칙을 바꾸면 `RULES_VERSION`, 상태 필드를 더하면 `RUN_STATE_VERSION`(6→7)을 올려야 한다. 밸런스를 바꾸면 `balanceVersion`도 올라간다. **셋 다 진행 중 저장의 이어하기를 막으므로 한 번에 내보낸다.**
- IndexedDB 버전을 올리면 시험 2곳이 깨진다(`privacy-storage.test.ts`, e2e `home.spec.ts:140`). 오답 노트는 **localStorage**에 둔다.
- PRD v0.5 §20.5는 "계정 간 개인화 숙련도 모델·매일 복습 알림"과 "검증 안 된 숙련도 점수 표시"를 막는다. 오답 노트는 **이 기기 안에서만, 점수·퍼센트 없이** 넣고 §20.5에 예외를 적는다.

## 2. 디자인 방향 v3 — 「그림책 원정대」

### 2.1 결정: 재질 흉내를 버리고 밝은 종이 면으로 바꾼다

- **원인 판단(Antigravity와 총괄 일치):** 호두나무·양피지·놋쇠를 그림 없이 단색 CSS와 테두리로 흉내 낸 것이 slop의 직접 원인이다. 짙은 갈색 틀은 원화의 밝은 초원색을 죽인다.
- **방향:** 원화의 세계(맵·타워·몬스터)가 주인공이다. UI는 그 위에 놓인 **밝은 종이 카드**와 **눌리는 키캡 버튼**이다. 개성은 그림으로 그린 상태·적 특성 아이콘이 맡는다.
- 9-slice 나무판 원화 키트는 만들지 않는다. 생성 질감이 오히려 싸구려 모바일 게임 느낌을 낼 위험이 크고, 작업량도 크다.

## 6. L — 오답 노트 + 난이도 자동 조절

### 6.1 오답 노트
- **저장:** localStorage `vocabulary-td.reviewNote.v1`
  - 구조: `{ v: 1, items: { [senseKey]: { lemma, senseKey, bankId, questionIds[], misses, clears, addedAt, lastSeenAt } }, graduated: number }`
  - 낱말 뜻(`senseKey`) 단위로 모은다. 같은 뜻의 다른 문항으로 다시 물어 정답 위치를 외우는 효과를 막는다.
- **담기:** 연습이 아닌 판이 끝날 때(`RunController.finish`) 그 판의 오답·'모르겠어요'를 담는다.
  - 담을 때 `misses+1`, `clears=0`이 된다.
  - "저장하고 나가기"는 담지 않고, "이번 판 끝내기"는 담는다.
- **졸업:** 다른 판에서 2번 맞히면 노트에서 빼고 `graduated`를 올린다.
- **상한:** 60개. 오래 안 본 것부터 뺀다. 철회 문항과 다른 은행 항목은 읽을 때 걸러 낸다.
- **판에 복사:** `createRun` 때 최대 12개 뜻(`misses` 많은 순, 같으면 오래 안 본 순)을 `RunState.quiz.reviewSenses`에 넣는다. 판 안에서는 이 복사본만 본다(결정성).
- **선택 규칙**(`selectQuestion`, PRD §9.4 제약 유지):
  - **준비 문제에서만** 3문항에 1번꼴로 복습 단계를 먼저 시도한다. 전투 중 읽기 부담은 늘리지 않는다.
  - 복습 단계 조건: 최근 30문항·최근 8뜻 제한을 지킨다. 같은 뜻의 다른 문항을 우선하고, 없으면 그 문항을 다시 낸다.
  - 한 판에서 뜻 하나는 최대 2번까지만 복습한다. 조건에 맞는 문항이 없으면 기존 단계로 넘어간다.
  - 보상은 똑같다.
- **화면에 넘길 값:** `view.question.isReview`, 결과의 새로 담은 뜻 수·졸업 뜻 수
- **지우기:** `clearLocalHistory`가 노트 키도 지운다.

### 6.2 난이도 자동 조절
- **도움 단계 h ∈ {−1, 0, +1}:** 이번 판 최근 채점 4개로 정한다.
  - 오답·'모르겠어요' 3개 이상이면 −1, 4연속 정답이면 +1, 나머지는 0이다.
  - 판마다 0에서 시작한다(판 밖 숙련도 모델 없음).
- **단계가 있는 은행:** 목표 단계를 h만큼 옮긴다(basic ↔ core ↔ advanced ↔ challenge). 난이도 문이 걸러 낸 범위 안에서만 옮긴다.
- **단계가 없는 은행(지금 3학년 51문항):** 읽기 부담(`readingLoad`)으로 대신한다. 지금 실제로 효과가 나는 것은 이 경로다.
  - h=−1이면 하위 40% 안에서 먼저 고르고, h=+1이면 상위 40% 안에서 먼저 고른다.
  - 고를 문항이 없으면 기존 단계로 넘어간다.
- h=−1일 때는 복습 단계를 쉰다(어려워하는 학생에게 틀린 낱말을 겹쳐 내지 않는다).
- 화면에 단계·점수를 보이지 않는다(§20.5).

### 6.3 버전·문서·시험
- `RUN_STATE_VERSION` 6→7, `RULES_VERSION` 1회 올림. `progression.test.ts:417`을 고친다. 밸런스 B1~B3의 `balanceVersion` 올림과 같은 출시로 묶는다.
- PRD v0.5 §20.5에 "이 기기 오답 노트(동기화·숙련도 점수 표시 없음)와 판 안 도움 단계는 허용"을 적고 개정 기록 1줄을 남긴다.
- 시험(바뀐 범위만):
  - 노트 담기·졸업·상한·철회 거르기
  - 복습 선택의 §9.4 준수
  - 같은 씨앗 재현(A18)
  - h 계산
  - 읽기 부담 우선이 빈 집합에서 넘어감
  - 기존 `difficulty-quiz`·`run.test` 통과

### 6.4 완료 기준
- 위 시험이 통과한다. 단계 없는 은행에서 h=−1일 때 고른 문항의 평균 읽기 부담이 낮아진다.
- 공개 은행에 단계가 들어오면 코드 변경 없이 단계 이동이 켜진다(합성 은행 시험).

## 7. B — 밸런스 재설계

### 7.1 목표표(밸런스 관문, B0 장비로 자동 판정)

가상 플레이어 기준이다. 4개 맵 평균이고, 맵 사이 차이는 ±2웨이브 안이어야 한다. "균형형"은 지금의 균형10 봇이고, "최적화형"은 B0에서 만드는 롤아웃 봇이다.

**보통 난이도 곡선**

| 지표 | 지금 | 목표 |
|---|---|---|
| 초보형 정답률 60% 중앙값 | 미측정(80%일 때 14) | **10~12**(첫 두 보스는 넘는다) |
| 균형형 80% 중앙값 | 17 | **14~17**(한 판 15~25분 확정 범위 안) |
| 최적화형 95% 중앙값 | 없음 | **22~26** |

### 7.2 설계 규칙

**A. 곡선 — 확정값(115%·전회복)은 그대로 두고 나머지로 모양을 만든다**
- **초반 완충:** W1~6은 HP 배율을 0.80에서 1.00으로 올린다. 누구나 첫 보스까지 쌓아 올리는 맛을 보게 한다.
- **웨이브 길이:** 적 수 증가 폭(지금 3웨이브마다 +2)과 등장 간격을 줄여 웨이브 1개를 1.4분 이하로 만든다. 적 수가 줄어든 만큼 개체 HP로 옮겨 총 HP는 그대로 둔다. 그래야 한 판 시간 안에서 실력 차이가 웨이브 수로 드러날 여유가 생긴다.
- **보스:** 보스 HP 배율과 호위 수를 조정해 보스 웨이브가 사망의 35% 이하가 되게 한다. 보스는 "고비"이지 "벽"이 아니다.

**B. 경제 — 정답과 실력이 복리로 쌓이게 한다**
- **정답 골드의 웨이브 성장:** `correctGold = 기본 + k × (웨이브−1)`(k는 B1에서 찾음, 후보 0.5~1.0). 지금처럼 고정이면 뒤로 갈수록 정답의 무게가 줄어든다.
- **불꽃 강화:** 전투 중 3연속 정답이면 불꽃 1단(지금 +25% 공격속도 8초), 6연속이면 2단을 준다(후보 +40%, 지속시간 갱신). 정답률이 높을수록 불꽃이 자주 켜져 실력 차이를 키운다.
- **처치 골드·보스 보상:** 정답 골드 몫이 55% 아래로 내려가지 않는 범위에서만 조정한다.
- 오답·'모르겠어요' 0골드는 그대로 둔다(확정).

**C. 적 등장 시점과 징집 — 상성이 판 중간부터 중요해지게**

|---|---|---|
| 빠름 | W3 | W3 |
| 튼튼 | W5 | W4 |
| 물리저항 | W7 | W6 |
| 떼 | W9 | W7 |
| 비행 | W14 | **W8**(처음 2웨이브는 10%) |

- 징집을 W3/6/10/14에서 **W3/6/9/12**로 옮긴다. 장착 8칸은 W12에 다 찬다.
- **대응 보장:** 3웨이브 안에 새 역할이 처음 나오는데 가진 타워 중에 그 역할의 강점 타워가 없으면, 징집 후보 3개 중 1개를 반드시 그 강점 타워로 낸다. 학생이 운 때문에 막히지 않게 한다.

**D. 타워 역할 — 강점·약점의 합리적 배치**
- 원칙: 궁수 = 기준(모든 적 1.0). 나머지는 **이름이 말하는 대로** 강하고, 그 반대에서 약하다.
- 이 표를 계약의 타워별 `strongVs`/`weakVs` 필드로 옮기고, 화면의 "잘 잡는 적·약한 적" 아이콘을 이 필드에서 자동으로 만든다. 수치와 설명이 어긋나지 않게 하기 위해서다.
