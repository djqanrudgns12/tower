# R6 엔진 변경 순서

이 문서는 구현 전 초안이다. [판정 데이터](../balance-v2-draft.json), [편성 규칙](wave-mixer.md), [표시 이름](theme-split.md)과 함께 사용한다. v0.4라는 파일명의 현재 계약은 내부 판 번호가 1.0.0이다.

## 1. 버전과 데이터

`src/contracts/balance.ts`의 20종 열거형, 무제한 레벨, Lv4·7 갈래, 종족별 예전 역할은 v1 파서로 보존한다. v2 파서를 별도로 두고 `src/content/index.ts`가 판을 선택한다. 새 판은 `balanceVersion=2.0.0`과 `mixer.algorithm=r6-mix-1`을 한 묶음으로 고른다. 누락 필드·범위 밖 수치·알 수 없는 ID·중복 해금·표 길이 오류를 로딩 시 거부한다. `src/domain/types.ts`, `context.ts`, `run.ts`에는 해당 판에 실제로 쓰이는 ID·상태만 들어가게 한다. v1 기록을 새 ID로 재해석할 수 없으므로 완료 기록·대기 제출은 원래 balanceVersion을 사용한다. 이전 활성 상태가 지원되는 진입점은 원래 파서와 엔진을 사용한다.

## 2. 타워, 비용, 해금

`src/domain/towers.ts:91,120,325,336`에서 다음 수식을 전투·미리보기·봇이 공유한다. L은 1~20이고, BP 10000은 1배, 거리 1000은 1칸, 피해 1000은 1HP다. ms를 30Hz 틱으로 바꿀 때 올림한다.

- 형태는 floor(L/2), 무기는 마지막 임계값 ≤ L의 단계(1·6·12·18), 재질은 같은 순서로 강철·합금·세라믹 장갑·금테다. L=1..20의 직접 피해는 floor(기본 피해 × 1000 × damageMultiplierBP[L−1] / 10000)이다. 무기에 별도 shotDamageBP가 있으면 추가로 곱해 내린다. 표에 없는 배율은 10000이다. 레벨만으로 바뀌는 수치는 직접 피해와 다음 강화 비용이다. 사거리·주기는 타워 표, 무기 효과는 해당 단계의 행을 쓴다.
- L→L+1 비용은 5 × floor((기본가 × upgradeCostOfBaseBP[L−1] + 25000) / 50000)골드다. Lv20에서 비용은 null이고 명령도 거부한다. 예컨대 레일 Lv1→2는 25골드, Lv19→20은 250골드다. 판매는 누적 실결제액을 기준으로 한다. `evolve_stone` 보물은 무기 II·III·IV로 들어가는 세 거래에만 적용하고 기존 보물 할인 반올림을 따른다.
- `src/domain/draft.ts`, `run.ts:405`에서 시작 목록 rail·mortar·cryo를 만든다. W3·6·9를 **완료한 뒤** 각각 prism·hangar·bastion을 추가한다. 자동 해금은 설치권만 주며, 실제 설치 시에는 골드를 낸다. owned를 중복 없는 집합처럼 다루고 결과 재전송·복원·미리보기로 중복 지급하지 않는다. 연습판은 별도 설정을 쓴다.
- `src/domain/combat.ts:20,176,407`과 `relics.ts:81`의 공격·보물 효과를 새 ID로 연결한다. 기본 우선순위는 사거리 안에서 진행도 내림차순, 동률이면 생성 ID 오름차순이다. 감속·밀치기·보스 저항·외부 속도는 기존 statusCaps와 externalCaps를 적용한다. 예전 20종의 상성 배율은 v2에 자동 상속하지 않는다.

| 타워 | 무기 I → II → III → IV의 판정 |
|---|---|
| rail | 즉발 한 발 → 4틱 차이 두 발 → 세 발 → 가속 단발. IV는 한 발 피해 두 배, 첫 표적 뒤 같은 직선 폭 안에서 추가 한 기에 65% 피해. 후속탄은 직전에 표적을 잃으면 다시 조준한다. |
| mortar | 지상 원형 착탄 최대 4기 → 최대 5기·반경 확대 → 같은 지점에 지연 착탄 한 번 → 착탄·지연 착탄 뒤 같은 지점에 장판 두 번. 탄속은 초당 8칸, 위치는 발사 시 확정한다. 장판 첫 타격은 첫 착탄 후 zonePeriodMs, 이후 같은 간격이다. 각 타격의 피해는 기본탄 대비 BP다. |
| cryo | 타워 중심 원형 파동으로 1→2→3→4기를 감속한다. IV는 300ms 뒤 같은 범위를 한 번 더 판정해 30% 피해와 감속을 준다. 감속이 풀렸거나 남은 시간이 짧은 순서를 먼저 적용한 뒤 기본 우선순위로 고른다. 감속은 가장 강한 값, 지속은 타격 시점 기준이다. |
| prism | 즉발 연쇄 2→3→4→5기. 마지막 타격 위치에서 반경 내 가장 가까운 미피격 적으로 넘어간다. 거리 동률은 생성 ID순이다. 매 연결마다 이전 피해에 감쇠 BP를 곱해 내린다. IV는 마법 저항을 1500BP만큼 차감하고 하한은 0이다. |
| hangar | 한 주기당 1→2→3→4기의 드론이 한 번씩 사격한다. 비행 우선, 같은 주기에서 아직 배정되지 않은 표적 우선, 후보가 한 기면 집중한다. 첫 기 이후는 followDamageBP로 줄인다. 발진 간격은 launchGapTicks이며 각 발진 때 재조준한다. 사격 틱에 즉시 적중하며 귀환은 연출이다. |
| bastion | 근접 지상 1→2→3→4기를 밀고 이웃 타워를 강화한다. 자신의 오라는 받지 않는다. 동일 종류의 오라는 가장 큰 값만 적용하고 III부터 공격 속도도 높인다. 보스 밀치기는 0으로 두고 일반 적은 생애 누적 상한을 적용한다. |

`src/domain/events.ts`에서 발사·연쇄·지연 착탄·수준 전환을 판정 틱과 ID로 내보낸다. 이미 예약된 공격은 발사 시점의 무기·피해를 보존한다. 판매·전투 종료 때 미발진 연사와 드론 예약을 취소하고, 이미 날아간 탄·지연 착탄은 기존 전투의 종료 경계를 따른다. 표시용 공격 프레임은 판정 시간을 바꾸지 않는다. 레시피 66행에서 수준·재질·무기 단계가 표와 일치해야 한다. 예컨대 레일 IV의 조준 1기 + 추가 관통 1기는 레시피 targetCount=1, pierceCount=1이다.

## 3. 100개체와 편성

`src/domain/factions.ts`, `traits.ts`, `waves.ts`, `combat.ts:69`에서 종류·그림 키·실행 상태를 분리한다. [JSON](../balance-v2-draft.json)의 표를 아래 순서로 펼친다.

1. 종족 5개 × 계통 4개 × 단계 4개가 일반 80개다. 식은 `종족-계통-t단계`이며 보스 20개는 계통에 boss를 쓴다. 아트 설정표의 문자열은 다음 일대일 치환으로 연결한다. 밑줄을 하이픈으로, mech→machine, golem→stone, rush→runner, heavy→armored, 보스 접미사 5·10·15·20→t1·t2·t3·t4로 바꾼다. 예를 들어 mech_heavy_t3는 machine-armored-t3이다. 저장·편성·테마·리그 조회에는 이 정규 ID 하나를 쓴다.
2. 체력·속도 BP는 계통 기본 × 단계 × 종족 × 계통별 특수 배율 순서다. 각 곱에서 10000으로 나누어 내리고, 빠진 배율은 10000이다. 양 저항은 계통 기본 + 단계 가산 + 종족 가산, 정예의 물리 가산까지 더한 뒤 각각 5000BP로 제한한다. 예를 들어 machine-armored-t3은 HP 12810BP, 속도 8364BP, 물리 저항 3700BP, 마법 저항 900BP다.
3. 웨이브 체력은 기존 `waveHpBaseMilli`를 쓴다(44000부터 115% 올림, 기준 개체 수 보정, W1~13 완충). 여기에 기존 `difficultyHpBP` → 개체 HP BP → 정예 HP BP → 보스 기술 HP BP 순으로 매번 올림한다. 이동 속도에는 정예 속도를 한 번 더 곱해 내린다. 보스는 boss 계통과 bossTierHpBP만 쓰며, 일반 단계의 속도·저항 가산은 생략한다. 종족 기본 보정은 받는다.
4. 엘프 특수는 비행, 인간 특수는 무거운 공성 수레다. 기계·벌레 특수는 처치된 자리에서 각각 1·2개의 조각으로 나뉜다. 조각 체력은 부모의 **정예 적용 전** 개체 HP BP × childHpBP다. 속도·저항은 정예 전 부모 값, 정예·분열·재생은 없고 누출 피해는 1이다. 바위 특수는 등장 3초 뒤부터 3초 간격으로 최대 체력의 3%를 최대 3회 회복한다(내림·최대 체력 상한). 정예는 양쪽 종류 모두 체력 2배, 장갑은 물리 저항 +2000BP, 신속은 속도 1.2배다. 일반 누출은 특수 표의 leakDamage 또는 1, 정예 2, 보스 3을 적용한다.
5. 각 종족의 보스 4종은 bossByFaction의 순서로 기존 여섯 기술 중 하나만 받는다. ward_layers와 snack_mend는 시작 HP를 85%로 보정한다. 바위 3단은 5겹, 4단은 회복만 적용한다. 아트의 self_mend는 기존 snack_mend를 가리키며 화면에는 “회복”으로 표시한다. 호위와 분열 조각에는 처치 골드·점수를 주지 않는다.
6. `run.ts:366`의 전투 난수 소비와 v1 composeWave 호출을 버전 분기로 나눈다. 웨이브별 스폰 예약·예고·시뮬레이터가 [혼합기](wave-mixer.md) 하나를 공유한다. 도감 첫 발견은 실제 등장 이벤트에서 기록하고, 편성 계획에 예약된 ID는 미리 발견 처리하지 않는다.

## 4. 불러오기와 화면

`src/content/index.ts:44,128`, `application/session.ts`에서 학년별 문제은행과 맵 선택을 분리한다. R6 네 학년은 자기 문제은행과 garden_u 좌표를 쓴다. v1의 학년별 맵·연습 흐름은 원래 설정으로 읽는다.

`src/game/BattleScene.ts:45`, `assets.ts`, `layers/EnemyLayer.ts`, `TowerLayer.ts`, `EffectLayer.ts`를 차례로 바꾼다. 첫 준비 화면에서 첫 편성의 두 종족만 요청한다. 다음 웨이브의 실제 종족 집합과 현재 적·이펙트가 참조하는 팩의 차이만 미리 받는다. 팩 키에 에셋 판과 종족을 포함하고 동시 요청은 하나의 Promise로 합친다. 실패 시 취소·재시도 또는 공용 역할 그림으로 진행한다. 렌더러만 대체 그림을 고른다. 완료된 이전 요청이 다음 장면에 붙지 않도록 장면 토큰을 확인하고 살아 있는 스프라이트가 참조하는 팩은 해제하지 않는다. 다섯 종족이 실제로 나오는 후반부는 저사양 기기의 최고 메모리·60fps를 G2에서 잰다.
