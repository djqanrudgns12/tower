# 웨이브 편성

[PRD §4.3](../PRD-r6.md)과 [밸런스 표](../balance-v2-draft.json)의 `mixer`를 함께 쓴다. 아래의 종족 수는 후보 수와 실제 등장 수가 같다. 예고 화면의 아이콘도 완성된 편성에서 집계한다.

| 웨이브 | 실제 종족 수 | 일반 적 단계 비율(T1/T2/T3/T4) | 편성 변화 |
|---|---:|---|---|
| 1~3 | 2 | 100/0/0/0 | 두 종족이 첫 웨이브부터 나온다. |
| 4~6 | 3 | 55/45/0/0 | W4에 특수 계통을 한 자리 보장한다. W5 첫 보스. |
| 7~10 | 4 | 0/85/15/0 | W10 두 번째 종족 보스. |
| 11~15 | 5 | 0/55/45/0 | 주 종족의 배정 가중치는 3, 나머지는 각각 1이다. |
| 16~20 | 5 | 0/0/60/40 | 주 종족 가중치는 2다. W20에 4단계 보스가 나온다. |
| 21~ | 5 | 0/0/0/100 | 주 종족과 보스 순환을 계속하고 정예 비율을 다시 높인다. |

## 재현에 쓰는 입력

판 시드(uint32), 맵 ID, `balanceVersion`, 혼합기 ID, 1부터 세는 웨이브 번호를 쓴다. 난수 상태는 용도별로 새로 만든다. 문자열 `[algorithm,balanceVersion,mapId,seed>>>0,wave,stream]`의 공백 없는 JSON 배열을 UTF-8로 바꿔 FNV-1a 32비트(초기 2166136261, 바이트 XOR 뒤 Math.imul로 16777619 곱하기)로 접는다. 해시가 0이면 0x6d2b79f5를 쓴다. 이 값으로 기존 `rng.ts`의 xorshift32, intBelow, Fisher–Yates를 시작한다. 전투·문제·보기·연출 난수에서 값을 가져오지 않는다. 후보 순서는 JSON에 적힌 factionOrder, familyOrder, 오름차순 단계다. 가중 추첨은 intBelow(가중치 합) 뒤 누적합에서 처음 넘는 항목을 고른다.

웨이브 0의 `order`로 다섯 종족을 한 번 섞어 P를 얻는다. 웨이브 0의 `reserve`로 P 순서의 각 종족에서 T4 질주·특수 두 ID씩, 총 10개를 한 번 섞는다. 아래 예약 ID는 지정 웨이브 전에 일반 추첨에서 제외한다. 예약은 이미 낸 적에 새 표식을 붙여 첫 등장으로 세는 일을 막는다.

| 첫 등장 웨이브 | 일반 편성에 정확히 한 자리 먼저 배정할 ID |
|---|---|
| 3 / 6 / 9 | P[0] 질주 T1 / P[1] 특수 T2 / P[2] 중장갑 T3 |
| 12 / 15 / 18 | P[3] 질주 T2 / P[4] 보병 T3 / P[0] 특수 T3 |
| 21, 24, …, 48 | 섞어 둔 T4 예약 목록에서 차례로 하나씩 |
| 51 이후 3의 배수 | 미등장 T4 일반 ID 중 첫 항목. 모두 나왔으면 마지막 등장 웨이브가 가장 오래된 ID(동률은 후보 순서). |

## 편성 의사코드

`lastSeen`은 이전까지 편성에 넣은 일반 ID별 마지막 웨이브다. 미등장은 0이다. 시드로 W1부터 순서대로 계산할 수 있으며, 예고·재접속은 같은 입력에서 캐시 사본을 쓰거나 순서대로 재생한다. 파생 적이나 보스, 정예 속성은 이 표에 넣지 않는다.

```text
band = fromWave <= w 인 마지막 행
active = P의 앞 band.factions개
primary = active[(w - 1) % active.length]
N = min(count.max, count.base + count.step * floor((w-1)/count.stepEveryWaves))
B = (w % 5 == 0)
n = N - int(B)
speciesQuota = apportion(n, primary에 primaryWeight, 다른 종족에 1씩)
tierQuota = apportion(n, band.tierWeights)
pins = 이 웨이브의 첫 등장 예약 목록
if w == 4: pins += [P[0].special.t1]
list = []
for id in pins:
    list에 id 추가, 해당 종족·단계 잔여량을 각각 1 줄임
speciesSlots = 남은 종족별 개수만큼 active 순서로 펼침
tierSlots = 남은 단계별 개수만큼 단계 순서로 펼침
shuffle(stream(w,"tiers"), tierSlots)
for i in 0 .. speciesSlots.length-1:
    후보 = speciesSlots[i]와 tierSlots[i]의 네 계통에서
           가중치 0과 아직 잠긴 예약 ID를 제외
    list에 stream(w,"families")로 familyWeights 가중 추첨한 후보 추가
shuffle(stream(w,"spawn"), list)
rate = W1~20 기존 eliteRate, W21부터 endlessEliteRate
eliteCount = floor(n * rateBP(w) / 10000)
indices = shuffle(stream(w,"eliteSlots"), [0..n-1])의 앞 eliteCount개
indices 순서대로 stream(w,"eliteKinds")의 intBelow(2)로 armored 또는 swift 부여
lastSeen에 list의 일반 ID와 w 기록
if B:
    j = w/5 - 1
    list의 floor(70*(N-1)/100) 자리에 P[j % 5].boss.b(1 + j % 4) 삽입
return list, lastSeen, 등장 종족 집합
```

각 stream(w,이름)은 한 웨이브에 한 번 초기화해 계속 소비한다. `apportion`은 기존 최대 나머지 방식이고 동률은 배열 순서로 푼다. 모든 허용 종족·단계 쌍에 예약되지 않은 계통이 하나 이상 있다. 종족 몫의 최솟값도 1보다 크므로 한 ID가 한 웨이브를 채울 수 없다. W11부터 다섯 주 종족이 매 웨이브 교대한다. 보스는 W5·10·15·20·25에 서로 다른 종족이며, 주기 5와 4가 서로소라 W100까지 20개 보스 ID가 모두 한 번씩 나온다.

**첫 등장 보장의 한계.** W3부터 3의 배수마다 일반 개체 한 종류가 처음 나온다. 따라서 해당 구간에서는 연속된 어느 세 웨이브에도 첫 등장이 있다. 무한 구간에서 등장 가능한 일반 ID는 T4 20개뿐이다. 이를 소진한 뒤에는 가장 오래 쉬었던 개체를 확정 배치하고, 도감의 첫 발견 수는 그대로 둔다. 100개 전체는 여러 판에 걸친 도감 목표다. 보스 호위가 미리 예약 ID를 보여 주지 않도록 호위는 자기 종족의 T1 보병으로 제한한다. 분열 조각은 도감·첫 발견에서 제외한다.

## 경계 시험과 랭킹

시드 0·1·0xffffffff 및 연속 256개 시드로 W1~105를 생성해 N, 보스 위치·20개 ID, 종족 수, 단계 정수 몫, 정예 수, W4 특수 및 첫 등장 간격을 검사한다. 경계 W3→4, W6→7, W10→11, W15→16, W20→21을 골든 편성으로 고정한다. 순차 생성·예고 두 번·중간부터 복원한 편성을 바이트 단위로 대조한다. 이미지 적재 실패·전투 입력·읽기 시간·정답 순서가 달라도 같은 편성이어야 한다.

서버의 현행 승인 단위는 은행 판·학년·밸런스 판·맵이다. 완료 요청에는 편성 시드나 명령 로그가 없다. 서버는 승인 조합과 난이도 규칙을 조회해 답안 재채점, 점수 상한, 최소 시간을 검증한다. 이번에는 N·등장 간격·5웨이브 보스·문항 구조를 유지해 기존 검증식을 사용한다. 편성 재현은 도메인·시뮬레이터의 시험으로 증명한다. 순위 제출·시즌 전환은 [엔진 변경 순서](engine-changes.md)에 따른다.

[실행 가능한 편성 예시](wave-mixer.mjs)는 같은 저장소의 `apportion`, `shuffle`, `intBelow`를 인자로 받는다. 예시에서 다음 웨이브를 한 번 요청하면 상태가 전진한다. 제품 예고 화면에서는 복제본을 쓴다. ID 문자열은 `machine-infantry-t1`, `machine-boss-t4` 형식이다.

### G0 편성 확인값

garden_u, 판 2.0.0, 시드 1에서 생성한 스폰 순서다. 공백 없는 JSON 배열 `[[id, elite 또는 null], ...]`의 UTF-8 SHA-256 앞 16자리로 비교한다.

| 3 | 8b620d61ed4895fa | 4 | f76075761cdc54e9 |
| 6 | 81d05a961169fb1f | 7 | 9ab285bd1f21e01e |
| 10 | b06fb83f4d5dd459 | 11 | 9e7910bed165a445 |

시드 0~255와 0xffffffff에서 W1~105를 검사했다. 총 26,985개 편성에서 종족 수·단계별 정수 몫·첫 특수·첫 등장 예약·소진 후 재등장·정예 수·보스 위치가 규칙과 일치했다. 각 시드는 W100까지 보스 20종을 모두 냈고, 전체 표본에서 100개 ID를 모두 확인했다. 시드 1을 처음부터 다시 계산한 스폰 순서도 105웨이브 모두 일치했다.
