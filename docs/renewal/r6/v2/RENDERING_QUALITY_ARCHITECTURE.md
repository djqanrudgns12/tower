## 1. 현행 "살짝 흐린 느낌" 원인 수학적 진단

브라우저 화면의 텍셀 밀도는 창 크기가 아니라 **Phaser 캔버스가 실제 점유한 CSS 영역과 DPR**, 그리고 **`r6Overview` 크롭 영역**에서 결정된다.
- 현행 `BattleScene.layout()`([BattleScene.ts](../../../src/game/BattleScene.ts#L124))은 전체 `960×576` 월드 중 **`r6Overview = (127, 37, 746, 467)`**([mapProjection.json](../../../src/game/r6/mapProjection.json))만을 화면에 맞춘다.
- 따라서 전체 월드 `2×`(`1920×1152`) 배경을 쓰더라도 실제로 화면에 들어오는 원본 픽셀은 **`1492×934`**뿐이다.
- 정상 품질 전체보기에서 `z = min(호스트 CSS폭 / 746, 호스트 CSS높이 / 467) × 실제 DPR`일 때 `texel / 물리 px = d / z`가 되며 실측 계산값은 아래와 같다.

| 조건 | 전장 CSS 크기 | 물리 px/월드 px (`z`) | 1× 밀도 | **2× 밀도 (`1920×1152`)** | **3× 밀도 (`2880×1728`)** |
| --- | ---: | ---: | ---: | ---: | ---: |
| `1366×768 DPR1` (제품 기록) | `820×513` | `1.099` | `0.910` | **`1.821`** | `2.731` |
| **`1440×900 DPR2` (Retina)** | `1031×646` | **`2.764`** | `0.362` | **`0.724` (1.382× 업스케일)** | **`1.085`** |
| `1366×768 DPR1` (전폭 시험) | `1366×768` | `1.645` | `0.608` | **`1.216`** | `1.824` |

> **핵심 진단**: 기존 계획의 `확대 ≤ 1.40×` 기준은 `1440×900 DPR2`에서 `0.724 texel/물리 px`로 **여전히 1.382배 확대 블러**를 허용한다. 반면 전체 월드 3×(`2880×1728`) 한 장은 RGBA8 **`18.98 MiB`**(밉 제외)로 `12 MiB` VRAM 상한을 초과한다. 또한 품질 3단계([quality.ts](../../../src/game/quality.ts))는 내부 캔버스를 축마다 `0.75×`로 축소하고 DPR은 최대 2로 제한한다.

## 2. 0% 블러 초선명 아키텍처 (멀티레이어 분리 합성 + DPR 티어링)

### 2.1 방식 비교 및 확정안
| 검토 방식 | 활성 맵 VRAM (RGBA8) | 그리기 · 전송 구조 | 채택 판단 |
| --- | ---: | --- | --- |
| 전체 월드 1× / 2× / 3× 단일 WebP | `2.11 / 8.44 / 18.98 MiB` (밉 제외) | 1쿼드 · 1파일 | **기각.** 2×는 DPR2 미달(`0.724`), 3×는 단일 맵만으로 16 MiB 초과 |
| `2048×1024` POT 타일 4장 상주 | `32.00 MiB` (밉 포함 `42.67 MiB`) | 최대 4쿼드 · 4파일 | **기각.** 4장 동시 상주 시 VRAM 폭증 |
| 2× 배경 + 동크기 투명 도로 1장 추가 | `16.88 MiB` (패드·성문 제외) | 최소 2쿼드 | **기각.** 도로 밖 투명 픽셀이 VRAM 8.44 MiB 낭비 |
| **가시 지형 + 반복 석판 도로 메시 + 분리 랜드마크** | **일반 `6.66 MiB` / 고밀도 `11.89 MiB`** | **지형 1~2쿼드, 도로 1메시, 성문 앞/뒤 2쿼드, 공용 시트** | **★ 최종 채택.** DPR2에서 `texel/물리px ≥ 1.013` 달성 + `≤ 12 MiB` + 성문 가림/지형 전용 틴트 동시 해결 |

### 2.2 `11.89 MiB` (`≤ 12 MiB`) 고밀도 티어 정량 예산표
- **지형 (`terrain`)**:
  - **일반 티어(DPR1)**: `r6Overview` 2× 가시 지형 `1492×934` = **`5.316 MiB`**.
  - **고밀도 티어(DPR2)**: 3×+ 원본 기반 가시 지형 `2090×1308` = **`10.428 MiB`**(월드당 약 `2.80` 텍셀 → 1440 DPR2 밀도 **`1.013`** 달성! `MAX_TEXTURE_SIZE=2048` 장치에서는 가로 2장 분할 + 거터 기록). 확대 모드에서 가시 지형 밖을 보면 카메라 뷰 사각형 타일만 선택 적재한다(미니맵은 저해상도 개요 별도).
- **분리 도로·랜드마크·패드·아우라**:
  - 랜드마크(`512×256` POT 시트: 성문 앞/뒤·입구·다리) + 석판·연석(`256×256` POT 반복 타일) 밉 포함 합계 **`~1.00 MiB`**.
  - 공용 아우라 시트(`256×256` POT): **`0.25 MiB`**.
  - 설치대(`pad`, 2상태): 2× `0.094 MiB` 또는 3× **`0.211 MiB`**.
  - **고밀도 총합 `11.89 MiB`** (패커는 알파 경계·거터 포함 최종 페이지 치수로 `12 MiB` 상한을 자동 검증; `2238×1401` 3× 지형 합계 `13.42 MiB`는 `16 MiB` 대안으로만 분류).

### 2.3 WebGL 필터 · WebP 인코딩 · 카메라 스냅 · FBO 기각
- **WebGL 필터**: Phaser `4.2.1` WebGL 1 컨텍스트([WebGLTextureWrapper.js](../../../node_modules/phaser/src/renderer/webgl/wrappers/WebGLTextureWrapper.js#L309))는 **POT 텍스처에만 밉맵**을 허용한다. 따라서 NPOT 지형판은 목표 밀도에 맞춰 오프라인 축소 후 `MIN=LINEAR, MAG=LINEAR, CLAMP_TO_EDGE`를 쓰고, 축소 샘플링되는 POT 도로·랜드마크 시트에는 `LINEAR_MIPMAP_LINEAR(9987) / LINEAR(9729)`(인접 프레임 침범 방지 거터·패딩) + UV가 비스듬히 축소되는 도로 메시에 한해 `EXT_texture_filter_anisotropic` `1×` vs `2×` 비교 적용한다.
- **WebP 인코딩**: 잔디·바위 등 자연 지형은 `cwebp -q 92 -sharp_yuv -m 6`, **청록 문틀·황동 연석·패드·글자/문양 등 고주파 엣지는 무손실 WebP**를 적용해 4:2:0 크로마 번짐을 완전히 막는다.
- **카메라 & 후처리**: `roundPixels=false`를 유지해 Spine 보행·포두·투사체 떨림을 방지하고, **정지 전체보기에서만 최종 화면 평행이동을 물리 픽셀 경계에 맞춘다**. 전면 FBO/AMD CAS 후처리는 `1440×900 DPR2` 컬러 버퍼만 `10.16 MiB`를 추가 소비하므로 **기각**한다.

## 4. 성문 우측 후퇴 · 끊김 없는 연속 도로 · 성문 앞/뒤 Y-깊이 분할

### 4.2 V2 좌표·도로·깊이 계약
1. **좌표 계약**: 맵 계약에 `overview`, `entry`, `exit`, `portalPlane`, `portalInterior`, `lastApproach`, `gateAlphaBounds`, `padPivots`를 명시한다. 성문 알파 bbox 전체가 실제 캔버스 CSS 기준 **`x = 76~88%, y = 63~78%`** 안에 **0px 잘림**으로 들어가며, 우상단 슬림 도크(`y ≤ 58%`)와 **교차 면적 `0px²`**을 검증한다(두 끝점·전 슬롯을 `center`·`overview` 함께 보정).
2. **연속 도로 계약**: 단일 중심선에서 도로 바닥·좌우 연석·교량 상판·문턱 안쪽 석판을 끊김 없이 생성한다. UV 길이 원점은 입구이며 문턱에서 초기화하지 않는다. 모서리 곡선 반경(`.66칸` 등)은 도메인 축정렬 이동선이 항상 포장 폭 안쪽에 있도록 제한하며, **최종 waypoint는 포털 안쪽(`portalInterior`), 문턱은 그 앞**에 두어 공식 누수 틱과 시각적 포털 진입을 일치시킨다.
3. **성문 앞/뒤 깊이 분할 (`gateBack < enemy < gateFront`)**: 평소에는 `r6UnitDepth(footY, kind)`를 유지하되, **문 통과 구간에서만** 마지막 접근 방향에 대한 발점의 부호 거리로 `gateBack`(뒤 기둥·청록 에너지 뒷면)과 `gateFront`(앞 기둥·상인방) 사이에 적의 깊이를 고정하고, 개구 마스크/클립 평면으로 포털 안쪽 소멸을 처리한다(그림자·HP 바·상태표시·윤곽 동일 처리, `leak` 이벤트 1회).

## 5. 50웨이브(10구간) 지형 전용 틴트 · 아우라 · 12 MiB 전환 수명주기

1. **지형 전용 틴트 (`GroundLayer.ts`)**: 현행 R6 `GroundLayer.build()`([GroundLayer.ts](../../../src/game/layers/GroundLayer.ts#L62))는 배경·패드 생성 후 조기 반환해 `mood` 사각형이 생성되지 않는다. V2에서는 `terrainImages`만 저장하고 준비 단계 진입 시 `phase = floor((clamp(wave, 1, 50) - 1) / 5)`를 계산해 `1.2초` 전환(`reducedMotion` 즉시, 전투 중 0회)을 실행한다.
   - **선형 휘도 `Y_after / Y_before ≥ 0.80` 보장**: 단순 sRGB `setTint(0xcccccc)`는 중간톤 선형 휘도가 0.8 아래로 떨어지므로 미리 검산한 곱셈값 또는 선형화→색적용→sRGB 복귀 지형 셰이더 1패스를 `terrain`에만 적용한다(도로·패드·타워·Spine 무접촉).
2. **아우라 0 MiB 증분**: 공용 `256²` 시트(`0.25 MiB`)와 풀링 입자 `≤ 24`개만 도로 아래 또는 마스크 밖에서 사용해 10구간 전환 시 추가 VRAM `0 MiB`를 지킨다.
3. **12 MiB 상한 전환 수명주기 (`acquireMapArt` / `releaseMapArt`)**: 11.89 MiB 맵 두 벌을 동시에 GPU에 올리면 순간 피크가 약 `24 MiB`에 달한다. 따라서 키 `r6.map.<mapId>.<revision>.<tier>.<part>.<page>`로 참조 수를 관리하며, **새 파일을 CPU에서 디코드한 뒤 준비 화면에서 이전 전용 페이지를 먼저 해제하고 새 페이지를 업로드**한다(중단·실패·WebGL 컨텍스트 복원 안전 포함).

## 6. 4대 정량 인수 검증 기준

1. **선명도**: `getBoundingClientRect()`, `drawingBufferWidth/Height`, UV 실측 기반 최악 방향 `texel / 물리 px ≥ 1.0` + 무손실 기준 렌더 대비 **10~90% 엣지 폭 증가 `≤ 0.5 물리 px`**, 정지 프레임 경계 떨림 `0`.
2. **성문 & 도로**: 3대 해상도(`1366×768 DPR1`, `1440×900 DPR2`, `1920×1080`) 성문 알파 bbox 비잘림 · 도크 교차 `0px²` · 도로 마스크 단일 연결 성분 · 문 통과 시 잔상 `0` & 누수 1회.
3. **색 & 대비**: 16전장 × 10구간에서 도로 내부 픽셀 차이 `0`, 지형 선형 휘도 비 `≥ 0.80`, G4 중앙값과 함께 **개체별·테마별 최솟값 `≥ 2.056`**.
4. **성능**: `1366×768 DPR1`, CPU 6×, **24타워 실연사** + 일반 적 40 + 보스 2에서 Phaser `prestep→postrender` CPU 작업시간 + `RunController` RAF 합산 **`p95 ≤ min(12ms, 기준선 × 1.15)`**, 평균 `≥ 55fps`, `> 100ms` `0`회.
