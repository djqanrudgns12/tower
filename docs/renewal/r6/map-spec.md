# R6 맵 규격

[PRD §5](PRD-r6.md)와 [R04 전술 지도](round3/concepts/R04/concept.md)에 따라 만든다. 첫 맵은 **초원 고원**이다.

## 좌표와 높이

| 항목 | 초원 고원 규격 |
| --- | --- |
| 게임 맵 ID | `garden_u`. 게임은 기존 [맵 계약](../../contracts/maps.candidate.v0.4.json)의 좌표를 사용한다. |
| 격자 | 15열 × 9행, 칸당 64 월드 px, 전체 960 × 576 px. 왼쪽 위가 원점이다. |
| 칸 중심 | `((x + 0.5) × 64, (y + 0.5) × 64)`. 전투 판정에서 1칸은 1,000 milli-cell이다. |
| 길 | 길 중심 41칸과 방향 전환점 8개. 입구 (0, 1), 성문 (14, 7). 화살표는 진행 방향을 따른다. |
| 설치 칸 | 계약에 정의된 20칸. 칸 ID와 중심 좌표를 입력으로 쓴다. |
| 높이 격자 | 가로 61 × 세로 37의 행 우선 정수 배열 `height[y][x]`. 16 월드 px마다 가상 고도(m)를 저장하며 동쪽·남쪽 경계도 포함한다. 전투 판정에는 사용하지 않는다. |
| 등고선 | 격자를 삼각형으로 나누고 높이 8m마다 교차점을 이어 1px 선을 그린다. 24m마다 1.5px 굵기와 아래쪽 음영으로 높이 차를 표시한다. |
| 명암 | 고도와 북서 경사를 기준으로 카본과 슬레이트를 섞는다. 길은 한 단계 밝은 슬레이트로 이어 그리고, 돌턱에 밝은 1px 선과 아래쪽 그림자를 더한다. 이음매는 직선 구간에 두고 모서리의 길 표면은 둥글게 잇는다. |

## 층과 색

그리는 순서는 **지형 → 길 → 설치 칸 → 소품 → 유닛 → 효과**다. 고정된 앞 네 층은 배경 WebP 한 장에 굽는다. 설치 받침은 길보다 어두운 모따기 윤곽과 작은 십자로 표시한다. Phaser는 선택하거나 끌어 놓을 칸에 앰버 윤곽을, 마우스를 올린 빈 칸에 은회 윤곽을, 키보드 커서에 틸 윤곽을 그린다. 움직이는 유닛은 발 위치의 y 좌표로 앞뒤를 정한다.

| 색 | 용도 |
| --- | --- |
| `#12161B` 카본 | 깊은 음영, 길과 소품 외곽 |
| `#1D242C` 슬레이트 | 바닥, 설치 받침, 길 |
| `#4A5563` 선색 | 등고선, 십자 눈금, 돌턱 |
| `#B8C0C8` 은회 | 길 돌턱과 금속 구조물의 밝은 면, 마우스 강조 |
| `#E69F24` 앰버 | 입구 화살표와 표지 |
| `#2FB5A3` 틸 | 성문 화살표와 표지 |

바위는 지도 테두리에 2~4무리로 모아 배치한다. 초원 고원에는 위·아래·좌·우에 한 무리씩 있다. 각 무리의 그림자까지 길과 설치 칸을 비워야 한다. 입구는 앰버 화살표와 양쪽 표지로 정리하고, 성문은 약 110×97px의 기단과 양쪽 금속 장갑으로 만든다. 틸 화살표는 기지 쪽을 향하며 적이 지나가는 가운데 폭을 확보한다.

## 예산과 새 맵 제작

- 배경은 한 장, **150,000B 이하**. 960 × 576의 RGBA8 텍스처 한 장은 약 2.11 MiB다. 배경을 그리는 동안 높이 계산, 타일 조립, 화면 필터를 실행하지 않는다.
- 새 맵의 격자, 길, 입구, 성문, 설치 칸을 맵 계약에 먼저 등록한다. 경로와 입구·성문의 진행 방향을 맞춘다.
- 고도 격자를 생성하고 등고선 간격과 명암을 적용한다. 가장자리 빈 칸에 소품 무리를 지정하고 주경로와 설치 칸을 대조한다.
- 저장소 루트에서 Pillow가 설치된 Python으로 아래 명령을 실행한다. 새 맵은 생성기에서 선택할 수 있게 한 뒤 별도 WebP로 내보내고, R6 매니페스트의 `maps`에 맵 ID 키로 파일을 연결한다.
- 브라우저에서 맵과 칸 선택 위치를 대조한다. 전투 중 배경 크기, 적과 설치 칸의 명도 차, Chromium CPU 4배 감속 프레임과 학교 기기에서의 가독성을 확인한다.

```sh
python -B tools/r6/map/bake.py
python -B -m unittest discover -s tools/r6/map
```

## 전장 에셋 연결

Phaser는 밸런스 `2.0.0`에서 `public/assets/r6/manifest-v2.json`을 읽고 맵 ID에 맞춰 배경을 고른다. R6의 종족별 아틀라스는 첫 웨이브 준비 때부터 현재 편성에 들어간 종족만 요청한다. 이미 받은 에셋은 판이 끝나면 Phaser와 함께 정리한다.

- `sheets`는 WebP 셀의 너비·높이·수·피벗을 기록한다. `towers`에 타워별 11형태의 몸체 프레임, 포두 시트, 몸체 위 장착점, 배율, 공격 시퀀스를 같은 단계 순서로 적는다. 포두는 16프레임이다. `projection`은 방향 0의 화면 기준각과 카메라의 세로 단축률을 정한다.
- 공격 시트는 각도·몸체 단계가 일치할 때 바로 재생한다. 그 외에는 방향별 포두 정지 프레임에 같은 박자의 반동 좌표를 적용한다. G2 레일 포탑에는 Lv20 방향 0의 8프레임 시트가 들어 있다.
- `species`는 종족별 `atlases` 키와 리그·스킨을 연결한다. 개체별 리그·스킨은 `entities`에서 지정하며 분열·호위 개체도 같은 종족 아틀라스를 쓴다. `rigs`는 Spine JSON과 걷기·피격·쓰러짐 동작을 지정한다. 현재 다섯 종족에 G2 보행체 리그 한 벌을 공유하며 T1~T4 스킨으로 단계를 표시한다.
- `@esotericsoftware/spine-phaser-v4@4.3.13`은 R6 전장에서 불러온다. Phaser 4.2.1 WebGL에서 기본 Mesh2D 백엔드로 재생한다. [Spine Phaser 런타임 문서](https://esotericsoftware.com/spine-phaser)

## 프로토타입 측정

배경은 **31,576B**다. Chromium 156.0.8078.4, ANGLE SwiftShader에서 CPU 4배 감속으로 레일 포탑 한 기와 첫 웨이브를 5초간 그렸다. 295프레임에서 평균 **58.81 FPS**, p95 프레임 간격 **16.7ms**를 기록했다. [전장 시험](../../../tests/e2e/r6-battlefield.spec.ts)은 포두 방향, Spine 보행, 등장 종족의 아틀라스 요청 범위와 이전 전장도 검사한다. 진행 시험에서는 R6 새 판을 열어 빈 칸에 마우스를 올렸을 때의 강조, 레일 포탑 Lv1~20의 11형태와 3·6·9웨이브 해금을 확인한다. 시험 화면에 표시한 종족별 수는 실제 생성 예정 목록과 비교한다. 실기기 크롬북과 양산 에셋을 사용하는 전장은 미측정이다.
