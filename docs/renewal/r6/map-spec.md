## 좌표와 높이

| 항목 | 초원 고원 규격 |
| --- | --- |
| 게임 맵 ID | `garden_u`. 게임은 기존 [맵 계약](../../contracts/maps.candidate.v0.4.json)의 좌표를 쓴다. |
| 격자 | 15열 × 9행, 칸당 64 논리 px. 칸 중심은 `((x + 0.5) × 64, (y + 0.5) × 64)`다. 전투 판정에서 1칸은 1,000 milli-cell이다. |
| 길과 설치대 | 길 중심 41칸, 입구 (0, 1), 성문 (14, 7), 설치대 20개. 길 표면과 설치대 윗면을 3D 높이 0에 맞춘다. |
| 카메라 | 곡사 포대와 같은 직교 카메라. X·Y·Z 방향은 `(6.1, −8.2, 6.05)`다. 높이 0에서 1칸은 렌더의 화면 오른쪽 축으로 52px, 깊이 축으로 약 26.51px에 해당한다. 960 × 576px 배경에서 길·설치대를 담은 `overview` 영역을 균일 배율로 맞춘다. 미니맵도 같은 영역을 중심으로 한다. |
| 고도 | 칸의 1/4 간격으로 가상 고도를 샘플링한다. 12m부터 82m까지 10m 간격으로 삼각형을 잘라 수평면과 수직 턱을 만들고, 그 아래 등고선에 좁은 그림자를 굽는다. 구불길 사이의 두 능선은 주변보다 높고 길과 설치대 윗면은 높이 0이다. |

[투영 설정](../../../src/game/r6/mapProjection.json)을 Blender와 Phaser가 함께 읽는다. Phaser는 `projectField`로 격자 px를 캔버스 월드 px에 놓고 `unprojectField`로 되돌린다. 적 이동, 타워의 몸체 피벗, 효과, 클릭·호버, 사거리 타원과 확대 중심에 이 변환을 쓴다. 공격 범위, 경로 보간과 좌표는 기존 격자에서 계산한다.

## 층과 색

등고선 지형, 돌턱과 그림자가 있는 길, 설치대 지주, 바위 무리, 입구와 성문을 배경 한 장에 굽는다. 길의 꺾이는 구간은 중심선을 부드럽게 잇고, 진행 방향 표식을 입구와 성문에 둔다. 바위는 테두리의 네 곳에 모아 둔다.

설치대 시트는 64 × 48px 프레임 두 장으로 구성한다. 왼쪽이 기본, 오른쪽이 선택 상태다. 피벗 (32, 19)는 육각 윗면 중심이며 타워 몸체 발 위치가 이 점에 맞는다. 마우스를 올린 빈 설치대는 은회, 선택·끌기 대상은 앰버, 키보드 커서는 틸로 표시한다. 유닛의 앞뒤는 투영한 발 위치의 y 좌표로 정한다.

| 색 | 용도 |
| --- | --- |
| `#12161B` 카본 | 가장 어두운 면, 그림자 |
| `#1D242C` 슬레이트 | 지형, 층계 옆면 |
| `#4A5563` 선색 | 길 표면, 등고선, 설치대 |
| `#B8C0C8` 은회 | 돌턱의 밝은 면과 마우스 강조 |
| `#E69F24` 앰버 | 입구 화살표와 선택 표시 |
| `#2FB5A3` 틸 | 성문 표지, 키보드와 사거리 표시 |

## 생성과 예산

1. 새 맵의 격자와 길, 입구·성문의 진행 방향, 설치대를 맵 계약에 등록한다.
2. 고도와 바위 무리를 정한 뒤 길·설치대를 가리지 않는지 확인한다. 길 높이와 설치대 윗면을 피벗 기준면에 맞춘다.
3. Blender에서 아래 명령으로 배경과 설치대 두 프레임을 렌더한다. 배경은 150,000B 이하를 지킨다. PNG는 작업 폴더, 게임에 싣는 WebP는 `public/assets/r6/map/`에 둔다.
4. 브라우저에서 클릭과 설치, 타워와 적의 발, 성문 위치, CPU 4배 감속 프레임을 확인한다.

```sh
r6_map_work="$(mktemp -d /tmp/tower-r6-map.XXXXXXXX)"
"$HOME/.local/bin/resource-guard" status --profile avatar
"$HOME/.local/bin/resource-guard" run --profile avatar --wait-seconds 900 -- \
  /Applications/Blender.app/Contents/MacOS/Blender -b -t 3 --python-exit-code 1 \
  --python tools/r6/map/scene.py -- "$r6_map_work"
python -B tools/r6/map/pack.py "$r6_map_work"
python -B -m unittest discover -s tools/r6/map
```

패킹과 Python 시험에는 Pillow가 필요하다. 배경과 설치대 시트는 각각 RGBA8 약 2.11 MiB와 24 KiB를 사용한다. Phaser는 WebP를 읽어 정적인 그림을 배치한다.

## 전장 에셋 연결

Phaser는 밸런스 `2.0.0`에서 `public/assets/r6/manifest-v2.json`을 읽고 맵 ID에 맞춰 배경을 고른다. `garden_u`는 `map/meadow-plateau.webp`와 `map/meadow-pads.webp`를 싣는다. 기존 미리보기는 기존 파일 경로를 쓴다. R6의 종족별 아틀라스는 첫 웨이브 준비 때부터 현재 편성에 들어간 종족만 요청한다. 이미 받은 에셋은 판이 끝나면 Phaser와 함께 정리한다.

- `sheets`는 WebP 셀의 너비·높이·수·피벗을 기록한다. `towers`에 타워별 11형태의 몸체 프레임, 포두 시트, 몸체 위 장착점, 배율, 공격 시퀀스를 같은 단계 순서로 적는다. 포두는 16프레임이다. `projection`은 방향 0의 화면 기준각과 카메라의 세로 단축률을 정한다.
- 공격 시트는 각도·몸체 단계가 일치할 때 바로 재생한다. 그 외에는 방향별 포두 정지 프레임에 같은 박자의 반동 좌표를 적용한다. G2 레일 포탑에는 Lv20 방향 0의 8프레임 시트가 들어 있다.
- `species`는 종족별 `atlases` 키와 리그·스킨을 연결한다. 개체별 리그·스킨은 `entities`에서 지정하며 분열·호위 개체도 같은 종족 아틀라스를 쓴다. `rigs`는 Spine JSON과 걷기·피격·쓰러짐 동작을 지정한다. 현재 다섯 종족에 G2 보행체 리그 한 벌을 공유하며 T1~T4 스킨으로 단계를 표시한다.
- `@esotericsoftware/spine-phaser-v4@4.3.13`은 R6 전장에서 불러온다. Phaser 4.2.1 WebGL에서 기본 Mesh2D 백엔드로 재생한다. [Spine Phaser 런타임 문서](https://esotericsoftware.com/spine-phaser)

## React 전장 연결

`FieldView.projected`가 참이면 카메라 좌표는 투영 후의 월드 px다. React는 설치 메뉴·타워 도구·보상 효과를 `projectField`로 화면에 놓고, 끌어 놓기의 포인터를 `unprojectField`로 격자에 되돌린다. 가로로 돌린 휴대폰은 상단 HUD와 안내 아래에서 전장을 한 화면에 맞춘다.

## 프로토타입 측정

배경 WebP는 **26,052B**, 설치대 시트는 **2,610B**다. 전장 점유율은 전투 화면의 캔버스를 기준으로 길과 설치대를 둘러싼 사각형의 가로·세로 비율을 잰다. 최외곽 설치대의 반투명 가장자리는 알파 50%부터 포함한다.

Chromium 156.0.8078.4의 ANGLE SwiftShader에서 CPU 4배 감속으로 첫 웨이브를 5초간 그린 결과 평균 **58.81 FPS**, p95 프레임 간격 **16.7ms**였다(295프레임). 전장에는 실제로 동작하는 레일 포탑 한 기와 검수용으로 올린 곡사 포대 원화 세 기가 들어 있다. [전장 시험](../../../tests/e2e/r6-battlefield.spec.ts)에서 레일 포탑의 발과 설치대 피벗 일치, 선택 프레임, Spine 보행과 이전 밸런스 전장도 확인한다. 실기기 크롬북 측정은 별도로 남아 있다.
