## 2. 근본 문제점 분석 (코드 · 실측 수치 · 검수 교정 포함)

### 문제 1 · 몬스터 리깅 & 애니메이션 ("그냥 동동 지나감" + 발 미끄러짐)
1. **직선 보간 + 강체 2키프레임 회전만 사용**:
   - 실제 산출물(`public/assets/r6/monsters/*/*.json`)과 `tools/r6/spine/rigs.py` 실측 결과 **`mesh=False`**, **`constraints=False`**, **`bezier_curve=False`**(100% 직선 Linear 보간).
   - `walk`가 4구간 삼각파(`body.y = 0 → 1.3 → 0` 또는 비행 `3.0`, 팔·다리 `±14°/±21°`, 발 `-0.5×다리각`)뿐이라 몸통 기울기·전후 탄력·착지 스쿼시·무릎 꺾임·발 접지 궤적·2차 추종 모션(망토/날개/무기)이 없다.
2. **발 미끄러짐(풋 슬라이딩)의 실제 원인 (클로드 검수 보완)**:
   - `EnemyLayer.ts:263`은 이미 `walk.timeScale = moving ? e.speedBP / 10000 : 0`을 적용 중이나, ① `rigs.py` 보폭이 개체 표시 배율·`r6EnemyScale` 압축과 무관하고, ② 3/4 투영 맵(`R6_MAP_SQUASH`)에서 세로 이동 화면 속도가 약 `0.51배`로 줄어드는 점이 반영되지 않아 발과 바닥 속도가 어긋난다.
3. **5종족 100개체 획일적 모션 · 빈약한 `hit`/`fall`/`boss-skill` · 코너 떨림**:
   - `hit`는 `body` 1개 본 회전(11°)뿐이고 피격 강조를 허공 흰 꺾쇠 4개(`EnemyLayer.ts:r6Marks`)에 의존한다.
   - `fall`은 `onKill`(`EnemyLayer.ts:133`)에서 `addToUpdateList()`로 등록돼 **품질 2·3단계에서도 매 프레임 갱신·윤곽 렌더가 계속 도는 성능 함정**이 있다.
   - `EnemyLayer.ts:216`의 `aheadX !== point.x` 비교는 세로에 가까운 경로 구간에서 1px 미세 흔들림만으로도 즉시 좌우 반전(`scaleX = ±1`)을 일으킨다.

### 문제 2 · 몬스터 이미지 화질 열화의 진짜 원인 & 윤곽선 이중선 (클로드 검수 교정)
1. **[핵심 교정] 해상도 부족이 아니라 "NPOT + 밉맵 미적용 축소 샘플링"이 주원인**:
   - 초기 가설은 `256(ppu=3)` 캔버스가 작아서(`36~55px` 파츠) 흐리다고 보았으나, 실제 텍셀 밀도 계산 결과 `1366×768 DPR1`(zoom ≈ `1.26~1.46`)에서 `ppu=3`은 이미 화면보다 **약 2.0~3.4배 큰 텍셀**을 가진다.
   - 그럼에도 선화가 깨지고 뭉개진 이유는 `monsters.py:238-241`이 **`pot=false`, `filterMin=Linear`**로 패킹해 Phaser WebGL과 Spine `PhaserTexture`가 **밉맵(`generateMipmap()`)을 생성하지 못한 채 2~3.4배 축소 샘플링**을 수행하기 때문이다.
   - 여기서 캔버스를 `384`나 `512`로 성급히 올리면 축소율이 `3.9~6.8배`로 더 커져 반짝임·계단 현상이 악화되고, 100개체 전체 재절단(`part_guides.py`, `cut_parts.py`, 100개 placement JSON) 비용만 폭증한다. → **확정안: `256/ppu=3` 유지 + `pot=true`, `filterMin=MipMapLinearLinear`, `filterMag=Linear`, 손실 `-q 92` 시 `-sharp_yuv` 적용.**
2. **8패스 런타임 아웃라인의 제출 수 증폭 & 밝은 유닛 이중선**:
   - `src/game/r6/enemyDisplay.ts:attachR6SilhouetteOutline`은 화질 0단계에서 8패스 추가 제출(총 9배)로 W20 프레임당 약 `2,400회` `renderMesh`를 호출한다(같은 아틀라스/셰이더라 GL 드로우콜 9배는 아니나 JS 제출·정점 처리 비용이 큼).
   - 또한 모든 종족에 동일한 은회(`#B8C0C8`) 테두리를 둘러 `human`처럼 밝은 갑주 바깥에 이중선이 생긴다.
   - *(기각된 대안)* 파츠별 오프라인 림 베이크는 관절 내부 이음매에 선이 생겨 기각, Phaser 4 FBO 1패스 셰이더는 개체당 FBO 전환(22회) 또는 Y정렬 파괴로 기각 → **확정안: 0단계도 4방향(5배, ~1,300회)으로 통일 + `silhouettes.json` 길 대비 기반 스킨별 윤곽 정책 + 동일 훅 ADD 틴트(`0x404040`) 피격 점멸.**
3. **2D 일관성 & 취약 개체**:
   - 경질 종족(`machine`·`stone`)에 Blender 3D 파츠를 섞으면 계통 내 T1~T4 선화·명암 일관성이 깨지므로 기각. **고해상도 2D 통일 + G4 이월 취약 5개체(`insect-special-t1`, `elf-armored-t3`, `elf-special-t1`, `insect-infantry-t4`, `stone-runner-t1`) 재작화 보강**으로 정리한다.

### 문제 3 · 타워 & 전투 VFX 생동감 부족
1. **포두 조준-표시 분리 부재 & Idle 없음 (`TowerPlayback.ts`)**:
   - 공격 클립이 `v.direction`을 그대로 쓰므로 단순 보간을 넣으면 회전 도중 오방향 클립이 재생된다 → 표시 방향과 조준 방향 분리가 필요하다.
   - 프리즘 코어는 포두 그림에 구워져 있어 별도 파츠 없이 부유가 불가하므로, 추가 텍스처 0 원칙에 맞는 경량 Idle(미표적 시 저속 스캔·상하 1px·드론 호버·32px 공용 광택 쿼드)로 설계한다.
2. **VFX 매 프레임 테셀레이션 부담 (`CombatVfx.ts`)**:
   - `sync`가 매 프레임 `Graphics.clear()` 후 도형을 전부 재테셀레이션한다. 장식 요소까지 Graphics로 늘리면 CPU 6배 감속에서 프레임이 튄다 → 핵심 선만 Graphics로 남기고 장식은 `256×256` 이하 VFX 아틀라스 1장(`≤ 30KB`) + 풀링 Image/파티클(ADD)로 분리한다.

### 문제 4 · UI/UX 결함 (현장 확인 로그 + 코드 감사)
1. **치명적 UX 모순 + 개인정보 고지 누락 (`settings.ts`, `lobbyClient.ts`, `LaunchDeck.tsx`, `copy.ts`)**:
   - 2026-11-27 현장 확인 D1 로그: `rate_limits`에 학교 검색(`schools`) 7회(12:08~12:10 KST)만 남고 `lobby_presence`·`run_start_dedup`·`completed_runs`·`standings` **0건**.
   - 원인: `shareRecords` 기본값이 `false`이고, 서버는 시작 기록이 없는 제출을 `START_REQUIRED`로 거절(`lobbyClient.ts:435`)하므로 **새 게임 시작 전에 동의가 켜져 있어야만** 기록이 올라간다. 그런데 `LaunchDeck.tsx:98`이 꺼진 상태에서도 `준비 완료 · 순위 연동`을 표시해 오해를 불렀다.
   - **[P0 고지 누락 발견]** `copy.ts:208` 고지 문구는 "닉네임·학년·난이도·점수·웨이브"만 안내하지만, 실제로는 `schoolName`·`schoolCode`를 전송(`lobbyClient.ts:477-478`)하고 서버 순위표에 `schoolName`을 공개한다(`server/src/store.ts:214`).
2. **홈 레이아웃 & 웨이브 예고**:
   - `.stageViewport`는 `object-fit: cover`를 쓰면 상하 35%가 잘려 성문·길이 사라질 수 있으므로 자르지 않고 좌우 여백에 웨이브·보스 정보 띠를 둔다.
   - `R6WaveForecast`는 홈 초상(256px 일상 원화) 대신 전투 준비 단계에서 Spine 기본 자세를 48px로 오프스크린 렌더해 쓰면 추가 전송량 0으로 실제 전장 개체와 100% 일치한다.
