## 0. 사용자 결정 (원문 요지)

1. 타워는 처음에 **6종**. **Lv20**까지 올라가고 **2레벨마다(Lv2·4·6…20) 모양이 조금씩 진화**한다. 무기가 바뀌고 형태가 고급스러워지는 것도 좋다. 이를 위한 고도화된 로직이 필요하다.
2. 타워 모양은 **절대 겹치면 안 된다**. 철저히 검수한다. 타워마다 **스타일과 공격 애니메이션이 확실히 달라야** 한다.
3. 몬스터는 사이버만이 아니라 **다양한 형태**로, **실제 게임 몬스터 수준의 높은 품질**. **종족 5개**(엘프·인간·기계·벌레 등, 세계관 재설계), **종족마다 20개체**, 모두 조금씩 다르고 **진화하는 개체**. 처음부터 같은 것만 나오지 않게 **단계에 따라 섞는다**.
4. **Tripo**와 **Spine Pro** 사용 가능. 가장 효율적인 구조로 설계한다.
5. 맵은 **프로토타입 1개**로 시작하고, **규격을 정해 나중에 양산**한다.
6. 운영: 에이전트 협업. Claude는 총괄(토큰 절약), **이미지 생성은 Antigravity(Neon 오케스트레이션)가 뚝심 있게 전담**, Codex는 구현·도구·검증을 맡는다. 브리지가 막히면 컴퓨터 사용으로 Antigravity를 직접 구동한다. **자체 품질 검수 후 속행**한다.

## 3. 타워 체계

### 3.1 6종 (실루엣·공격 연출이 겹치지 않게)

| ID | 이름(가안) | 역할 | 실루엣 원칙 | 공격 애니메이션 원칙 |
|---|---|---|---|---|
| `rail` | 레일 포탑 | 단일 고속 | **높고 가는** 수직 포신 | 포신 후퇴 반동 + 가는 예광선(즉발) |
| `mortar` | 곡사 포대 | 범위 폭발 | **낮고 넓은** 사각 포상 | 포구 상향 → 포물선 포탄 → 착탄 원형 충격 |
| `cryo` | 냉각 중계탑 | 감속·제어 | **겹친 고리 기둥** | 고리 회전 가속 → 원형 냉기 파동 |
| `prism` | 프리즘 탑 | 연쇄·관통(마법) | **틀 속 결정** | 결정 충전 → 짧은 광선이 2~5기 연쇄 |
| `hangar` | 드론 격납고 | 대공·추적 | **육각 발진대 + 안테나** | 드론이 떠올라 선회 → 표적 추적 사격 후 귀환 |
| `bastion` | 방벽 기지 | 지원·근접 | **접시 안테나 + 방벽판** | 방벽 전개(근접 밀치기) + 주변 타워 강화 고리 |

- 한 판의 흐름(가안): 시작 3종(rail·mortar·cryo) → 3·6·9웨이브 뒤 나머지 3종을 하나씩 해금. 칸에 둘 수 있는 수는 기존처럼 설치 칸 제한.
- 서로 겹침 금지 검수(§8 G1): 48px 실루엣의 겹침 비율(IoU) **0.55 미만**, 공격 연출 타이밍·형태가 표로 서로 달라야 함.

### 3.2 Lv20 · 2레벨마다 진화 (11형태)

- 형태 단계 = `stage = level < 2 ? 0 : floor(level / 2)` → **Lv1(0) · Lv2(1) · Lv4(2) … Lv20(10) = 11형태**. 6종 × 11 = **66형태**.
- **무기 단계 4개**: Lv1~5 무기 I → **Lv6 무기 II** → **Lv12 무기 III** → **Lv18 무기 IV**(무기 모양과 공격 방식이 실제로 바뀜. 예: 레일 단포신 → 쌍포신 → 삼연장 → 가속 고리 레일).
- **재질 단계 4개**(고급스러워짐): 강철(Lv1~5) → 합금(Lv6~11) → 세라믹 장갑(Lv12~17) → 금테 완성형(Lv18~20). 색 수는 R04 팔레트 안에서 명도·금속감·장식선만 늘린다(빛 번짐 금지).
- 그 사이 짝수 레벨(2·4·8·10·14·16·20)은 **미세 진화**: 장갑판·기단 확장·안테나·포구 보강·표식 띠 등 부품 1~2개가 더해진다.
- 레벨 업 순간 연출: 0.6초 이내의 절제된 변신(부품이 맞물려 끼워지는 짧은 움직임 + 작은 먼지). 무기 단계 바뀔 때만 1.2초.

### 3.3 "고도화된 로직" = 진화 레시피 데이터

- 타워마다 `tower-recipes/<id>.json`: 11단계 각각의 **부품 슬롯 목록**(기단·몸체·장갑·포두·무기·장식·표식), 부품 ID, 재질 단계, 무기 단계, 공격 연출 파라미터.
- 한 레시피에서 **(1) 3D 조립 렌더**와 **(2) 게임 능력치 곡선**이 같이 나온다 → 그림과 성능이 어긋나지 않는다.
- 능력치는 새 계약 `balance v2`(§6)에서 Lv1~20 곡선으로 정의. 무기 단계는 공격 방식(표적 수·연사·관통·장판)을 바꾼다.

### 3.4 타워 제작 공정 (권장, G2 스파이크로 확정)

**도구 결정(2026-11-25, 사용자 요청으로 총괄 판정): 제작·렌더는 Blender 5.2 LTS가 주력, three.js는 제작에 쓰지 않는다. 게임 실행은 지금처럼 Phaser 2D + 미리 렌더한 스프라이트.**
- 품질: 모델링·재질·조명·주변광 차폐·외곽선(Line Art·반전 셸)·애니메이션이 Blender 쪽이 압도적. 3차 R06~R08(three.js 기본 도형)의 한계가 확인됐다.
- 최적화: 무거운 3D 계산은 제작 때 한 번만 하고, 학교 크롬북은 가벼운 WebP 스프라이트만 그린다. 실행 중 3D(three.js 실시간)는 전장 전면 재작성·GPU 부담·모델 수백 개 관리가 필요해 채택하지 않는다.
- 장기 효율: `.blend` 부품 키트 + 레시피 JSON + 렌더 스크립트가 원본이 된다. 화풍·해상도(고해상도 화면 2배 등)를 바꿀 때 셰이더만 고쳐 전체를 다시 렌더하면 된다. Geometry Nodes로 진화 레시피를 매개변수 조립할 수 있고, Tripo GLB도 바로 들어온다. 나중에 3D 실행이 필요해지면 같은 원본에서 GLB로 내보낼 수 있어 길이 막히지 않는다.
- three.js의 남은 쓰임: 필요하면 브라우저 안 GLB 미리보기·검수 도구 정도. 3차 R06~R08 코드는 참고 기록으로만 둔다.
- 몬스터는 그대로 Spine 2D(100개체를 뼈대 20개 + 스킨으로). 단단한 개체의 형태 기준이 필요하면 Blender/Tripo 렌더를 파츠 작화 참고로만 쓴다.

1. Antigravity: 타워별 **콘셉트 시트**(Lv1·Lv6·Lv12·Lv18·Lv20 정면·측면, 부품 분해도) — 이미지 생성.
2. 부품 모델링: **Blender 헤드리스 파이썬**으로 부품 키트 제작. 복잡한 포두·장식은 **Tripo**로 기본 메시를 뽑아 정리 후 키트에 편입.
3. 조립·렌더: 레시피 JSON → Blender 스크립트가 11단계를 자동 조립 → **고정 카메라·고정 조명·R04 무광 툰+외곽선 셰이딩**으로 렌더. 몸체와 회전 포두를 분리 렌더(포두는 16방향 또는 회전 가능 탑뷰 각도로 결정).
4. 공격 애니메이션: 포두 반동·충전·드론 발진 등은 Blender에서 6~10프레임 시퀀스로 렌더 → 스프라이트 시트.
5. 결과는 WebP 아틀라스 + 매니페스트. 사람 손 보정은 검수 반려분만.

## 4. 몬스터 체계

### 4.1 5종족 (다양한 세계, 실제 게임 몬스터급)

| 종족(가안) | 정체성 | 대표 성향 |
|---|---|---|
| **숲 엘프** | 덩굴·나무·빛 문양의 숲 종족과 짐승 | 빠름·마법 저항·은신 느낌 |
| **철갑 인간** | 갑옷 병사·방패·공성 수레의 왕국 군단 | 물리 저항·균형·대형 공성 |
| **기계 군단** | 보행기·드론·비행체 | 장갑·비행·분열(소형 드론 사출) |
| **군체 벌레** | 갑충·유충·날벌레 무리 | 떼·분열·재생 |
| **바위 거인** | 골렘·수정 정령·용암 구조체 | 느림·매우 단단함·보스 존재감 |

- 품질 기준: 실제 상용 게임 몬스터처럼 **해부·재질·실루엣이 설득력** 있게. 초등 대상이라 **피·공포 표현 금지**, 치비·밈·음식 금지.

### 4.2 종족당 20개체 = 계통 4 × 단계 4 + 보스 4

| 계통(역할) | T1 → T2 → T3 → T4 (조금씩 진화) |
|---|---|
| 보병 | 기본 병사가 장비·체격이 커지며 진화 |
| 질주 | 빠른 짐승/정찰체가 더 날렵하고 커짐 |
| 중장갑 | 방패·갑각이 두꺼워짐(물리 또는 마법 저항) |
| 특수 | 종족별: 엘프 = 비행 정령, 인간 = 공성 수레, 기계 = 드론 모함(분열), 벌레 = 분열 유충떼, 바위 = 재생 수정 |
| **보스 4** | 5·10·15·20웨이브급. 각자 기술 1개(기존 보스 기술 6종 재사용·추가) |

- 5종족 × 20 = **100개체**. 같은 계통의 T1~T4는 **같은 뼈대 + 부품 교체(Spine 스킨)**로 만들어 "조금씩 진화"를 싸고 일관되게 표현한다.

### 4.3 단계별 섞기 (웨이브 혼합 규칙, 가안)

| 웨이브 | 등장 종족 | 단계 |
|---|---|---|
| 1~3 | 무작위 2종족 | T1 |
| 4~6 | +1종족(3종족) | T1~T2, 첫 특수 계통 |
| 7~10 | 4종족, 10웨이브 보스 | T2 위주 + T3 소수 |
| 11~15 | 5종족 전부, 웨이브마다 주 종족 교대 | T2~T3 |
| 16~20 | 5종족, 혼성 편성 | T3~T4, 20웨이브 최종 보스 |
| 21~ | 무한: 종족 순환 + 정예(장갑·신속) 확률 상승 | T4 + 정예 |

- 원칙: **3웨이브마다 처음 보는 개체가 최소 1종**, 같은 개체만 한 웨이브를 다 채우지 않음, 보스 웨이브는 종족을 돌아가며.
- 시드 고정(재현 가능)·랭킹 검증과 맞물리므로 혼합은 결정적 난수로 구현.

### 4.4 몬스터 제작 공정 (권장, G2 스파이크로 확정)

1. Antigravity: 종족별 **설정화 시트**(20개체 라인업), 개체별 **3/4 측면 콘셉트**, 그리고 **파츠 분리 시트**(머리·몸통·팔다리·장비 레이어).
2. 파츠 → `spine-authoring` 스킬의 `layers_to_spine.py`로 Spine 4.3 JSON → 계통 뼈대 20개(5종족×4계통)에 리깅, **T1~T4는 스킨**, 보스는 개별 뼈대.
3. 애니메이션: 걷기(루프)·피격·쓰러짐·보스 기술 1개. Spine CLI로 내보내기.
4. 런타임: **(a) Phaser 4용 Spine 런타임 직접 재생** 또는 **(b) 프레임 시트로 구워 재생** 중 G2에서 크롬북 성능·호환성으로 결정. 메모리 예산 때문에 웨이브에 나올 종족 아틀라스만 지연 적재.
5. Tripo는 바위 거인·기계처럼 단단한 개체의 3D 기준 모형이 필요할 때 보조로만 쓴다(2D 일관성 우선).

## 5. 프로토타입 맵 1개 + 맵 규격

## 8. 품질 관문 (자체 검수 후 속행)

관문은 **에이전트 비평 + 자동 검사 + 총괄 확인**이 모두 통과하면 사용자 확인 없이 다음으로 간다. 사용자에게는 각 관문 결과를 비교판으로 **보고만** 하고(막지 않음), 운영 반영만 확인을 받는다.

| 관문 | 통과 기준 | 검수자 |
|---|---|---|
| **G0 기획** | 이 PRD + 세부 명세(타워 레시피 66단계, 몬스터 100 설정표, 웨이브 혼합표) 서로 모순 없음 | Codex 교차 검토 1회 + 총괄 |
| **G1 아트 바이블** | 타워 6종 Lv1/6/12/18/20 시트, 5종족 20개체 라인업. 비평가(아트 디렉터 ≥8/10, 초6 "멋있다"), **실루엣 겹침 IoU < 0.55**, 팔레트 위반 0, AI 티 점검표 통과 | Antigravity 비평 하위 에이전트 2명 + Codex 자동 검사 + 총괄 |
| **G2 공정 스파이크** | 타워 1종 11형태 Blender 자동 렌더, 몬스터 1계통 T1~T4 Spine 리깅·걷기, Phaser 4 재생 방식 결정, 크롬북 감속 측정 60fps | Codex + 총괄 |
| **G3 수직 단면** | 프로토타입 맵 + 타워 2종 Lv1~20 + 1종족 20개체 + 전투·홈 UI가 실제 게임에서 동작. 맵 규격 문서 | 비평가 2명 + e2e 범위 시험 + 총괄 |

- 반려 규칙: 같은 항목이 2회 반려되면 기록하고 다음 항목으로 넘어간다(무한 루프 금지). 3회째는 총괄이 직접 판단.
