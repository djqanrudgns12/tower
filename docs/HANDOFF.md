## 구현 요청을 받은 뒤의 순서

1. PRD §25와 41번 기준을 유지하고, 작은 호환성 검증 후 React/TypeScript/Vite + Phaser 어댑터 후보를 정확한 버전으로 잠근다.
2. 렌더러와 독립된 규칙·명령·이벤트·직렬화 계약부터 만든다. 도메인 30Hz, 렌더 보간, 결정적 난수, 멱등 보상.
3. 긴 실제 좌표 맵 한 개, 타워 3종/적 2종, 내부 문항 fixture로 완주 흐름을 먼저 연결한다. 미승인 문항을 공개하지 않는다.
4. 41번 기준의 타워/적/고정 장식/UI 소량 표본을 Argon에 요청하고 소켓·피벗·알파·보행·작은 화면을 검수한다.
5. 4→5→6 웨이브에서 무드·보스·보상·정지·패배·저장/복원부터 검증한다. 10/15/20 및 이후 무한 구간으로 확장한다.
6. 한 학년 비공개 검증 이후 기존 상세 계획의 전체 범위·문항 공동검수·실기기·운영 게이트를 진행한다.

**현재는 구현하지 말라는 사용자 지시가 유효하다. 이 문서를 읽었다는 이유만으로 위 작업을 자동 시작하지 않는다.**

## 파일·복원 정보

프로젝트 이미지 정리 후 이미지 파일은 41번 PNG **1개**만 남긴다. 기존 시안·동작 이미지 99개(41번의 이전 위치 사본 포함)를 삭제했고, 41번은 해시 검증 후 새 위치로 복사했다. 컴퓨터의 Codex 캐시나 사용자 임시 첨부 경로를 실행 의존성으로 사용하지 않는다.

`docs/archive/`의 코드·manifest·검사 기록은 이력이다. 삭제된 이미지나 이전 PC 절대경로를 가리킬 수 있으며 실행/재생성을 하지 않는다. 이 자료는 다른 화풍을 되살리거나 제품 코드를 이어 붙이는 출발점이 아니다. 현재 활성 도구는 `tools/build-plan.mjs`, `tools/validate-plan.mjs`뿐이다.

통합 PRD 생성 원본은 `vocabulary_td_prd_claude_v0_1.md` + `docs/prd_v0_3_additions.md` + `docs/prd_v0_3_decisions.md`다. `node tools/build-plan.mjs`가 `vocabulary_td_prd_v0_3.md`를 만든다. 원문은 보존하고 생성 파일만 따로 수정하지 않는다. 검산 16항목은 과거 후보/경제 산술 검사이며 게임 테스트나 최신 맵 밸런스 승인으로 보고하지 않는다.
